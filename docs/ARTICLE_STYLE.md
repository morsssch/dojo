# Оформление интерактивных статей

Эталон общего оформления — статья «Линейное программирование с нуля»: `articles/linear-programming/index.html` и `style.css`. Новые статьи и изменения существующих должны повторять её общие компоненты, а не создавать похожую версию с другими размерами и отступами. Предметные графики и схемы могут отличаться по устройству.

## Оглавление

Используй разметку и правила `lpt` из статьи по ЛП:

- контейнер `lpt`, заголовок `lpt-title`, список `lpt-parts`;
- строка `lpt-head`: номер `lpt-n` отдельно от названия-ссылки; время `lpt-min` — если оно уже известно;
- короткое описание раздела `lpt-desc`;
- ссылки на подтемы в `lpt-subs`, оформленные компактными округлыми плашками;
- ссылка на шпаргалку в `lpt-cheat` после основного списка.

Не объединяй номер с текстом ссылки. Не заменяй плашки постоянно подчёркнутыми ссылками. Сохраняй якоря, порядок разделов и доступность всех ссылок. На ширине до 560 px описания и подтемы выравниваются по левому краю контейнера, как в эталоне.

## Общие компоненты

| Элемент | Правило |
|---|---|
| Шрифты и цвета | Только токены Dojo. Основной текст наследует оформление `.md`, включая выбранный пользователем шрифт и размер. |
| Заголовки | `h2`: 26 px и `margin: 0`; `h3`: верхний отступ 2 rem. Остальную типографику наследуй как в ЛП; не вводи общий сброс `h1,h2,h3,h4`, `p`, `li` или `b,strong`. |
| Разделы | `.sec`: верхний отступ 48 px, `scroll-margin-top: 110px`; `.sec-head`: тонкая линия `--line-2`. |
| Метки | `.eyebrow` и `.part` повторяют ЛП, включая размеры, регистр и интервалы. |
| Карточки и задачи | Подложка `--surface`, рамка `1px solid var(--line)`, скругление `--r-l`. Отступы — из соответствующего компонента ЛП. |
| Выноски и списки алгоритма | Повторяй `.note`, `.note.red`, `.algo` из ЛП. Цвет используется для смысла. |
| Пошаговый плеер | Повторяй `.stepper`, `.sp-bar`, `.sp-mid`, `.sp-stage`, `.sp-text` из ЛП. Подложка сцены — `--surface-2`, без общей тетрадной сетки. |
| Мобильное управление | До 560 px строка счётчика и ползунка переносится перед кнопками; размеры и отступы кнопок соответствуют ЛП. |
| Навигация | Липкая панель на высоте 56 px, горизонтальная прокрутка, подсветка текущего раздела через `.on`. |

Копируй соответствующие правила эталона точно. Не добавляй в конец файла приближённые переопределения, которые оставляют другую типографику или мобильную компоновку. Правила специфических графов должны оставаться в пределах статьи и не менять общие компоненты.

## Образцы решений в тетрадном стиле

В статье по автоматам **сохраняй тетрадное оформление `.sheet`**: сетку, оформление записей, графов и таблиц. Это отдельный вид учебного материала; его не нужно превращать в обычную карточку или блок записей из статьи по ЛП. Общий стиль страницы и плееров при этом остаётся единым.

Для существующих образцов используй действующие правила `.sheet` из `articles/automata/style.css`. На мобильном экране сохраняй внутренние отступы 16 px и прокрутку широких графов и таблиц.

## Движение и интерактивность

Все пошаговые интерактивы должны анимировать изменения прежним механизмом: `fresh` для прорисовки дуг и появления вершин, `fr` для появления ячеек. Сохраняй смысловую подсветку текущего шага. Не ограничивай новый разбор статичной заменой картинок, если аналогичные разборы уже анимированы. Уважай `prefers-reduced-motion`; снимай таймеры и обработчики при уходе со страницы.

## Проверка перед публикацией

Сравни с ЛП оглавление, заголовки, интервалы, карточки и плееры в браузере. Проверь десктоп и ширину 390 px, светлую и тёмную тему. Для общих компонентов сравнивай вычисленные стили на одинаковой разметке, а для предметных графов — реальные снимки и доступность всего содержимого при прокрутке.

Проверь якоря и подсветку навигации, кнопки, ползунок, клавиатуру, автопроигрывание, анимацию, решения под спойлерами и уход/возврат. Запусти проверки алгоритмов статьи, если они есть, и `npm run build`.
