# Как писать курсы для Dojo

Инструкция для автора — человека или нейронки. Её достаточно, чтобы написать курс целиком, не читая код платформы.
Живые примеры каждого блока — в `courses/demo/` (курс «Витрина Dojo»). Если сомневаешься, как что-то записать, открой его.

---

## 0. Короткий чек-лист

1. Создай/найди папку курса `courses/<course-id>/`.
2. Пиши уроки в Markdown: шаг = заголовок `# ...`, задания = fenced-блоки (`quiz`, `task`, `git`, `anim`, `project`).
3. Запусти `npm run check` — он валидирует YAML и **прогоняет эталонные решения всех задач**. Ноль ошибок — можно коммитить.
4. Посмотри урок глазами: `npm run dev` → http://localhost:5173.
5. Обнови статус урока (`draft: false`) и бэклог курса, если он есть.

## 1. Структура файлов

```
courses/
  <course-id>/                 # id курса = имя папки (латиница, kebab-case)
    course.yaml                # метаданные курса
    roadmap.yaml               # роадмап (необязательно)
    modules/
      01-go-basics/            # порядок — по числовому префиксу; id модуля = "go-basics"
        module.yaml
        01-hello.md            # урок; id = "hello", ключ урока = "go-basics/hello"
        02-variables.md
      02-sql/
        ...
```

- **Порядок** модулей и уроков задаётся только числовым префиксом (`01-`, `02-`, …). Перенумеровать можно свободно —
  прогресс учеников привязан к id *без* префикса.
- **Нельзя переименовывать id** (часть имени после префикса) у уже опубликованных уроков: прогресс учеников потеряется.
- Префиксы удобно делать с запасом (`010-`, `020-`), чтобы вставлять уроки между.

### course.yaml

```yaml
title: Go Backend с нуля
subtitle: Одна строка под заголовком
icon: 🐹                     # необязательно
order: 1                     # порядок на главной
draft: false                 # true — курс виден только в dev-режиме
description: |               # markdown, показывается на странице курса
  Для кого курс и что будет в конце.
belts:                       # необязательно: свои уровни. По умолчанию — пояса дзюдо
  - { at: 0, name: Белый пояс, color: '#eef0f4' }
  - { at: 0.5, name: Синий пояс, color: '#3d7be0' }
```

### module.yaml

```yaml
title: Основы Go
description: Переменные, функции, слайсы и мапы.
draft: false                 # true — модуль помечен «скоро»
```

### Frontmatter урока

```markdown
---
title: Слайсы изнутри
minutes: 15                  # оценка времени
draft: false                 # true — урок виден в программе как «скоро», открыть нельзя
checkpoint: false            # true — урок-тест, см. раздел 7
pass: 0.8                    # для checkpoint — доля решённых заданий для зачёта
tags: [slices, memory]
---
```

## 2. Шаги урока

Урок делится на **шаги** заголовками первого уровня. Каждый шаг — отдельная «плитка» сверху, как на Stepik.

~~~~markdown
# Что такое слайс          ← шаг 1 (теория)
Текст...

# Проверим                 ← шаг 2 (квиз)
```quiz
...
```

# Под капотом              ← шаг 3
~~~~

Правила хорошего шага:
- **Порция:** 1 идея на шаг, 150–400 слов теории. Длинный текст разбивай на несколько шагов.
- **Ритм:** теория → вопрос → теория → вопрос → задача. После каждого куска теории — хотя бы один квиз.
- Внутри шага используй `##` и `###` для подзаголовков (не `#` — он начинает новый шаг).
- Шаг без заданий засчитывается при открытии. Шаг с заданиями — когда решены все задания в нём.

Тип плитки определяется автоматически по первому заданию в шаге: теория / вопрос / задача / git / схема / проект.

## 3. Теория: Markdown и выноски

Работает весь GitHub-flavored Markdown: таблицы, списки, `код`, ссылки, картинки.

### Выноски

```markdown
> [!NOTE]
> Нейтральная заметка.

> [!TIP] Свой заголовок
> Совет. Текст после метки становится заголовком.

> [!WARNING]
> Типичная ошибка.

> [!DANGER]
> Так делать нельзя.

> [!DEEP]
> «Под капотом» — сворачиваемый блок. Сюда — как устроено внутри: память, планировщик, протокол.
```

`[!DEEP]` — главный инструмент для глубоких объяснений: основной текст остаётся коротким, а желающие раскрывают подробности.

### Код

- Обычный блок ```` ```go ```` — просто подсветка. Языки: go, sql, js/ts, python, bash, json, yaml, dockerfile, http, xml/html, diff, kotlin, nginx, proto.
- **Запускаемый пример:** ```` ```go run ```` (также `sql run`, `js run`, `python run`). Ученик может поменять код и запустить. Без проверки.
- В `sql run` всё, что выше строки `-- ^ setup`, выполняется незаметно (создание таблиц):

````markdown
```sql run
CREATE TABLE t (x int); INSERT INTO t VALUES (1), (2);
-- ^ setup
SELECT sum(x) FROM t;
```
````

### Mermaid

```` ```mermaid ```` — статичные диаграммы (sequence, flowchart, ER, state). Для пошаговых объяснений лучше `anim` (см. ниже).

## 4. Квизы — блок `quiz`

Содержимое блока — YAML. Поля с Markdown: `question`, `options[].text`, `options[].why`, `explain`, `hints`.

```yaml
id: slices-append          # уникален в пределах урока; лучше задавать явно (иначе прогресс привязан к позиции)
kind: single               # single | multiple | text | number | order   (по умолчанию single)
question: Что выведет программа?
code: |                    # необязательно — код под вопросом
  fmt.Println(len("привет"))
lang: go                   # язык подсветки code (по умолчанию go)
options:
  - text: "6"
    why: Это количество символов, а len считает байты.   # показывается, если ученик выбрал этот вариант
  - text: "12"
    correct: true
explain: |                 # показывается после верного ответа или после 2 ошибок
  Кириллица в UTF-8 — 2 байта на символ.
hints:                     # открываются по одной кнопкой
  - Чем отличается байт от символа?
```

Виды:
- `single` — один правильный (`correct: true` ровно у одного).
- `multiple` — несколько правильных; ученик должен выбрать все и только их.
- `text` — `answer: "go"`, или список `answer: [go, golang]`, или регулярка `answer: /^\s*select\s*$/i`. Регистр и лишние пробелы игнорируются.
- `number` — `answer: 404`, допуск `tolerance: 0.01`.
- `order` — `options` перечисляются **в правильном порядке**, ученику они показываются перемешанными.

Как писать хорошие вопросы:
- Неверные варианты — **типичные заблуждения**, а не очевидная чушь. У каждого неверного варианта — `why`.
- Вопросы «что выведет код» — лучший формат для Go: заставляют мысленно исполнить код.
- Варианты, начинающиеся с `` ` ``, `[`, `{`, `*`, `-`, или содержащие `: `, **бери в кавычки** (это YAML).

## 5. Задачи с кодом — блок `task`

### Go / JS / Python: ввод-вывод

```yaml
id: sum
lang: go                   # go | js | python | sql
title: Сумма двух чисел
prompt: |                  # markdown
  Прочитай два числа и выведи сумму.
starter: |                 # стартовый код в редакторе
  package main
  ...
solution: |                # эталон: проверяется `npm run check`, ученику показывается после 3 попыток
  package main
  ...
tests:
  - { stdin: "2 3", stdout: "5" }
  - { name: большие числа, stdin: "1000000000 1000000000", stdout: "2000000000", hidden: true }
hints: [...]
explain: |                 # показывается после решения: разбор, альтернативы
```

Сравнение вывода игнорирует пробелы в конце строк и пустые строки в конце.

### Go / JS / Python: проверка функций (харнесс)

Ученик пишет функции (без `main`), скрытый `harness` их вызывает:

```yaml
harness: |
  package main

  func main() {
  	dojoCheck("Reverse([1 2 3])", Reverse([]int{1, 2, 3}), []int{3, 2, 1})
  	dojoAssert("не паникует на nil", Reverse(nil) != nil, "Reverse(nil) вернул nil")
  }
```

- `dojoCheck(имя, получено, ожидалось)` — сравнение через `reflect.DeepEqual` (Go) / JSON (JS) / `==` (Python).
- `dojoAssert(имя, условие, сообщение)` — произвольная проверка.
- Харнесс может импортировать пакеты — импорты склеиваются с импортами ученика автоматически.
- В Python функция называется `dojo_check` (или `dojoCheck`).
- Можно комбинировать `harness` и `tests`.

### HTTP в Go

Сети в браузере нет, но `net/http` + `net/http/httptest` работают: харнесс вызывает хендлер через `httptest.NewRecorder()`.
Пример — `courses/demo/modules/02-practice/01-go.md`, шаг «HTTP-хендлер».

### Ограничения Go в браузере (важно!)

Код выполняет интерпретатор **yaegi**, а не компилятор. Отличия:
- **Не** ругается на неиспользуемые переменные и импорты. Не делай задачи, проверяющие именно это.
- Стандартная библиотека уровня **Go 1.22**: нет `slices.Sorted`, `maps.Keys` как итераторов, range-over-func.
- Вывод типов в дженериках слабее: иногда нужно явно `Map[int, string](xs, f)`. Проверяй эталон через `npm run check`.
- Доступные пакеты: bufio, bytes, cmp, container/heap, container/list, context, crypto/(md5, sha1, sha256, rand, hmac),
  encoding/(base64, hex, json, csv, xml), errors, fmt, hash/fnv, io, io/fs, log, log/slog, maps, math, math/bits, math/rand,
  net/http, net/http/httptest, net/url, os, path, path/filepath, reflect, regexp, slices, sort, strconv, strings, sync,
  sync/atomic, text/template, html, time, unicode, unicode/utf8.
  Нужен другой пакет — добавь в `runtimes/go/build.sh` (`PKGS`) и пересобери (`npm run build:go-runtime`).
- Нет: файловой системы, сети, сторонних модулей (`github.com/...`), `go test`. Для этого — блок `project`.
- Таймаут — 8 секунд. Дедлок не детектится, а ловится таймаутом.

### SQL (PostgreSQL)

```yaml
id: top3
lang: sql
setup: |                   # схема и данные; выполняется перед кодом ученика и эталоном
  CREATE TABLE teams (id serial PRIMARY KEY, name text, place int);
  INSERT INTO teams (name, place) VALUES ('a', 2), ('b', 1);
starter: |
  SELECT
solution: |
  SELECT name FROM teams ORDER BY place LIMIT 3;
ordered: true              # важен ли порядок строк (по умолчанию нет)
check: |                   # для INSERT/UPDATE/DELETE: этот запрос выполняется после кода, сравниваются его результаты
  SELECT * FROM teams ORDER BY id;
```

- Каждая проверка — в отдельной транзакции, которая откатывается. Ученик ничего не может сломать.
- Сравниваются значения, не имена колонок (алиасы не важны). Число колонок — важно.
- Ученик видит схему таблиц (парсится из `CREATE TABLE` в setup) и, при ошибке, свой и ожидаемый результат.

## 6. Git — блок `git`

Терминал с настоящим git (isomorphic-git) в браузере, граф коммитов, вкладка «Файлы» с редактором.

```yaml
id: first-commit
title: Первый коммит
prompt: |
  Создай репозиторий в папке app и закоммить README.md.
setup:                     # команды, выполняются молча перед стартом
  - mkdir app
goals:                     # цели отмечаются автоматически после каждой команды
  - text: Есть репозиторий
    check: { repo: true }
  - text: Сделан коммит
    check: { commits: 1 }
solution:                  # эталон — обязателен для `npm run check`
  - cd app
  - git init
  - echo "# app" > README.md
  - git add . && git commit -m "init"
hints: [...]
explain: |                 # после решения
sandbox: false             # true — песочница без целей, не влияет на прохождение
```

**После setup ученик всегда начинает в домашней папке `~` (`/home/student`)**, и `solution` выполняется оттуда же.

### Проверки (`check`)

Все проверки выполняются в репозитории, внутри которого сейчас находится ученик (ищется вверх от текущей папки).

| check | смысл |
|---|---|
| `{ repo: true }` | ученик внутри git-репозитория |
| `{ file: path }` | файл существует; `contains: "текст"` — содержит строку; `absent: true` — файла нет |
| `{ branch: name }` | ветка существует; `exists: false` — ветки нет |
| `{ head: name }` | текущая ветка — `name` |
| `{ commits: N }` | в HEAD (или `branch: x`) не меньше N коммитов |
| `{ message: regex }` | сообщение последнего коммита HEAD (или `branch`) подходит под regex |
| `{ clean: true }` | нет незакоммиченных изменений и незавершённого merge |
| `{ staged: path }` | файл в индексе с изменениями |
| `{ tracked: path }` | файл отслеживается git |
| `{ merged: a, into: b }` | ветка `a` влита в `b` |
| `{ tag: name }` | тег существует |
| `{ remote: origin }` | remote добавлен; с `branch: main` — ветка запушена и совпадает с локальной |

### Сценарии с «удалённым» репозиторием и тиммейтами

Remote — это папка: `git init --bare /srv/origin.git`. В setup можно сыграть за тиммейта в другой папке:

```yaml
setup:
  - git init --bare /srv/origin.git
  - mkdir /petya && cd /petya && git clone /srv/origin.git bot && cd bot && git config user.name Петя && echo x > a.txt && git add . && git commit -m "petya" && git push
  - cd /home/student && git clone /srv/origin.git bot
```

Поддерживаемые команды: `ls cd pwd cat echo (> >>) touch mkdir rm mv tree clear help`, `&&` и `;`.
Git: `init config status add rm commit (-m -a --amend) log (--oneline --all -n) show diff (--staged) restore reset (--soft --hard)
branch (-d -D -m -a) checkout (-b, файлы) switch (-c) merge (--no-ff --abort, конфликты) tag remote clone push (-u -f) fetch pull`.
**Нет:** rebase, stash, cherry-pick, revert, редактора (сообщение коммита — только `-m`).

> [!WARNING]
> Команды в YAML, содержащие `: ` (двоеточие с пробелом, например в сообщении коммита), **бери в одинарные кавычки**,
> иначе YAML превратит строку в объект: `- 'git commit -m "feat: x"'`.

## 7. Анимированные схемы — блок `anim`

Пошаговая анимация: узлы на сетке, по стрелкам летят «пакеты», подсвечиваются узлы, меняются подписи. Лучший способ объяснить
протоколы, жизненный цикл запроса, горутины и каналы, работу индекса, очередь сообщений, кэш.

```yaml
title: Путь запроса
nodes:                     # x, y — клетки сетки (≈170×110 px)
  - { id: client, label: Клиент, x: 0, y: 0, kind: actor }
  - { id: api, label: API, x: 1, y: 0, sub: "ждёт" }          # sub — вторая строка (моноширинная)
  - { id: db, label: Postgres, x: 2, y: 0, kind: db }
  - { id: cache, label: Redis, x: 1, y: 1, kind: box, w: 2 }  # w — ширина в клетках
edges:                     # статичные линии: [from, to] или [from, to, подпись]
  - [client, api]
  - [api, db, "SQL"]
steps:
  - text: Клиент отправляет запрос.            # markdown-подпись шага
    send: { from: client, to: api, label: "GET /users" }      # можно список send — несколько пакетов сразу
    highlight: [client]
  - text: API идёт в базу.
    send: { from: api, to: db, label: SELECT, color: "#4fb477" }
    set: { api: "ждёт БД" }       # поменять sub у узлов (состояние сохраняется на следующих шагах)
  - text: Появляется кэш.
    show: [cache]                # узлы из show скрыты до этого шага
    hide: [db]                   # скрыть узел начиная с этого шага
```

`kind`: `box` (по умолчанию), `actor` (скруглённый), `db` (цилиндр), `cloud` (пунктир), `queue` (с делениями),
`cell` (ячейка памяти), `note` (подсвеченная заметка).

Советы: 4–9 шагов, одна мысль на шаг, подпись шага — 1–2 предложения. Схема не засчитывается как задание.

## 9. Урок-чекпоинт

`checkpoint: true` во frontmatter. Это тест по модулю: если решено ≥ `pass` (по умолчанию 0.8) заданий урока,
ученику предлагается отметить **весь модуль** как пройденный. Нужен, чтобы знающие люди быстро проскакивали базу.
Обычно последний урок модуля; 5–10 вопросов на ключевые идеи модуля.

## 10. Роадмап — `roadmap.yaml`

Карта всего курса: узлы-темы со стрелками. Ученик может перетаскивать узлы, кликать (видит уроки темы и статус),
отмечать «я это уже знаю». Узел зеленеет, когда пройдены все связанные уроки.

```yaml
sections:                  # группы-цвета
  - { id: lang, title: Язык Go, color: '#5b9df5' }
nodes:
  - id: go-syntax
    title: Синтаксис Go
    section: lang
    x: 0                   # координаты в пикселях; узел ≈ 200×70, шаг сетки удобно брать 260×130
    y: 0
    description: Переменные, функции, управление потоком.   # markdown
    links: [go-basics, go-basics/slices]                   # id модуля целиком или "модуль/урок"
    optional: false        # true — пунктирная рамка «по желанию»
edges:
  - [go-syntax, go-structs]
```

`npm run check` проверит, что все `links` ведут на существующие модули/уроки, а рёбра — на существующие узлы.

## 11. Стиль текста

- **Тон — живой, неформальный, на «ты».** Как старший товарищ объясняет за ноутбуком. Шутки — можно, вода — нельзя.
- **Сначала зачем, потом как.** Каждую тему начинай с проблемы, которую она решает (лучше — из жизни хакатона).
- **Глубоко «почему».** Не «делай так», а «вот что происходит в памяти/сети/планировщике, поэтому так». Детали — в `[!DEEP]`.
- **Порциями.** Короткие абзацы, один шаг — одна идея, после теории — вопрос.
- **Код — рабочий и минимальный.** Каждый пример должен запускаться (`go run`). Не показывай код, который не компилируется,
  если это не специально (и тогда скажи об этом).
- **Задачи — от простого к сложному**, последняя задача урока — «на подумать».
- Термины: при первом упоминании — по-русски + оригинал: «горутина (goroutine)», «мьютекс (mutex)».

## 12. Проверка перед коммитом

```bash
npm run check                  # всё
npm run check -- --fast        # только схемы, без запуска кода
npm run check -- --course demo # один курс
npm run dev                    # посмотреть глазами
```

`check` падает, если: YAML не по схеме; у квиза нет правильного ответа; эталонное решение не проходит тесты; git-решение не
выполняет цели; ссылки роадмапа битые. Предупреждает, если стартовый код уже проходит тесты или у задачи нет тестов.
Сборка (`npm run build`) запускает `check` первым шагом — сломанный курс не задеплоится.
