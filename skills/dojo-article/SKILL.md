# Статья и интерактивный материал для Dojo

Статьи живут отдельно от курсов в `articles/<article-id>/`. Перед работой прочитай текущие `CLAUDE.md`, `BACKLOG.md`
и раздел «Статьи и интерактивные артефакты» в `docs/AUTHORING.md` — он главный источник правды о формате. Сверяйся
с кодом: `src/core/articles.ts` (схема `article.yaml`), `src/articles/runtime.ts` (`mount` и `ctx`),
`src/pages/Article.tsx`, `tools/check.ts`. Образцы: `articles/how-articles-work/` (Markdown + блок-интерактив)
и `articles/linear-programming/` (артефакт Claude, перенесённый почти без правок).

## Репозиторий и права

1. Узнай логин через `gh api user --jq .login`, затем проверь `git remote -v`. Локальное имя и `git config user.name` не являются доказательством владельца.
2. Логин `morsssch` → работай в копии `morsssch/dojo`. Другой логин → работай только в форке этого пользователя; при отсутствии форка предложи `gh repo fork morsssch/dojo --clone` и спроси подтверждение. Никогда не пушь материалы другого автора в оригинальный `morsssch/dojo`.
3. Если `gh auth` не настроен, предложи `! gh auth login`; не проси токены в чате и не записывай их в файлы.
4. Push, PR, создание форка и деплой — внешние действия. Перед ними покажи diff/результаты и получи явное подтверждение, если пользователь не поручил публикацию явно.

## Как устроена статья

```text
articles/<article-id>/          # id — латиница, kebab-case; после публикации не переименовывать
  article.yaml                  # title, subtitle, description, tags, draft, script, style, width
  index.md   или  index.html    # тело (index.html выигрывает, если есть оба)
  style.css                     # стили статьи — только токены Dojo
  *.js / *.ts                   # скрипт статьи и модули блоков; Vite компилирует TS, import работает
```

- **Тело в Markdown** (`index.md`): Markdown Dojo + формулы `$…$`, `$$…$$` + HTML-вставки. Для нового материала — по умолчанию.
- **Тело в HTML** (`index.html`): разметка без `<html>/<head>/<body>/<script>`. Для переноса готовых артефактов.
- **Скрипт статьи** (`script: ./x.js`): `export function mount(root, ctx)` — оживляет места крепления по `id`/`data-*`.
- **Блок-интерактив** в Markdown:

  ````markdown
  ```interactive
  id: wave
  module: ./wave.ts
  export: wave          # (el, props, ctx) => cleanup?; по умолчанию mount
  props: { amplitude: 1.5 }
  ```
  ````

Интерактив работает **прямо на странице, без iframe**: ищи элементы через `root`/`el`, не через `document`.
`ctx`: `typeset(el)` (формулы после вставки HTML), `tex(el, src, display?)`, `reducedMotion`, `store.get/set`,
`on(target, type, fn)`, `onCleanup(fn)`. Возвращай из `mount` функцию уборки, если запускаешь таймеры или `requestAnimationFrame`.

## Дизайн — всегда Dojo

Подача и интерактив могут быть богатыми (пошаговые разборы, анимации, графики, слайдеры), но **вид — Dojo**:

- цвета только токенами: `--text`, `--muted`, `--line`, `--line-2`, `--surface`, `--surface-2`, `--bg`, `--accent`
  (главный цвет линий и выделений), `--ok`, `--bad`, `--warn`, `--info`; полупрозрачность — `color-mix(in srgb, var(--accent) 15%, transparent)`;
- шрифты `--font-ui`, `--font-display`, `--font-mono`; радиусы `--r-s/m/l`; кнопки — классы `btn`, `btn primary`, `btn small`;
- без своих фонов страницы, декоративных шрифтов, эмодзи в интерфейсе и капса в подписях;
- оглавление в начале — нумерованные разделы со ссылками на подтемы, а не чек-лист;
- свои классы — с префиксом статьи: имена Dojo (`.toc`, `.toc-head`, `.panel`, `.bar`, `.tag`, `.md`) уже заняты.

## Перенос артефакта Claude (HTML с `<style>` и `<script>`)

Цель — интерактив «почти в первозданном виде», стиль — Dojo. Не переписывай движок артефакта заново и не упрощай его.

1. Сохрани исходник в изолированную временную папку и изучи: разметку, `<style>`, `<script>`, места крепления
   (`getElementById`, `querySelector`, `data-*`), что вшито (MathJax, шрифты — не переносить).
2. `<body>` без собственной шапки → `index.html`; заголовок и подзаголовок — в `article.yaml`.
3. `<style>` → `style.css`. Если палитра в переменных (`--ink`, `--blue`…), переопредели их токенами Dojo в `:root { … }`
   и оставь правила как есть; убери оформление страницы и стили кнопок артефакта.
4. `<script>` → модуль с `export function mount(root, ctx)`: `document.getElementById(x)` → `root.querySelector('#'+x)`,
   `document.querySelector(All)` → `root.querySelector(All)`, MathJax → `ctx.typeset` / `ctx.tex`,
   `window.addEventListener` → `ctx.on(window, …)`, `matchMedia(prefers-reduced-motion)` → `ctx.reducedMotion`.
   Остальной код — без изменений. Удобно делать это скриптом-заменой, а не вручную.
5. Якоря `href="#id"` работают сами. Чек-листы прогресса из артефакта убери — оглавление вместо них.
6. Убери личный контекст: имена людей, группы, даты занятий, названия вузов. Репозиторий публичный.

## Новый материал

Сохраняй авторскую структуру источника (разделы, определения, примеры, формулы, таблицы, разборы), не сокращай до выжимки.
Интерактив добавляй, когда он даёт пользу: шаги, параметры, вычисления, графики. Статичную схему оставляй Markdown/SVG/Mermaid.
Большой материал дели на разделы `##` с `id`, чтобы на них ссылалось оглавление.

## Проверка и передача

1. `npm run check` (ловит отсутствующие файлы, `mount`/`export` модулей, `<script>` в теле, цвета не токенами),
   `npx tsc -p tsconfig.json`, `npm run build`.
2. В браузере (`npm run dev`, страница `#/articles/<id>`): каждый интерактив, кнопки и анимации, формулы, оглавление
   и якоря, светлая и тёмная тема, ширина 390 px, нет ошибок в консоли. Сборка не доказывает, что интерактив работает.
3. Обнови `BACKLOG.md`: что перенесено, из какого источника, что осталось.
4. Покажи пользователю файлы, источник и результаты проверок. Коммит и push — только после согласования и только в
   репозиторий автора; внешний автор получает изменения в своём форке.
