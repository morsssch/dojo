# Операции возвращают отношения

Реляционная алгебра применяет операции к отношениям, а результат снова является отношением. Для примера возьмём `А = {(1, Книга), (2, Журнал)}` и `Б = {(2, Журнал), (3, Газета)}` с одинаковыми атрибутами `(id, тип)`.

**Объединение** `А ∪ Б` содержит кортежи из A или Б: три разных кортежа. **Разность** `А ∖ Б` содержит только `(1, Книга)`; `Б ∖ А` — только `(3, Газета)`. Для классических операций объединения, пересечения и разности отношения должны быть **совместимы по схеме**: соответствующие атрибуты и их домены согласованы. В конспекте рядом с объединением иногда стоит слово «соединение»; здесь не путай *объединение множеств строк* (`UNION`) с *соединением таблиц по общим атрибутам* (`JOIN`). Это разные операции.

```quiz
id: union-difference
kind: match
question: Для A = {1, 2} и Б = {2, 3} сопоставь результат.
pairs:
  - { left: A ∪ Б, right: "{1, 2, 3}" }
  - { left: A ∖ Б, right: "{1}" }
  - { left: Б ∖ A, right: "{3}" }
explain: Для объединения и разности нужны сопоставимые отношения; направление разности важно.
```

# Все комбинации — ещё не связанные строки

**Декартово произведение** `Читатель × Книга` соединяет *каждый* кортеж читателя с *каждым* кортежем книги. Если есть 3 читателя и 4 книги, получится 12 комбинаций — включая те, в которых читатель никогда не брал книгу. Произведение полезно как основа для последующего отбора связанных комбинаций, но само по себе не означает наличия реальной связи.

```quiz
id: cartesian-size
kind: number
question: Сколько строк в произведении отношения из 3 кортежей и отношения из 4 кортежей?
answer: 12
explain: Каждая строка первого отношения соединяется с каждой строкой второго; 3 × 4 = 12.
```

# SQL и математическая модель

В SQL `UNION` по умолчанию удаляет повторы, а `UNION ALL` сохраняет их; математика множеств рассматривает только уникальные кортежи. SQL-эквивалентом разности в PostgreSQL служит `EXCEPT`; произведение даёт `CROSS JOIN`. Чтобы эти операции имели смысл, проверяй схему, домены и условие отбора.

```quiz
id: union-vs-join
question: Надо добавить строки второго списка к первому, сохранив только уникальные строки одинаковой структуры. Какая операция подходит?
options:
  - text: Объединение (UNION)
    correct: true
  - text: Естественное соединение (JOIN)
    why: Соединение сопоставляет столбцы связанных строк, а не добавляет строки одного списка к другому.
  - text: Декартово произведение (CROSS JOIN)
    why: Произведение создаст все сочетания строк и обычно увеличит число столбцов.
explain: Объединение складывает совместимые наборы кортежей; соединение сопоставляет их по связи.
```

# Полный ответ для самопроверки

## Вопрос 32. Основные реляционные операции

Пусть A(x)={(1),(2)}, B(x)={(2),(3)}, C(y)={(a),(b)}. Объединение A∪B={(1),(2),(3)}, разность A∖B={(1)}, пересечение A∩B={(2)}; для этих операций нужны совместимые схемы и домены. Произведение A×C={(1,a),(1,b),(2,a),(2,b)} сочетает каждую строку с каждой.

Пусть R(id, имя, возраст)={(1, «Лев», 20),(2, «Лев», 21),(3, «Ира», 19)}. Селекция σ(возраст≥20)(R) оставляет первые два кортежа со всеми атрибутами; проекция π(имя)(R) даёт {(«Лев»),(«Ира»)} без повторов. Для Выдача(reader_id,book_id)={(1,7),(2,8)} и Книга(book_id,title)={(7,«Атлас»),(9,«Словарь»)} естественное соединение даёт {(1,7,«Атлас»)}: совпасть должны значения всех одноимённых атрибутов, каждый общий атрибут выводится один раз. Результат каждой операции — отношение. SQL SELECT без DISTINCT может сохранить повторы, в отличие от математической проекции.
