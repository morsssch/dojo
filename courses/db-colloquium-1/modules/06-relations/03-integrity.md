# Какая запись считается допустимой

**Целостность БД** означает, что данные удовлетворяют установленным правилам. **Ограничения целостности** — сами правила: уникальный `id`, обязательный `title`, ссылка `reader_id` только на существующего читателя, неотрицательная цена. Ключи обеспечивают идентификацию, внешние ключи — согласование связей, проверки — допустимые значения. Но БД не гарантирует, что все реальные события вообще были записаны: корректность правил и полнота ввода остаются задачами людей и приложений.

```sql
CREATE TABLE reader (id integer PRIMARY KEY);
CREATE TABLE loan (
  id integer PRIMARY KEY,
  reader_id integer NOT NULL REFERENCES reader(id),
  days integer NOT NULL CHECK (days > 0)
);
```

Попытка добавить выдачу с несуществующим `reader_id` нарушит ссылочную целостность. Проверка того, что книгу нельзя одновременно выдать дважды, потребует дополнительно сформулированного правила и корректной работы при конкуренции запросов.

```quiz

    correct: true
  - text: Индекс по названию книги

  - text: Сортировка по дате выдачи

```

# Два изменения как одно

При выдаче книги нужно добавить событие выдачи и поменять доступность экземпляра. Если записалось только одно, БД окажется в противоречивом состоянии. **Транзакция** объединяет несколько действий в единицу работы: при успехе фиксируем их вместе, при ошибке откатываем вместе.

Свойства **ACID** расшифровываются так:

- **Atomicity (атомарность):** всё или ничего.
- **Consistency (согласованность):** завершённая транзакция сохраняет *заданные* ограничения целостности.
- **Isolation (изоляция):** одновременно идущие транзакции не должны непредусмотренно мешать друг другу; конкретные гарантии зависят от уровня изоляции.
- **Durability (долговечность):** после подтверждения фиксации результат переживает сбои в рамках гарантий СУБД и её конфигурации.

> [!WARNING]
> «Согласованность» не означает, что СУБД самостоятельно проверяет смысл любого текста. Если не задать правило, ошибочное с точки зрения человека значение может быть допустимым для базы.

# Кто может читать и менять

**Защита БД** включает идентификацию пользователя, права на чтение/изменение, контроль доступа и организационные меры: резервное копирование, управление секретами, аудит. Права «может читать выдачи» и «может удалять читателей» не должны выдаваться автоматически вместе. Резервирование помогает при потере данных, а разграничение доступа — при несанкционированных изменениях; они решают разные задачи.

## Вопрос 31. Основные термины и понятия реляционных БД

Объект — сущность предметной области; атрибут — её свойство; домен — множество допустимых значений атрибута. Схема отношения задаёт атрибуты и их домены; отношение — конечное множество соответствующих кортежей. Кортеж содержит по значению для каждого атрибута. Потенциальный ключ — минимальный набор атрибутов, однозначно идентифицирующий кортеж; первичный ключ — выбранный потенциальный ключ. Например, Читатель(id, имя), кортеж (7, «Лев»), ключ id. Схема реляционной БД объединяет схемы отношений и ограничения, экземпляр БД — их текущие отношения.

Реляционная операция возвращает отношение; выражение сочетает такие операции, а его результат также является отношением. Запрос описывает, какие данные и по каким условиям нужны. СУБД предоставляет управление этой БД. DDL задаёт структуру (CREATE TABLE); DML читает и меняет данные (SELECT, INSERT, UPDATE, DELETE); язык запросов — средства получения данных в составе DML в принятой здесь классификации.

Целостность — выполнение заданных правил непротиворечивости и полноты, ограничения — формально записанные условия: ключи, обязательность значений, внешние ссылки и проверки. СУБД не может сама установить истинность любого введённого факта. Транзакция — единица работы: начало → операции → COMMIT при успехе либо ROLLBACK при отмене. ACID: атомарность — всё или ничего; согласованность — сохранение ограничений; изоляция — гарантии совместной работы согласно уровню изоляции; долговечность — сохранение зафиксированного результата после сбоев в пределах гарантий системы. Например, создание выдачи и смена доступности книги фиксируются вместе. Защита БД — меры против несанкционированного чтения, хищения, изменения и уничтожения: роли, права, аудит и организационные процедуры.
