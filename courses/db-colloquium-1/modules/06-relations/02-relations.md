# Таблица как отношение

Возьми отношение `Читатель(id, имя, email)`. **Объект** предметной области — читатель; **атрибут** — его свойство, например `email`. **Домен атрибута** — множество допустимых значений: для `id` это допустимые номера, для `email` — адреса в согласованном формате. В SQL допустимость `NULL` задаётся отдельно: это маркер отсутствия/неизвестности, а не обычный адрес из домена. **Схема отношения** описывает имя отношения, атрибуты, их домены и ограничения; **отношение** — набор кортежей, соответствующих схеме в конкретный момент. **Кортеж** — одна строка значений атрибутов.

| id | имя | email |
|---:|---|---|
| 1 | Ира | ira@example.test |
| 2 | Лев | lev@example.test |

Здесь `id` — **первичный ключ**: его значение уникально и не должно быть неопределённым, так что оно идентифицирует ровно один кортеж. Ключ может состоять и из нескольких атрибутов, если уникальна лишь их комбинация. Если одинаковые имена разрешены, `имя` ключом не подходит. **Схема реляционной БД** — совокупность схем связанных отношений (включая ограничения), **реляционная БД** — сами отношения и их данные, связанные по смыслу.

В классической математической модели отношение — множество без повторяющихся кортежей и без порядка строк. SQL-таблицы на практике допускают повторения при `SELECT` и неопределённый порядок вывода без `ORDER BY`; это практическое расширение, не повод считать порядок частью математического отношения.

# Запрос как выражение

**Реляционная операция** принимает отношение или отношения и возвращает отношение. **Реляционное выражение** сочетает операции: например, сначала выбрать выданные книги, затем оставить только названия. Результат — снова отношение; благодаря этому операции можно вкладывать друг в друга. **Реляционный запрос** формулирует, какие данные нужны и каким условиям они удовлетворяют; SQL `SELECT title FROM book WHERE year > 2020` — практический пример.

Не путай ключ с номером строки на экране: позиция меняется после сортировки, ключ остаётся тем же. Если у `Выдачи` есть `reader_id`, это ссылка на ключ читателя; такую ссылку называют **внешним ключом**. Он помогает не хранить выдачу для несуществующего читателя.

## Вопрос 31. Основные термины и понятия реляционных БД

Объект — сущность предметной области; атрибут — её свойство; домен — множество допустимых значений атрибута. Схема отношения задаёт атрибуты и их домены; отношение — конечное множество соответствующих кортежей. Кортеж содержит по значению для каждого атрибута. Потенциальный ключ — минимальный набор атрибутов, однозначно идентифицирующий кортеж; первичный ключ — выбранный потенциальный ключ. Например, Читатель(id, имя), кортеж (7, «Лев»), ключ id. Схема реляционной БД объединяет схемы отношений и ограничения, экземпляр БД — их текущие отношения.

Реляционная операция возвращает отношение; выражение сочетает такие операции, а его результат также является отношением. Запрос описывает, какие данные и по каким условиям нужны. СУБД предоставляет управление этой БД. DDL задаёт структуру (CREATE TABLE); DML читает и меняет данные (SELECT, INSERT, UPDATE, DELETE); язык запросов — средства получения данных в составе DML в принятой здесь классификации.

Целостность — выполнение заданных правил непротиворечивости и полноты, ограничения — формально записанные условия: ключи, обязательность значений, внешние ссылки и проверки. СУБД не может сама установить истинность любого введённого факта. Транзакция — единица работы: начало → операции → COMMIT при успехе либо ROLLBACK при отмене. ACID: атомарность — всё или ничего; согласованность — сохранение ограничений; изоляция — гарантии совместной работы согласно уровню изоляции; долговечность — сохранение зафиксированного результата после сбоев в пределах гарантий системы. Например, создание выдачи и смена доступности книги фиксируются вместе. Защита БД — меры против несанкционированного чтения, хищения, изменения и уничтожения: роли, права, аудит и организационные процедуры.
