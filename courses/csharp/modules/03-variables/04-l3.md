# Два подкласса типов

Все типы данных делятся на 2 подкласса:

- **Значимые типы.** Хранят значение.
- **Ссылочные типы.** Хранят ссылку.

| Значимые | Ссылочные |
| --- | --- |
| Числа | Любые классы |
| Логические | Интерфейсы |
| char | Делегаты |
| Кортежи | Массивы |
| Структуры | Тип string |
|  | Записи |

![Переменные a и b хранят по своей копии числа на стеке; переменные x и y хранят одну и ту же ссылку на массив в куче](./diagrams/csharp/diagram-2.svg)

По лекции: для значимых типов память выделяется на стеке, для ссылочных — в динамической памяти. System.Object находится на вершине иерархии.

В отличие от C++, и в .net, и в JVM ссылки управляются средой исполнения. Среде известно, сколько ссылок указывает на данные ссылочного типа, поэтому она может **двигать данные в памяти**. Память освобождается, когда исчезают все переменные, указывающие на элемент.

```cs run
int a = 5;
int b = a;      // копия значения
b = 100;
Console.WriteLine(a); // 5

int[] x = { 1, 2, 3 };
int[] y = x;    // копия ССЫЛКИ, массив один
y[0] = 100;
Console.WriteLine(x[0]); // 100
```

> [!DEEP] В конспекте / на самом деле
> «Значимые — на стеке» — упрощение. Локальная переменная `int` действительно на стеке, но поле `int` внутри объекта класса живёт вместе с объектом в куче. Точнее: значимый тип хранится **там, где объявлен**, ссылочный — всегда в куче, а в переменной лежит ссылка.
> 
> - «Память освобождается, когда исчезают все ссылки» — точнее, объект становится **доступен** для сборщика мусора (GC), а освободит он его позже, когда сам решит.
> 
> - В таблице с лекции записи стоят в ссылочных — это `record` (он же `record class`). Бывает ещё `record struct`, он значимый.

````task
  using System;

  class Program
  {
      // AddOne и AddOneToAll

      static void Main()
      {
          int n = 10;
          int[] arr = { 10, 20 };
          AddOne(n);
          AddOneToAll(arr);
          Console.WriteLine(n);
          Console.WriteLine(arr[0] + " " + arr[1]);

  }
solution: |-
  using System;

  class Program
  {
      static void AddOne(int x) { x++; }
      static void AddOneToAll(int[] arr)
      {
          for (int i = 0; i < arr.Length; i++) arr[i]++;
      }

      static void Main()
      {
          int n = 10;
          int[] arr = { 10, 20 };
          AddOne(n);
          AddOneToAll(arr);
          Console.WriteLine(n);
          Console.WriteLine(arr[0] + " " + arr[1]);
      }
  }
tests:
  - stdout: |-
      10
      11 21
hints:
  - 'В AddOneToAll цикл for по индексам: arr[i]++. В AddOne просто x++ — и это изменение останется внутри метода.'
````


# null — ссылка в никуда

Ссылочная переменная может не указывать ни на какой объект. Это значение `null`. Обращение к члену через null — исключение `NullReferenceException`, самая частая ошибка в C#.

```cs run
string? s = null;               // ? — «здесь может быть null»
Console.WriteLine(s == null);
Console.WriteLine(s?.Length);    // ?. — если s null, результат null, без исключения
Console.WriteLine(s ?? "пусто"); // ?? — «если слева null, взять правое»
Console.WriteLine(s.Length);     // NullReferenceException
```

Значимые типы null быть не могут: `int x = null;` не скомпилируется. Если нужно «число или ничего», есть `int?`. Поэтому во всех лабах стоит требование «проверка параметров на null»: строки, массивы и объекты могут прийти пустыми ссылками.

# Методы System.Object и совместимость

Базовые методы System.Object, применимые к любым сущностям в C#:

- `.ToString()` — строковое представление объекта;
- `.GetHashCode()` — хэш-функция объекта;
- `.Equals(object a)` — `true`, если объекты совпадают по содержанию.

Поэтому можно написать даже `5.ToString()` или `(5 + 9).ToString()`.

> [!DEEP] В конспекте / на самом деле
> В конспекте метод назван `.GetHash()`, правильно `GetHashCode()`. Ещё у Object есть `GetType()` — он возвращает тип объекта, пригодится в рефлексии.

**Правило совместимости:** с классом совместимы объект самого класса или его прямые или косвенные наследники. Так как Object — предок всех, в переменную `object` можно положить что угодно.

```cs run
object o1 = 5;
object o2 = "строка";
object o3 = new int[] { 1, 2 };
Console.WriteLine(5.ToString() + (5 + 9).ToString());
Console.WriteLine(o1.GetType() + " | " + o2.GetType() + " | " + o3.GetType());
Console.WriteLine(o1.Equals(5));
```


# Boxing и unboxing

В примере `object o = 5;` мы приводим значимый тип к ссылочному, и происходит так называемый **boxing** (упаковка). Создаётся **обёртка**, хранимая в динамической памяти, где хранится само значение 5 и тип объекта, в данном случае `int`.

Аналогично для `5.ToString()`: сначала для 5 создаётся обёртка, и уже для обёртки вызывается `.ToString()`.

![object o = 5 создаёт в куче коробку с типом Int32 и значением 5, переменная o хранит ссылку на неё](./diagrams/csharp/diagram-3.svg)

В примере `int i = (int)o;` происходит обратное действие — **unboxing** (распаковка).

**Ключевое правило:** из упаковки можно достать только тот тип данных, который в ней хранится. `double y = (double)o;` приведёт к ошибке. Решение: `double y = (double)(int)o;` — сначала распаковать как `int`, потом обычным преобразованием сделать `double`.

```cs run
object o = 5;            // boxing
int i = (int)o;          // unboxing
Console.WriteLine(i);

double ok = (double)(int)o;
Console.WriteLine(ok);

double bad = (double)o;  // упадёт: в коробке int, а не double
Console.WriteLine(bad);
```

> [!DEEP] Уточнение про 5.ToString()
> В конспекте сказано, что для `5.ToString()` создаётся обёртка. На самом деле `int` сам переопределяет `ToString`, и компилятор вызывает его без упаковки. Упаковка при вызове метода случается, когда метод не переопределён в структуре и берётся из `object` (например, `GetType()`). Если преподаватель спросит именно про пример с лекции — отвечай по лекции: «создаётся обёртка»; если копнёт глубже — вот уточнение.


# Три способа приведения: (тип), as, is

| Запись | Для чего | Если не получилось |
| --- | --- | --- |
| `(тип) значение` | Стандартное C-подобное преобразование | Ошибка. Компилятор не всегда может обнаружить её заранее, тогда при выполнении летит исключение `InvalidCastException` |
| `значение as тип` | Преобразование для **ссылочного** типа | Ошибка не пробрасывается, возвращается `null` |
| `значение is тип` | Проверка | `true`, если значение слева можно привести к типу справа |

```cs run
object o = "hello";

string? s = o as string;       // получилось: s = "hello"
int[]? arr = o as int[];       // не получилось: null, без исключения
Console.WriteLine(s + " " + (arr == null));

Console.WriteLine(o is string);  // True
Console.WriteLine(o is int);     // False

if (o is string text)            // проверка и приведение сразу
    Console.WriteLine(text.ToUpper());
```

Последняя форма `o is string text` — сопоставление с образцом (pattern). преподаватель обещал подробнее позже, но её удобно знать уже сейчас: проверили и сразу получили переменную нужного типа.

Почему as только для ссылочных
Если не вышло, `as` возвращает `null`, а обычный `int` не может быть null. Поэтому `o as int` не компилируется. Можно `o as int?` — это int, допускающий null.


# Задача: что лежит в коробке


````task
id: step-8
lang: cs
title: 'Задача: что лежит в коробке'
prompt: |-
  Допиши метод `Describe(object o)`, который возвращает строку:

  - для `int` — `целое: N`;
  - для `double` — `дробное: N`;
  - для `string` — `строка длины L`;
  - для `null` — `пусто`;
  - для всего остального — `другое: ИмяТипа` (короткое имя, `o.GetType().Name`).

  Используй `is`. Main уже написан, его не меняй.
starter: |-
  using System;

  class Program
  {
      static string Describe(object o)
      {
          // твой код
          return "";
      }

      static void Main()
      {
          Console.WriteLine(Describe(42));
          Console.WriteLine(Describe(2.5));
          Console.WriteLine(Describe("hello"));
          Console.WriteLine(Describe(null));
          Console.WriteLine(Describe(new int[3]));
          Console.WriteLine(Describe('x'));
      }
  }
solution: |-
  using System;

  class Program
  {
      static string Describe(object o)
      {
          if (o is null) return "пусто";
          if (o is int i) return "целое: " + i;
          if (o is double d) return "дробное: " + d;
          if (o is string s) return "строка длины " + s.Length;
          return "другое: " + o.GetType().Name;
      }

      static void Main()
      {
          Console.WriteLine(Describe(42));
          Console.WriteLine(Describe(2.5));
          Console.WriteLine(Describe("hello"));
          Console.WriteLine(Describe(null));
          Console.WriteLine(Describe(new int[3]));
          Console.WriteLine(Describe('x'));
      }
  }
tests:
  - stdout: |-
      целое: 42
      дробное: 2,5
      строка длины 5
      пусто
      другое: Int32[]
      другое: Char
hints:
  - 'Сначала проверь null (o == null или o is null). Потом if (o is int i) return "целое: " + i; и так далее.'

    - Используй оператор is.
````

# Как это могут спросить на защите


````cards
id: step-12
title: Как это могут спросить на защите
items:
  - q: Что такое boxing?
    a: Приведение значимого типа к ссылочному, например `object o = 5;`. В динамической памяти создаётся обёртка, где хранится само значение и его тип. Обратное действие — unboxing, `(int)o`.
  - q: Почему `(double)o` падает, если в o лежит 5?
    a: 'Из упаковки можно достать только тот тип, который в ней хранится, а там int. Правильно `(double)(int)o`: сначала распаковка, потом обычное преобразование.'
  - q: Чем as отличается от приведения в скобках?
    a: '`as` работает только для ссылочных типов и при неудаче возвращает null, не бросая исключение. Приведение `(тип)` при неудаче бросает InvalidCastException.'
  - q: Где хранятся значимые и ссылочные типы?
    a: 'По лекции: значимые — на стеке, ссылочные — в динамической памяти. Уточнение, если спросят глубже: значимый тип хранится там, где объявлен, поэтому поле-int внутри объекта класса лежит в куче вместе с объектом.'
````
