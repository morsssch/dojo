# Три подхода к ООП

**Базовый принцип ООП**: существует множество сущностей, у каждой из которых есть свойства и поведение, и они обмениваются между собой событиями.

Известный нам подход из Java и .net — **классы с наследованием** — только один из трёх:

- **Классы с наследованием** — Java, .net, C#.

- **Объект-прототип** — лежит в основе JavaScript.

- **Обобщённые методы** — в смешанном виде в Lisp, Go, Rust.

> [!NOTE] Пример с лекции: барабаны и палочки
> На барабанной установке много разных барабанов и видов палочек. Каждая уникальная комбинация барабана и палочки даёт уникальный звук. В привычном нам подходе это очень неудобно: придётся прописать во всех барабанах варианты палочек или наоборот. А в подходе обобщённых методов это естественный способ проектирования: метод «ударить» выбирается сразу по двум типам — барабана и палочки.

Тебе, кстати, из JavaScript знаком второй подход: там объект наследует напрямую от другого объекта через прототип, а классы — синтаксическая надстройка над этим.


# Template и pattern

На русский «template» и «pattern» переводятся одинаково — «шаблон», но в оригинале смысл совсем разный:

|  | template | pattern |
| --- | --- | --- |
| Образ | Пресс-форма, по которой штампуется предмет | Распознающий шаблон |
| Что делает | **Порождает** предмет | Ничего не порождает, **определяет соответствие** условию |
| Где встретишь | Ключевое слово `template` в C++; обобщения `List` в C# | Сопоставление с образцом: `o is int n`, `switch` с шаблонами |

В C# «pattern matching» переводят как «сопоставление с образцом». Ты уже видел его в `if (o is string text)`.


# Свойства и инкапсуляция

**Свойства** — внешне наблюдаемые характеристики сущности. Внутреннее состояние и принципы работы должны быть скрыты — это **инкапсуляция**.

**Задача инкапсуляции** — сокрытие внутренней работы класса и обеспечение внутренней целостности объекта.

> [!NOTE] Пример нарушения целостности с лекции
> Существует ящик с 10 яблоками. Пользователь подходит и директивно говорит: «здесь 5 яблок». А внутреннее состояние осталось старым — объект врёт сам себе.

```cs run
class BadBox
{
    public int Count;                 // открытое поле: кто угодно запишет что угодно
    public string[] Apples = new string[0];   // на самом деле яблок нет
}

class GoodBox
{
    private readonly List apples = new();
    public int Count => apples.Count;  // только чтение, считается из реального содержимого
    public void Put(string apple)
    {
        if (apple == null) throw new ArgumentNullException(nameof(apple));
        apples.Add(apple);
    }
    public string Take()
    {
        if (apples.Count == 0) throw new InvalidOperationException("Ящик пуст");
        string a = apples[apples.Count - 1];
        apples.RemoveAt(apples.Count - 1);
        return a;
    }
}

class Program
{
    static void Main()
    {
        var bad = new BadBox();
        bad.Count = 5;                 // «здесь 5 яблок», а их ноль — целостность нарушена
        Console.WriteLine($"BadBox: Count={bad.Count}, реально яблок: {bad.Apples.Length}");

        var good = new GoodBox();
        for (int i = 0; i < 10; i++) good.Put("яблоко " + i);
        good.Take();
        // good.Count = 5;             // не скомпилируется: свойство только для чтения
        Console.WriteLine($"GoodBox: Count={good.Count}");
    }
}
```


# Класс и интерфейс: два вопроса

В общем смысле **класс** — это набор объектов, которые обладают одинаковым набором свойств и поведения.

|  | Отвечает на вопрос | Пример с лекции |
| --- | --- | --- |
| **Класс** | Чем **является** объект? | Шкаф является мебелью. Платяной шкаф является шкафом. Чем ниже спускаемся по иерархии, тем детальнее описание объекта |
| **Интерфейс** | Какой **функционал поддерживает** объект? | Интерфейс — стандарт на взаимодействие нескольких частей |

![Вложенные множества: мебель содержит шкафы, шкафы содержат платяные шкафы](./diagrams/csharp/diagram-5.svg)

В коде это выглядит так: наследование через двоеточие отвечает «чем является», интерфейсы через запятую — «что умеет».

```cs
class Furniture { }
class Wardrobe : Furniture { }                        // шкаф является мебелью
class ClothesWardrobe : Wardrobe, ILockable { }       // платяной шкаф — шкаф, и его можно запереть
interface ILockable { void Lock(); }
```
