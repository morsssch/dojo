# С маленькой или с большой: как решить за три вопроса

Сначала договоримся о словах. В классе живут два вида «переменных»:

- **поле** — ячейка памяти внутри объекта. По соглашению закрытые поля пишут **с маленькой** буквы: `owner`, `balance`;

- **свойство** — «окошко» к данным для внешнего кода, по сути пара методов get/set. Его пишут **с большой**: `Owner`, `Balance`.

Большая или маленькая буква сама по себе ничего не делает, это только соглашение. Важно другое: **поле — это хранилище, свойство — это доступ**. Чтобы понять, что писать, задай про каждое значение три вопроса по порядку.

> [!NOTE] Вопрос 1. Нужно ли это значение снаружи класса?
> **Нет** → только закрытое поле с маленькой буквы, свойство не нужно. Пример: внутренний список, вспомогательный счётчик.
> 
> ```cs
> private readonly List log = new();   // никто снаружи про него не знает
> ```
> 
> **Да** → нужно свойство с большой буквы. Переходи к вопросу 2.

> [!NOTE] Вопрос 2. Это значение хранится или вычисляется из других?
> **Вычисляется** → свойство со стрелкой, поля нет вообще:
> 
> ```cs
> public string Masked => new string('*', 4) + Number.Substring(4);
> ```
> 
> **Хранится** → переходи к вопросу 3.

> [!NOTE] Вопрос 3. Нужно ли что-то делать при записи: проверить, обрезать, пересчитать?
> **Нет** → **автосвойство**, только с большой буквы. Поле с маленькой **не заводи**: компилятор создаст скрытое поле сам. Остаётся выбрать, кто может записывать:
> 
> ```cs
> public string Number { get; }                // записать можно только в конструкторе
> public int BooksTaken { get; private set; }   // снаружи только читать, внутри класса — менять
> public string Title { get; set; }             // читать и писать могут все
> ```
> 
> **Да** → **пара**: закрытое поле с маленькой (там лежат данные) и свойство с большой (там проверка):
> 
> ```cs
> private string owner = "";          // хранилище
> public string Owner                 // доступ с проверкой
> {
>     get => owner;
>     set
>     {
>         if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустое имя");
>         owner = value.Trim();
>     }
> }
> ```

## Все четыре случая на одном классе

| Что за значение | Как пишется | Поле с маленькой? |
| --- | --- | --- |
| Внутреннее, снаружи не нужно | `private List log` | только оно |
| Наружу, вычисляется | `public string Masked => …;` | нет |
| Наружу, хранится, без проверок | `public string Number { get; }` | нет — компилятор сделает сам |
| Наружу, хранится, с проверкой | `private string owner;` + `public string Owner { get => owner; set { … } }` | да, пара |

## Правило работы с парой

Если у значения есть пара «поле + свойство», то **везде, кроме самих get и set, работай со свойством** (с большой). И в конструкторе тоже: `Owner = owner;`, а не `this.owner = owner;`. Тогда проверка из set срабатывает всегда. С полем (с маленькой) напрямую работают только get и set этого свойства.

> [!WARNING] Самая частая путаница
> ```cs
> private string number;           // поле, которое ты завёл
> public string Number { get; }    // автосвойство — у него СВОЁ скрытое поле
> 
> public LibraryCard(string number)
> {
>     this.number = number;        // записал в своё поле…
> }
> // …а Number читает скрытое поле автосвойства, там null → NullReferenceException
> ```
> 
> Поле `number` и автосвойство `Number` никак не связаны, хоть имена и похожи. Связь появляется, только если ты сам пишешь `get => number;`. Правило: **у автосвойства своего поля не бывает**. Если написал `{ get; }`, лишнее поле удали.

# private, protected, public: кому что видно

Модификатор доступа отвечает на вопрос «**чей код** может обратиться к этому члену». Не «какой объект», а именно «код какого класса».

| Модификатор | Код этого класса | Код наследника | Любой другой код |
| --- | --- | --- | --- |
| `private` | да | нет | нет |
| `protected` | да | да | нет |
| `public` | да | да | да |

Член без модификатора — `private`. Есть ещё `internal` («видно внутри своего проекта»), но в лабах он почти не нужен.

## Пример: банковский счёт и наследник

```cs run
class Account
{
    private decimal balance;                     // private: деньги трогает только сам Account
    public decimal Balance => balance;           // public: смотреть можно всем

    protected void Change(decimal delta, string reason)   // protected: инструмент для наследников
    {
        if (balance + delta < 0) throw new InvalidOperationException("Недостаточно средств");
        balance += delta;
        Console.WriteLine($"  {reason}: {delta:+0.##;-0.##} → {balance}");
    }

    public void Deposit(decimal amount)          // public: то, что можно делать снаружи
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        Change(amount, "пополнение");
    }
}

class SavingsAccount : Account
{
    public void AddInterest(decimal percent)
    {
        // balance += …;          // CS0122: private поле предка наследнику не видно
        Change(Balance * percent / 100, "проценты");   // а protected метод — виден
    }
}

class Program
{
    static void Main()
    {
        var acc = new SavingsAccount();
        acc.Deposit(1000);
        acc.AddInterest(5);
        Console.WriteLine("Баланс: " + acc.Balance);
        // acc.Change(1_000_000, "хочу");   // CS0122: protected не виден из Program
    }
}
```

Что здесь видно:

- `balance` — **private**. Даже наследник не может написать в него напрямую, иначе он мог бы обойти проверку «не уйти в минус».

- `Change` — **protected**. Это «внутренний инструмент» для семьи классов: наследник может менять баланс, но только через проверку. Внешний код (`Program`) его не видит.

- `Deposit`, `Balance` — **public**: это то, что класс обещает внешнему миру.

## Как выбирать

- **По умолчанию — private.** Всё, про что не можешь объяснить, зачем это нужно снаружи, закрывай.

- **public** — только то, чем пользуется внешний код: методы-действия (`Deposit`, `Take`) и свойства на чтение.

- **protected** — только если класс задуман как **базовый** (от него будут наследоваться), и наследникам реально нужен доступ: вспомогательный метод (`Change`), конструктор абстрактного класса (`protected Employee(string name)`), `protected set` у свойства. Поля почти никогда не делают protected: лучше private поле и protected метод с проверкой, как `Change`.

- Если класс **не** предназначен для наследования (а это большинство классов в лабах) — protected тебе не нужен. Хватает private и public.

## У свойства доступ можно разделить

```cs
public int Attempts { get; private set; }     // читают все, пишет только этот класс
public decimal Balance { get; protected set; } // читают все, пишет этот класс и наследники
```

Модификатор перед свойством — для чтения, модификатор перед `set` — более строгий, только для записи.
