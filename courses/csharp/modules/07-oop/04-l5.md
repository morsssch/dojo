# Зачем свойства: от открытого поля к get и set

Задача: у кошелька есть баланс. Снаружи его нужно **видеть**, но нельзя **записать** что попало. Посмотрим, как к этому приходят, в три шага.

## Шаг 1. Открытое поле — плохо

```cs
class Wallet
{
    public decimal Balance;     // кто угодно может написать w.Balance = 1_000_000;
}
```

Это нарушение инкапсуляции, как ящик с яблоками из лекции: состояние объекта меняют в обход его правил.

## Шаг 2. Закрытое поле + метод-«геттер» — работает, но громоздко

```cs
class Wallet
{
    private decimal balance;
    public decimal GetBalance() { return balance; }   // так делают в Java
}
// снаружи: w.GetBalance()
```

## Шаг 3. Свойство — то же самое, но удобно

```cs
class Wallet
{
    private decimal balance;
    public decimal Balance           // свойство: снаружи выглядит как поле
    {
        get { return balance; }      // что вернуть при чтении w.Balance
    }
}
// снаружи: Console.WriteLine(w.Balance);   а w.Balance = 5; — ошибка CS0200
```

Свойство — это пара методов с удобной записью. Компилятор превращает `get` в метод `get_Balance()`, а `set` — в `set_Balance(value)`. Снаружи пишешь `w.Balance`, как будто это поле, а внутри выполняется твой код.

Короткие формы того же самого:

```cs
public decimal Balance { get { return balance; } }   // полная
public decimal Balance { get => balance; }           // get стрелкой
public decimal Balance => balance;                   // только чтение, самая короткая
```

Если нужна и запись, добавляется `set`. Новое значение приходит в него в скрытой переменной `value`, и тут можно проверить его перед записью:

```cs
public string Owner
{
    get => owner;
    set
    {
        if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустое имя");
        owner = value;               // value — то, что стоит справа в w.Owner = "Марк"
    }
}
```

Дальше — все виды свойств в одном примере и таблица, к которой стоит возвращаться при решении задач.


# Свойства: get и set

Свойство выглядит снаружи как поле, а внутри это пара методов: `get` (чтение) и `set` (запись, новое значение приходит в `value`). Вот так инкапсуляция делается на практике.

```cs run
class Account
{
    private string owner = "";
    private decimal balance;

    public string AccountNumber { get; }                  // только чтение, задаётся в конструкторе

    public decimal Balance                                // чтение всем, запись — только своим и наследникам
    {
        get => balance;
        protected set => balance = value;
    }

    public string Owner                                   // чтение/запись с валидацией
    {
        get => owner;
        set
        {
            if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Имя владельца пустое");
            owner = value.Trim();
        }
    }

    public int Version { get; private set; }              // автосвойство с закрытой записью

    public Account(string number, string owner)
    {
        AccountNumber = number;
        Owner = owner;                                    // проверка сработает и здесь
    }

    public void Deposit(decimal amount)
    {
        if (amount  0");
        Balance += amount;
        Version++;
    }
}

class Program
{
    static void Main()
    {
        var acc = new Account("40817-001", "  Марк ");
        acc.Deposit(1500m);
        Console.WriteLine($"{acc.AccountNumber} | {acc.Owner} | {acc.Balance} | v{acc.Version}");
        try { acc.Owner = " "; }
        catch (ArgumentException e) { Console.WriteLine("Ошибка: " + e.Message); }
        // acc.Balance = 1_000_000;   // CS0272: set защищённый
        // acc.AccountNumber = "x";   // CS0200: свойство только для чтения
    }
}
```

| Запись | Смысл |
| --- | --- |
| `public int X { get; set; }` | автосвойство: компилятор сам создаёт скрытое поле |
| `public int X { get; }` | только чтение, присвоить можно в конструкторе |
| `public int X { get; private set; }` | снаружи только чтение, внутри класса можно менять |
| `public int X { get; init; }` | можно задать только при создании: `new P { X = 5 }` |
| `public int X => выражение;` | вычисляемое свойство только для чтения (стрелочная форма) |


# Задача: кошелёк


````task
id: step-3
lang: cs
title: 'Задача: кошелёк'
prompt: |-
  Кошелёк — классический пример инкапсуляции. Деньги лежат в закрытом поле, менять их можно только через методы с проверками. Снаружи баланс видно, но записать в него нельзя.

  **Что написать**

  - `class Wallet` с закрытым полем `balance` типа `decimal`. Конструктор писать не нужно: подойдёт тот, что добавляет компилятор, и баланс начнётся с 0.
  - Свойство `Balance` типа `decimal` только для чтения — возвращает поле. Удобнее всего стрелочной формой из таблицы выше.
  - Метод `public void Deposit(decimal amount)` — положить деньги. Если `amount  balance`) — `InvalidOperationException`. Обе проверки делай **до** вычитания, чтобы при ошибке баланс не изменился.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  var w = new Wallet();          // конструктор без параметров: его добавил компилятор
  w.Deposit(1000m);              // m — суффикс типа decimal
  w.Withdraw(250.5m);
  Console.WriteLine(w.Balance);  // 749,5
  w.Withdraw(5000m);             // InvalidOperationException, баланс остаётся 749,5
  w.Deposit(-1m);                // ArgumentOutOfRangeException
  // w.Balance = 100;            // не должно компилироваться: свойство только для чтения
  ```
starter: |-
  class Wallet
  {
  }
solution: |-
  class Wallet
  {
      private decimal balance;
      public decimal Balance => balance;

      public void Deposit(decimal amount)
      {
          if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
          balance += amount;
      }

      public void Withdraw(decimal amount)
      {
          if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
          if (amount > balance) throw new InvalidOperationException("Недостаточно средств");
          balance -= amount;
      }
  }

      мало денег 100
      плохая сумма
      False
    harness: |-
      var w = new Wallet();
      w.Deposit(100m);
      try { w.Withdraw(500m); } catch (InvalidOperationException) { Console.WriteLine("мало денег " + w.Balance); }
      try { w.Deposit(-1m); } catch (ArgumentOutOfRangeException) { Console.WriteLine("плохая сумма"); }
````

# Задача: класс Temperature


````task
id: step-4
lang: cs
title: 'Задача: класс Temperature'
prompt: |-
  Температура, которая не даёт задать значение ниже абсолютного нуля и сама переводит градусы Цельсия в Фаренгейты. Тренируем свойство с проверкой в `set` и вычисляемое свойство.

  **Что написать**

  - `class Temperature` с закрытым полем `celsius` типа `double`.
  - Свойство `Celsius` с `get` и `set`. `get` возвращает поле. `set` получает новое значение в `value`: если оно меньше −273,15, бросает `ArgumentOutOfRangeException`, иначе записывает его в поле.
  - Свойство только для чтения `Fahrenheit` = Celsius × 9 / 5 + 32, в стрелочной форме `=>`. Отдельное поле для него не нужно: оно каждый раз считается из Celsius.
  - Конструктор `public Temperature(double celsius)`. Присваивай **свойству**, а не полю: `Celsius = celsius;`. Тогда проверка из `set` сработает и при создании объекта.
  - `public override string ToString()` — температура с одним знаком после запятой и значком градуса: `$"{Celsius:F1}°C"`.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  var t = new Temperature(36.6);
  Console.WriteLine(t);                            // 36,6°C
  Console.WriteLine(t.Fahrenheit.ToString("F2"));  // 97,88
  t.Celsius = 100;                                 // сработает set
  Console.WriteLine(t.Fahrenheit);                 // 212
  t.Celsius = -300;                                // ArgumentOutOfRangeException, значение остаётся 100
  new Temperature(-500);                           // тоже ArgumentOutOfRangeException
  ```

  В коде дробная часть пишется через точку: `-273.15`. Запятая появляется только при выводе — так настроена русская культура.
starter: |-
  class Temperature
  {
      // твой код
  }
solution: |-
  class Temperature
  {
      private double celsius;

      public double Celsius
      {
          get => celsius;
          set
          {
              if (value < -273.15) throw new ArgumentOutOfRangeException(nameof(value), "Ниже абсолютного нуля");
              celsius = value;
          }
      }

      public double Fahrenheit => Celsius * 9 / 5 + 32;

      public Temperature(double celsius)
      {
          Celsius = celsius;
      }

      public override string ToString() => $"{Celsius:F1}°C";
  }
tests:

    harness: |-

      Console.WriteLine(t.Fahrenheit.ToString("F2"));
  - name: изменение через свойство
    stdout: '212'
    harness: |-
      var t = new Temperature(0);
      t.Celsius = 100;
      Console.WriteLine(t.Fahrenheit);
  - name: валидация в set
    stdout: |-
      ok
      10,0°C
    harness: |-
      var t = new Temperature(10);
      try { t.Celsius = -300; Console.WriteLine("нет исключения"); }
      catch (ArgumentOutOfRangeException) { Console.WriteLine("ok"); }

  - name: валидация в конструкторе
    stdout: ok
    harness: |-
      try { new Temperature(-500); Console.WriteLine("нет исключения"); }
      catch (ArgumentOutOfRangeException) { Console.WriteLine("ok"); }
  - name: Fahrenheit только для чтения
    stdout: 'True'
    harness: |-

  - public double Celsius { get => celsius; set { if (value < -273.15) throw new ArgumentOutOfRangeException(nameof(value)); celsius = value; } } и в конструкторе Celsius = celsius;
````

# Задача: свойства студента


````task
id: step-5
lang: cs
title: 'Задача: свойства студента'
prompt: |-
  Студент с четырьмя свойствами четырёх разных видов — по одному на каждую строку таблицы из теории.

  **Что написать**

  - `Name` (string) — чтение и запись, с собственным закрытым полем. В `set`: если строка пустая, из одних пробелов или null — `string.IsNullOrWhiteSpace(value)` — брось `ArgumentException`; иначе сохрани её без пробелов по краям: `value.Trim()`.
  - `Number` (int) — только чтение: `{ get; }`. Задаётся в конструкторе.
  - `Variant` (int) — вычисляемое, стрелочной формой: остаток `Number % 5`, а если остаток 0, то 5.
  - `Attempts` (int) — снаружи только чтение, внутри класса можно менять: `{ get; private set; }`. Начинается с 0.
  - Метод `public void Submit()` — увеличивает Attempts на 1.
  - Конструктор `public Student(string name, int number)`: если `number <= 0` — `ArgumentOutOfRangeException`. Имя присваивай через свойство `Name = name;`, чтобы сработала проверка из set.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  var s = new Student("  Марк ", 7);
  s.Submit();
  s.Submit();
  Console.WriteLine($"[{s.Name}] {s.Number} {s.Variant} {s.Attempts}");  // [Марк] 7 2 2
  Console.WriteLine(new Student("Аня", 10).Variant);                    // 5
  s.Name = "  ";              // ArgumentException, имя остаётся "Марк"
  new Student("X", 0);        // ArgumentOutOfRangeException
  // s.Number = 8;  s.Attempts = 0;  s.Variant = 1;   — всё это не должно компилироваться
  ```
starter: |-
  class Student
  {
  }
solution: |-
  class Student
  {
      private string name = "";

      public string Name
      {
          get => name;
          set
          {
              if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустое имя");
              name = value.Trim();
          }
      }

      public int Number { get; }
      public int Variant => Number % 5 == 0 ? 5 : Number % 5;
      public int Attempts { get; private set; }

      public Student(string name, int number)
      {
          if (number <= 0) throw new ArgumentOutOfRangeException(nameof(number));
          Name = name;
          Number = number;
      }

      public void Submit() => Attempts++;
  }

  - name: валидация

      ok1 Марк
      ok2
    harness: |-

      try { s.Name = "  "; Console.WriteLine("нет"); } catch (ArgumentException) { Console.WriteLine("ok1 " + s.Name); }

  - public string Name { get => name; set { if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустое имя"); name = value.Trim(); } } public int Attempts { get; private set; }
````

# Сопоставь


````quiz

kind: match
question: Сопоставь запись свойства и что с ним можно делать снаружи класса.
pairs:
  - left: '`public int X { get; set; }`'
    right: читать и писать
  - left: '`public int X { get; }`'
    right: только читать; задать можно в конструкторе
  - left: '`public int X { get; private set; }`'
    right: только читать; класс сам меняет внутри
  - left: '`public int X => a + b;`'
    right: только читать; значение вычисляется при каждом обращении
````
