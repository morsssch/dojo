# Что происходит при new: четыре шага

Строчка `var d = new Demo();` выглядит как одно действие, но внутри это четыре шага, всегда в одном и том же порядке:

- **Выделить память** в куче под все поля объекта и заполнить её нулями. Каждое поле получает значение по умолчанию (таблица ниже).

- **Выполнить инициализаторы полей** — то, что написано прямо в объявлении: `private int a = 1;`. Сверху вниз, в порядке объявления.

- **Выполнить тело конструктора**, которое может перезаписать любые поля.

- **Вернуть ссылку** на готовый объект. Она и попадает в переменную `d`.

```cs run
class Demo
{
    private int a = Log("2) инициализатор поля a", 1);
    private int b;                                  // без инициализатора: остаётся 0
    private int c = Log("2) инициализатор поля c", 3);

    public Demo()
    {
        Console.WriteLine($"3) тело конструктора видит: a={a}, b={b}, c={c}");
        b = 2;
    }

    private static int Log(string what, int value)
    {
        Console.WriteLine(what);
        return value;
    }

    public override string ToString() => $"a={a}, b={b}, c={c}";
}

class Program
{
    static void Main()
    {
        Console.WriteLine("до new");
        var d = new Demo();                         // 1) память, все поля = 0
        Console.WriteLine("4) после new: " + d);
    }
}
```

| Тип поля | Значение по умолчанию (шаг 1) |
| --- | --- |
| `int`, `long`, `double`, `decimal` | `0` |
| `bool` | `false` |
| `char` | `'\0'` (символ с кодом 0) |
| `string`, массивы, любые классы | `null` |
| структуры | все их поля по этой же таблице |

Отсюда правило: всё, что не задал ни инициализатор, ни конструктор, остаётся «нулём». Для `string` это `null`, и обращение `name.Length` упадёт. Поэтому строковые поля часто инициализируют пустой строкой: `private string name = "";`.

## Чем конструктор отличается от метода

|  | Конструктор | Метод |
| --- | --- | --- |
| Имя | точно как у класса | любое, кроме имени класса |
| Тип результата | **не пишется вообще**, даже `void` | обязателен: `void`, `int`… |
| Когда вызывается | один раз, при `new` | сколько угодно раз, у готового объекта |
| Может присвоить свойству `{ get; }` | да | нет |

> [!WARNING] Частая ошибка: void перед конструктором
> `public void Player(string name) { … }` — это уже не конструктор, а попытка объявить **метод** с именем класса. Компилятор выдаст CS0542 «имена членов не могут совпадать с именем включающего их типа». Конструктор пишется без типа: `public Player(string name)`.

# Несколько конструкторов и цепочка : this(…)

Конструкторов может быть несколько — это обычная перегрузка, как у методов в [модуле 5](lesson:methods/l4). Компилятор выбирает тот, у которого подходят типы и число аргументов.

Проблема: в каждом конструкторе нужны одни и те же проверки. Копировать их — плохо: поправишь в одном месте и забудешь в другом. Решение — **главный конструктор** со всеми проверками, а остальные передают ему работу через `: this(…)`:

```cs run
class Rgb
{
    public int R { get; }
    public int G { get; }
    public int B { get; }

    public Rgb(int r, int g, int b)                  // главный: все проверки здесь
    {
        if (r  255 || g  255 || b  255)
            throw new ArgumentOutOfRangeException("Компонента цвета вне 0..255");
        R = r; G = g; B = b;
        Console.WriteLine($"   главный конструктор ({r}, {g}, {b})");
    }

    public Rgb(int gray) : this(gray, gray, gray)    // серый: три одинаковые компоненты
    {
        Console.WriteLine("   тело Rgb(int gray)");
    }

    public Rgb() : this(0)                           // по умолчанию — чёрный
    {
        Console.WriteLine("   тело Rgb()");
    }

    public override string ToString() => $"({R}, {G}, {B})";
}

class Program
{
    static void Main()
    {
        Console.WriteLine("new Rgb():");
        Console.WriteLine(new Rgb());
        Console.WriteLine("new Rgb(128):");
        Console.WriteLine(new Rgb(128));
        try { new Rgb(300); }
        catch (ArgumentOutOfRangeException) { Console.WriteLine("Rgb(300) не прошёл проверку главного конструктора"); }
    }
}
```

**Трассировка `new Rgb()`:** выбран конструктор без параметров. Перед его телом стоит `: this(0)` — переход в `Rgb(int gray)` с gray = 0. Перед его телом `: this(0, 0, 0)` — переход в главный. Главный проверяет, присваивает и печатает. Потом довыполняется тело `Rgb(int gray)`, и последним — тело `Rgb()`. То есть тела выполняются в порядке, обратном вызовам: от главного наружу.

Это ровно тот же механизм, что `: base(…)` у наследников (урок про наследование): `this(…)` — «сначала мой другой конструктор», `base(…)` — «сначала конструктор предка».

## Куда пропадает конструктор по умолчанию

Пока в классе нет ни одного конструктора, компилятор сам добавляет пустой `public Имя() { }`. Как только ты написал **любой** свой конструктор, этот «бесплатный» исчезает. Если нужен и он — напиши его явно, как `Rgb()` выше.

## Инициализатор объекта: new { … }

```cs run
class Settings
{
    public string Theme { get; set; } = "светлая";   // инициализатор свойства — как у поля
    public int FontSize { get; set; } = 14;
    public override string ToString() => $"{Theme}, {FontSize}px";
}

class Program
{
    static void Main()
    {
        var a = new Settings();
        var b = new Settings { FontSize = 18 };          // конструктор, потом сеттер FontSize
        var c = new Settings { Theme = "тёмная", FontSize = 16 };
        Console.WriteLine(a);
        Console.WriteLine(b);
        Console.WriteLine(c);
    }
}
```

Запись `new Settings { FontSize = 18 }` — это сокращение: сначала обычный конструктор (все четыре шага), потом по очереди вызываются **сеттеры** перечисленных свойств. Поэтому так можно задавать только свойства с `set` или `init`. Свойство `{ get; }` в фигурных скобках не задашь, только через параметр конструктора.

# Задача: прямоугольник с тремя конструкторами


````task
id: step-6
lang: cs
title: 'Задача: прямоугольник с тремя конструкторами'
prompt: |-
  Тренируем перегрузку конструкторов и цепочку `: this(…)`: все проверки живут в одном главном конструкторе, а остальные только подставляют значения.

  **Что написать**

  - `class Rect` с автосвойствами только для чтения `Width` и `Height` (double): `{ get; }`.
  - **Главный** конструктор `public Rect(double width, double height)`: если ширина или высота ≤ 0 — `ArgumentOutOfRangeException`; иначе присвоить свойствам.
  - Конструктор квадрата `public Rect(double side)` — передаёт работу главному: `: this(side, side)`. Своё тело ему не нужно, хватит пустых `{ }`.
  - Конструктор без параметров `public Rect()` — единичный квадрат 1 на 1, тоже через `: this(…)`.
  - Вычисляемые свойства: `Area` (площадь) и `IsSquare` (bool: ширина равна высоте).
  - `ToString()` → `Ш на В`, например `2 на 3`.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  Console.WriteLine(new Rect(2, 3));          // 2 на 3
  Console.WriteLine(new Rect(4));             // 4 на 4
  Console.WriteLine(new Rect());              // 1 на 1
  var r = new Rect(2, 3);
  Console.WriteLine($"{r.Area} {r.IsSquare} {new Rect(5).IsSquare}");   // 6 False True
  new Rect(-1);        // ArgumentOutOfRangeException — сработала проверка главного конструктора
  new Rect(3, 0);      // ArgumentOutOfRangeException
  ```

  Проверку пиши **только** в главном конструкторе. Если тест на `new Rect(-1)` проходит без проверки в `Rect(double side)` — значит, цепочка работает.
starter: |-
  class Rect
  {
  }
solution: |-
  class Rect
  {
      public double Width { get; }
      public double Height { get; }

      public Rect(double width, double height)
      {
          if (width <= 0) throw new ArgumentOutOfRangeException(nameof(width));
          if (height <= 0) throw new ArgumentOutOfRangeException(nameof(height));
          Width = width;
          Height = height;
      }

      public Rect(double side) : this(side, side) { }
      public Rect() : this(1) { }

      public double Area => Width * Height;
      public bool IsSquare => Width == Height;
      public override string ToString() => $"{Width} на {Height}";
  }
tests:
  - name: три конструктора
    stdout: |-
      2 на 3
      4 на 4
      1 на 1
      6 False True
    harness: |-
      Console.WriteLine(new Rect(2, 3));
      Console.WriteLine(new Rect(4));
      Console.WriteLine(new Rect());
      var r = new Rect(2, 3);
      Console.WriteLine($"{r.Area} {r.IsSquare} {new Rect(5).IsSquare}");
  - name: проверки через цепочку
    stdout: |-
      ok
      ok
      ok
      False
    harness: |-
      foreach (var make in new Func<Rect>[] { () => new Rect(-1), () => new Rect(3, 0), () => new Rect(0, 2) })
      {
          try { make(); Console.WriteLine("нет исключения"); }
          catch (ArgumentOutOfRangeException) { Console.WriteLine("ok"); }
      }
      Console.WriteLine(typeof(Rect).GetProperty("Width")!.CanWrite);
hints:
  - 'public Rect(double side) : this(side, side) { } и public Rect() : this(1) { } — второй вызывает конструктор квадрата, тот вызывает главный.'
needs:
  - oop/l7
  - oop/l5
require:
  - - ':\s*this\s*\([^)]*\)[\s\S]*:\s*this\s*\('
    - 'Оба дополнительных конструктора должны вызывать другой через : this(…).'
forbid:
  - - Rect\s*\(\s*double\s+side\s*\)\s*:\s*this\s*\([^)]*\)\s*\{[^}]*throw
    - 'В Rect(double side) не нужна своя проверка: её делает главный конструктор.'
````


# Задача: почини класс игрока


````task
id: step-7
lang: cs
title: 'Задача: почини класс игрока'
prompt: |-
  Класс написан с **четырьмя ошибками** — ровно теми, что разобраны в этом уроке и в уроке про свойства. Две найдёт компилятор, одну — проверка, а одна тихая: код работает, но обходит проверку. Найди и исправь все четыре, не меняя задуманного поведения.

  **Что написать**

  - Задуманное поведение: имя проверяется (не пустое) и хранится без пробелов по краям — и при создании, и при изменении через свойство `Name`.
  - Уровень `Level` снаружи только читается, у нового игрока он 1.
  - Очки `Score` снаружи только читаются, растут в `AddScore`. Когда очков становится не меньше `Level × 100`, уровень растёт на 1.
  - Проверка обращается к `Name`, `Level`, `Score` и вызывает `AddScore` снаружи класса.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  var p = new Player("  Марк ");
  Console.WriteLine($"[{p.Name}] ур.{p.Level} очки {p.Score}");   // [Марк] ур.1 очки 0
  p.AddScore(150);
  Console.WriteLine($"ур.{p.Level} очки {p.Score}");             // ур.2 очки 150
  new Player("   ");      // ArgumentException — проверка должна сработать и при создании
  p.Name = "";            // ArgumentException
  ```

  Подсказка по порядку: сначала добейся, чтобы код скомпилировался (сообщения компилятора с номерами строк помогут), потом читай, какой тест упал.
starter: |-
  class Player
  {
      private string name = "";
      public string Name
      {
          get => name;
          set
          {
              if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустое имя");
              name = value.Trim();
          }
      }

      private int level;
      public int Level
      {
          get => level;
      }

      int Score { get; set; }

      public void Player(string name)
      {
          this.name = name;
          Level = 1;
      }

      public void AddScore(int points)
      {
          if (points <= 0) throw new ArgumentOutOfRangeException(nameof(points));
          Score += points;
          if (Score >= Level * 100) level++;
      }
  }
solution: |-
  class Player
  {
      private string name = "";
      public string Name
      {
          get => name;
          set
          {
              if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустое имя");
              name = value.Trim();
          }
      }

      public int Level { get; private set; }
      public int Score { get; private set; }

      public Player(string name)
      {
          Name = name;
          Level = 1;
      }

      public void AddScore(int points)
      {
          if (points <= 0) throw new ArgumentOutOfRangeException(nameof(points));
          Score += points;
          if (Score >= Level * 100) Level++;
      }
  }
````
