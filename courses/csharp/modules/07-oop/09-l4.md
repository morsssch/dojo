# Интерфейс как стандарт взаимодействия

По лекции интерфейс — **стандарт на взаимодействие нескольких частей**, он отвечает на вопрос «какой функционал поддерживает объект». В коде интерфейс — список членов без реализации. Класс, который его реализует, обязан реализовать их все.

```cs run
interface ICommand
{
    string Name { get; }
    int Execute(string[] args);
}

class HelloCommand : ICommand
{
    public string Name => "hello";
    public int Execute(string[] args)
    {
        Console.WriteLine("Привет, " + (args.Length > 0 ? args[0] : "мир"));
        return 0;
    }
}

class SumCommand : ICommand
{
    public string Name => "sum";
    public int Execute(string[] args)
    {
        int s = 0;
        foreach (var a in args) s += int.Parse(a);
        Console.WriteLine(s);
        return 0;
    }
}

class Program
{
    static void Main()
    {
        ICommand[] commands = { new HelloCommand(), new SumCommand() };
        foreach (ICommand c in commands)
        {
            Console.Write(c.Name + " → ");
            c.Execute(new[] { "2", "3" });
        }
    }
}
```

Узнаёшь? Это почти интерфейс `ICommand` из твоей Лабы 3. Хозяину команд неважно, что за класс внутри: он знает стандарт взаимодействия — есть `Name` и `Execute`.

|  | Абстрактный класс | Интерфейс |
| --- | --- | --- |
| Сколько можно унаследовать | один | сколько угодно |
| Поля, конструкторы | есть | нет |
| Отвечает на вопрос | чем является | что умеет |
| Имя по соглашению | `Shape` | `IShape`, с буквы I |


# Обобщения и коллекции

`List` — это template в смысле лекции: пресс-форма, из которой компилятор штампует `List`, `List`. `T` — параметр типа.

**List<T>** — список переменной длины (в отличие от массива):

```cs run
var list = new List { "яблоко", "груша" };
list.Add("слива");
list.Insert(0, "киви");
list.Remove("груша");
Console.WriteLine(list.Count + ": " + string.Join(", ", list));
Console.WriteLine(list[0] + " " + list.Contains("слива") + " " + list.IndexOf("слива"));
list.Sort();
Console.WriteLine(string.Join(", ", list));
```

**Dictionary<TKey, TValue>** — словарь «ключ → значение», поиск по ключу мгновенный:

```cs run
var stock = new Dictionary();
stock["яблоко"] = 10;              // добавить или перезаписать
stock["груша"] = 3;
stock["яблоко"] += 5;

Console.WriteLine(stock["яблоко"]);
Console.WriteLine(stock.ContainsKey("слива"));
if (stock.TryGetValue("груша", out int n)) Console.WriteLine("груш: " + n);

foreach (var kv in stock)           // KeyValuePair: kv.Key, kv.Value
    Console.WriteLine($"{kv.Key} = {kv.Value}");

try { Console.WriteLine(stock["слива"]); }
catch (KeyNotFoundException) { Console.WriteLine("сливы нет"); }
```

## Короткая запись new()

Когда тип уже написан слева, справа его можно не повторять: `List items = new();` — то же самое, что `new List()`. Компилятор берёт тип из объявления. Особенно удобно для полей с длинными типами: `private readonly Dictionary map = new();`.

## Только для чтения наружу

Инкапсуляция коллекций: внутри класса хранишь `List`, наружу отдаёшь интерфейс только для чтения, чтобы никто не добавил элемент в обход проверок. В лабах это `IReadOnlyCollection` и `IReadOnlyList`:

```cs
private readonly List items = new();
public IReadOnlyList Items => items.AsReadOnly();
```

Со словарём то же: `map.Keys` — коллекция всех ключей, и её можно отдать наружу как `IReadOnlyCollection`. Снаружи ключи можно перебрать и посчитать, но добавить или удалить нельзя.

```cs
private readonly Dictionary map = new();
public IReadOnlyCollection Names => map.Keys;
```


# Задача: реестр команд


````task
id: step-3
lang: cs
title: 'Задача: реестр команд'
prompt: |-
  Разминка к Лабе 3 — «реестр команд». Команды — это классы, реализующие общий интерфейс `ICommand`. Реестр хранит их в словаре по имени и запускает по имени. Интерфейс уже есть в заготовке, менять его не нужно.

  **Что написать**

  - `class EchoCommand : ICommand`: свойство `Name` возвращает `"echo"`; метод `Execute(string[] args)` печатает все аргументы через пробел (`string.Join(" ", args)`) и возвращает 0.
  - `class CountCommand : ICommand`: `Name` — `"count"`; `Execute` печатает, сколько аргументов пришло, и возвращает это же число.
  - `class Registry`:
  закрытое поле-словарь `Dictionary`: ключ — имя команды, значение — сама команда;
  - `public void Add(ICommand cmd)`: если `cmd == null` — `ArgumentNullException`; если команда с таким именем уже есть (`ContainsKey`) — `InvalidOperationException`; иначе добавить в словарь;
  - `public int Run(string name, string[] args)`: найти команду по имени, вызвать её `Execute(args)` и вернуть результат; если такой команды нет — `KeyNotFoundException`;
  - свойство `public IReadOnlyCollection Names` — имена всех команд, то есть ключи словаря (`.Keys`).

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  var r = new Registry();
  r.Add(new EchoCommand());
  r.Add(new CountCommand());
  int code1 = r.Run("echo", new[] { "a", "b" });       // печатает: a b
  int code2 = r.Run("count", new[] { "x", "y", "z" });  // печатает: 3
  Console.WriteLine($"{code1} {code2}");                // 0 3
  Console.WriteLine(string.Join(",", r.Names));         // echo,count (порядок не важен)
  r.Add(new EchoCommand());       // InvalidOperationException: echo уже есть
  r.Run("nope", new string[0]);   // KeyNotFoundException
  r.Add(null);                    // ArgumentNullException
  ```

  Обрати внимание: `Registry` не знает про `EchoCommand` и `CountCommand`, он работает только с интерфейсом `ICommand`. Это и есть «стандарт взаимодействия» из лекции.
starter: |-
  interface ICommand
  {
      string Name { get; }
      int Execute(string[] args);
  }

  // EchoCommand, CountCommand, Registry
solution: |-
  interface ICommand
  {
      string Name { get; }
      int Execute(string[] args);
  }

  class EchoCommand : ICommand
  {
      public string Name => "echo";
      public int Execute(string[] args)
      {
          Console.WriteLine(string.Join(" ", args));
          return 0;
      }
  }

  class CountCommand : ICommand
  {
      public string Name => "count";
      public int Execute(string[] args)
      {
          Console.WriteLine(args.Length);
          return args.Length;
      }
  }

  class Registry
  {
      private readonly Dictionary<string, ICommand> map = new();

      public IReadOnlyCollection<string> Names => map.Keys;

      public void Add(ICommand cmd)
      {
          if (cmd == null) throw new ArgumentNullException(nameof(cmd));
          if (map.ContainsKey(cmd.Name)) throw new InvalidOperationException($"Команда {cmd.Name} уже есть");
          map[cmd.Name] = cmd;
      }

      public int Run(string name, string[] args)
      {
          if (!map.TryGetValue(name, out var cmd)) throw new KeyNotFoundException($"Нет команды {name}");
          return cmd.Execute(args);
      }
  }

    stdout: |-

      r.Add(new CountCommand());

      int code2 = r.Run("count", new[] { "x", "y", "z" });
      Console.WriteLine($"{code1} {code2}");
      Console.WriteLine(string.Join(",", r.Names.OrderBy(n => n)));
  - name: повтор имени
    stdout: ok
    harness: |-

      r.Add(new EchoCommand());
      try { r.Add(new EchoCommand()); Console.WriteLine("нет исключения"); } catch (InvalidOperationException) { Console.WriteLine("ok"); }

    stdout: |-
      ok1

    harness: |-
      var r = new Registry();
      try { r.Run("nope", new string[0]); Console.WriteLine("нет исключения"); } catch (KeyNotFoundException) { Console.WriteLine("ok1"); }
      try { r.Add(null); Console.WriteLine("нет исключения"); } catch (ArgumentNullException) { Console.WriteLine("ok2"); }
````

# Задача: частота слов в словаре


````task
id: step-4
lang: cs
title: 'Задача: частота слов в словаре'
prompt: |-
  Подсчёт слов в тексте — типичная задача для словаря: ключ — слово, значение — сколько раз оно встретилось.

  **Что написать**

  - Прочитай одну строку (это уже есть в заготовке).
  - Приведи её к нижнему регистру (`ToLower()`) и разбей на слова по пробелам, пропуская пустые куски от двойных пробелов: `Split(' ', StringSplitOptions.RemoveEmptyEntries)`.
  - Для каждого слова: если оно уже есть в словаре `counts` — увеличь число на 1; если нет — положи в словарь 1 и добавь слово в список `order`.
  - Выведи каждое слово из `order` в формате `слово: число`. Список нужен, чтобы вывести слова в порядке их первого появления: порядок обхода словаря не гарантирован.
  - LINQ (`GroupBy`, `OrderBy` и т. п.) не используй: он будет в модуле 9, здесь тренируем словарь руками.
starter: |-
  string text = Console.ReadLine();
  var counts = new Dictionary<string, int>();
  var order = new List<string>();
solution: |-
  string text = Console.ReadLine();
  var counts = new Dictionary<string, int>();
  var order = new List<string>();
  foreach (var w in text.ToLower().Split(' ', StringSplitOptions.RemoveEmptyEntries))
  {
      if (counts.ContainsKey(w)) counts[w]++;
      else { counts[w] = 1; order.Add(w); }
  }
  foreach (var w in order)
      Console.WriteLine($"{w}: {counts[w]}");

  - stdin: |
      Мама мыла раму мама  МЫЛА
    stdout: |-
      мама: 2
      мыла: 2
      раму: 1
  - stdin: |
      a b c a
    stdout: |-
      a: 2
      b: 1
      c: 1
    hidden: true
hints:
  - foreach (var w in text.ToLower().Split(' ', StringSplitOptions.RemoveEmptyEntries)) { if (counts.ContainsKey(w)) counts[w]++; else { counts[w] = 1; order.Add(w); } }

  - oop/l4

  - - \.(GroupBy|OrderBy|Distinct|ToDictionary)\s*\(
````

# Как это могут спросить на защите


````cards
id: step-5
title: Как это могут спросить на защите
items:
  - q: Что такое инкапсуляция? Приведите пример нарушения.
    a: 'Сокрытие внутренней работы класса и обеспечение внутренней целостности объекта. Пример с лекции: ящик с 10 яблоками, пользователь директивно говорит «здесь 5», а внутреннее состояние осталось старым. Поэтому количество делают свойством только для чтения, которое считается из содержимого.'
  - q: Чем интерфейс отличается от класса?
    a: 'Класс отвечает на вопрос «чем является объект», интерфейс — «какой функционал он поддерживает»; интерфейс — стандарт взаимодействия частей. Технически: базовый класс один, интерфейсов сколько угодно; в интерфейсе нет полей и конструкторов.'
  - q: Чем virtual отличается от abstract?
    a: У virtual есть реализация по умолчанию, её можно переопределить. У abstract реализации нет, наследник обязан переопределить, а сам класс тоже должен быть abstract.
  - q: Зачем свойство, если можно сделать поле public?
    a: 'Свойство — это get/set методы: можно проверить значение (валидация), сделать запись закрытой (private set), вычислять значение на лету. Открытое поле этого не даёт и ломает инкапсуляцию.'
  - q: Какие три подхода к ООП вы знаете?
    a: Классы с наследованием (Java, .net), объект-прототип (JavaScript) и обобщённые методы (Lisp, Go, Rust — в смешанном виде). Пример из лекции для обобщённых методов — барабаны и палочки.
  - q: Почему в методе Point можно обратиться к other.x, если поле private?
    a: 'private ограничивает доступ на уровне класса, а не объекта: код внутри класса Point видит закрытые поля любой точки. Снаружи, например в Main, — нет.'
  - q: В каком порядке вызываются конструкторы при наследовании?
    a: 'Сверху вниз: сначала конструктор самого дальнего предка, потом следующего, последним — конструктор самого класса. Аргументы передаются наверх через : base(…). Если у предка нет конструктора без параметров, а base(…) не написан — ошибка CS7036.'
````
