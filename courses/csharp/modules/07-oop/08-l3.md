# Наследование, base, virtual/override

Наследник пишется через двоеточие: `class Dog : Animal`. В C# у класса ровно один базовый класс (а интерфейсов сколько угодно). Наследник получает все члены базового, может добавить свои и **переопределить** поведение.

- `virtual` в базовом классе: «этот метод можно переопределить».

- `override` в наследнике: «переопределяю».

- `base.Метод()` — вызвать версию базового класса; `: base(...)` — вызвать конструктор базового.

```cs run
class Animal
{
    public string Name { get; }
    public Animal(string name) => Name = name;
    public virtual string Speak() => "…";
    public override string ToString() => $"{GetType().Name} {Name}: {Speak()}";
}

class Dog : Animal
{
    public Dog(string name) : base(name) { }
    public override string Speak() => "Гав";
}

class Puppy : Dog
{
    public Puppy(string name) : base(name) { }
    public override string Speak() => base.Speak() + "-тяв";   // дополняем, а не заменяем
}

class Program
{
    static void Main()
    {
        Animal[] zoo = { new Animal("Некто"), new Dog("Рекс"), new Puppy("Бим") };
        foreach (Animal a in zoo)
            Console.WriteLine(a);   // для каждого вызовется СВОЯ версия Speak
    }
}
```

Это и есть **полиморфизм**: переменная типа `Animal`, а вызывается метод реального объекта. По правилу совместимости с лекции наследник совместим с базовым классом, поэтому `Animal[]` принимает собак.


# Конструкторы наследников: base(…) и protected

В примере выше у каждого наследника была строка `: base(name)`. Зачем она и в каком порядке всё выполняется?

Объект наследника содержит в себе и «часть предка»: у собаки есть свойство `Name` из `Animal`. Эту часть должен заполнить конструктор предка. Поэтому при `new Puppy("Бим")` конструкторы вызываются **сверху вниз**: сначала самого дальнего предка, потом следующего, и последним — самого класса.

```cs run
class Animal
{
    public string Name { get; }
    protected Animal(string name)          // protected: вызывать могут только наследники
    {
        Console.WriteLine("1) конструктор Animal");
        Name = name;
    }
}

class Dog : Animal
{
    public Dog(string name) : base(name)   // передаём name наверх, в Animal
    {
        Console.WriteLine("2) конструктор Dog");
    }
}

class Puppy : Dog
{
    public Puppy(string name) : base(name + " мл.")   // можно передать и что-то вычисленное
    {
        Console.WriteLine("3) конструктор Puppy");
    }
}

class Program
{
    static void Main()
    {
        var p = new Puppy("Бим");
        Console.WriteLine(p.Name);
        Console.WriteLine(p.GetType().Name);   // настоящий класс объекта: Puppy
    }
}
```

**Что происходит при `new Puppy("Бим")`:** вызывается конструктор Puppy, но раньше его тела выполняется `: base("Бим мл.")` — переход в конструктор Dog. Там сначала `: base(name)` — переход в Animal. Тело Animal печатает «1)» и записывает Name. Возврат в Dog — печатается «2)». Возврат в Puppy — «3)». Объект готов.

| Запись | Что значит |
| --- | --- |
| `: base(name)` | перед телом моего конструктора вызвать конструктор предка с этими аргументами |
| `base.Speak()` | внутри метода вызвать версию метода из предка, а не свою |
| `protected Animal(…)` | конструктор виден только наследникам. Для абстрактного класса это естественно: снаружи его всё равно не создать |
| `GetType().Name` | имя настоящего класса объекта во время работы программы, даже если переменная типа предка |

> [!WARNING] Частая ошибка: CS7036
> Если у предка есть только конструктор с параметрами, а наследник не написал `: base(…)`, компилятор попытается вызвать конструктор предка **без** параметров, не найдёт его и выдаст CS7036 «отсутствует аргумент, соответствующий параметру name». Лечится строкой `: base(name)`.

# Абстрактные классы и методы

`abstract class` — класс-заготовка: объект от него создать нельзя, только от наследников. `abstract` метод не имеет тела, и каждый наследник **обязан** его переопределить. Это ровно конструкция из Лабы 1 варианта 1 (`BankAccount`), а в Лабе 4 — `ComputeJob`.

```cs run
abstract class Shape
{
    public abstract double Area();                     // тела нет
    public virtual string Name => "фигура";
    public string Describe() => $"{Name}, площадь {Area():F2}";   // общий метод пользуется абстрактным
}

class Circle : Shape
{
    private readonly double r;
    public Circle(double r)
    {
        if (r  Math.PI * r * r;
    public override string Name => "круг";
}

class Rect : Shape
{
    private readonly double w, h;
    public Rect(double w, double h) { this.w = w; this.h = h; }
    public override double Area() => w * h;
}

class Program
{
    static void Main()
    {
        Shape[] shapes = { new Circle(1), new Rect(2, 3) };
        foreach (var s in shapes) Console.WriteLine(s.Describe());
        // var x = new Shape();   // CS0144: нельзя создать экземпляр абстрактного класса
    }
}
```

| Ключевое слово | Смысл |
| --- | --- |
| `virtual` | есть реализация по умолчанию, переопределять можно |
| `abstract` | реализации нет, переопределять обязательно; класс тоже abstract |
| `override` | переопределяю virtual/abstract метод предка |
| `sealed` | дальше наследовать (или переопределять) нельзя |


# Задача: иерархия сотрудников


````task
id: step-5
lang: cs
title: 'Задача: иерархия сотрудников'
prompt: |-
  Иерархия сотрудников: общий абстрактный предок и три вида сотрудников, у каждого своя формула зарплаты. Проверка складывает их в один массив `Employee[]` и печатает, и для каждого должна вызваться **своя** версия `Salary()`.

  **Что написать**

  - `abstract class Employee`:
  свойство `Name` (string) только для чтения;
  - конструктор `protected Employee(string name)`: если имя пустое или из пробелов (`string.IsNullOrWhiteSpace`), брось `ArgumentException`, иначе запиши в Name. `protected` — потому что вызывать его будут только наследники через `: base(name)`;
  - абстрактный метод `public abstract decimal Salary();` — без тела, с точкой с запятой;
  - `public override string ToString()` → `Имя: зарплата`, например `Анна: 90000`. Внутри просто вызови `Salary()` — сработает версия настоящего класса объекта.

  - `class FullTime : Employee` — сотрудник на окладе. Конструктор `public FullTime(string name, decimal salary) : base(name)`, оклад сохрани в закрытое поле. `Salary()` возвращает оклад.
  - `class Hourly : Employee` — почасовая оплата. Конструктор `public Hourly(string name, decimal rate, int hours) : base(name)`. `Salary()` = rate × hours.
  - `class Intern : FullTime` — стажёр. Наследуется от **FullTime**, а не от Employee. Конструктор `public Intern(string name, decimal salary) : base(name, salary)` — передаёт оба параметра в конструктор FullTime. `Salary()` возвращает половину оклада: возьми оклад через `base.Salary()` и раздели на 2.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  Employee[] staff =
  {
      new FullTime("Анна", 90000m),
      new Hourly("Борис", 500m, 120),
      new Intern("Вера", 60000m)
  };
  foreach (var e in staff) Console.WriteLine(e);
  // Анна: 90000
  // Борис: 60000
  // Вера: 30000
  new FullTime(" ", 1m);    // ArgumentException — проверка в конструкторе Employee
  // new Employee("X");     // не должно компилироваться: класс абстрактный
  ```
starter: |-
  abstract class Employee
  {
  }
solution: |-
  abstract class Employee
  {
      public string Name { get; }

      protected Employee(string name)
      {
          if (string.IsNullOrWhiteSpace(name)) throw new ArgumentException("Пустое имя", nameof(name));
          Name = name;
      }

      public abstract decimal Salary();
      public override string ToString() => $"{Name}: {Salary()}";
  }

  class FullTime : Employee
  {
      private readonly decimal salary;
      public FullTime(string name, decimal salary) : base(name) => this.salary = salary;
      public override decimal Salary() => salary;
  }

  class Hourly : Employee
  {
      private readonly decimal rate;
      private readonly int hours;
      public Hourly(string name, decimal rate, int hours) : base(name)
      {
          this.rate = rate;
          this.hours = hours;
      }
      public override decimal Salary() => rate * hours;
  }

  class Intern : FullTime
  {
      public Intern(string name, decimal salary) : base(name, salary) { }
      public override decimal Salary() => base.Salary() / 2;
  }
````
