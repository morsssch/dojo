# Что компилятор делает со свойством

Для процессора и для IL ([модуль 1](lesson:dotnet/l2)) никаких «свойств» не существует, есть только поля и методы. Свойство — удобная запись, которую компилятор превращает в обычные методы:

| Ты пишешь | Компилятор делает |
| --- | --- |
| `get { … }` у свойства `Name` | метод `string get_Name()` |
| `set { … }` у свойства `Name` | метод `void set_Name(string value)` — отсюда и слово `value`: это просто имя его параметра |
| `p.Name` (чтение) | вызов `p.get_Name()` |
| `p.Name = "Марк"` (запись) | вызов `p.set_Name("Марк")` |
| автосвойство `{ get; set; }` | то же самое **плюс** скрытое закрытое поле с именем `k__BackingField`, в которое эти методы пишут и из которого читают |

Это можно увидеть своими глазами: рефлексия покажет все поля и методы, которые реально есть в классе.

```cs run
using System.Reflection;

class Student
{
    private string name = "";                       // своё поле
    public string Name                              // свойство с телом
    {
        get => name;
        set => name = value.Trim();
    }
    public int Number { get; }                      // автосвойство только для чтения
    public int Attempts { get; private set; }       // автосвойство с закрытым set
    public int Variant => Number % 5;               // вычисляемое

    public Student(string name, int number) { Name = name; Number = number; }
}

class Program
{
    static void Main()
    {
        var flags = BindingFlags.Instance | BindingFlags.Public | BindingFlags.NonPublic | BindingFlags.DeclaredOnly;
        Console.WriteLine("Поля:");
        foreach (var f in typeof(Student).GetFields(flags))
            Console.WriteLine("   " + f.Name);
        Console.WriteLine("Методы:");
        foreach (var m in typeof(Student).GetMethods(flags))
            Console.WriteLine($"   {(m.IsPublic ? "public " : "private")} {m.Name}");
    }
}
```

Что видно в выводе:

- у `Name` поле только одно, `name` — его написал ты. Своего скрытого поля у такого свойства нет;

- у `Number` и `Attempts` есть скрытые поля `k__BackingField` и `k__BackingField` — их добавил компилятор, потому что это автосвойства;

- у `Number` есть только `get_Number`, метода записи нет вообще. Присвоение в конструкторе компилятор переводит в прямую запись в скрытое поле — поэтому `{ get; }` можно присвоить **только** в конструкторе;

- `set_Attempts` — **private**: отсюда «снаружи только чтение»;

- у `Variant` нет поля, только `get_Variant`: значение считается каждый раз заново.

## Главный вывод

Раз `get` и `set` — это методы, внутри них можно делать всё, что в методе: проверять, вычислять, бросать исключения, менять другие поля. А раз это методы, у них бывают и ошибки методов — например, бесконечная рекурсия. Про это следующий шаг.


# Шесть типичных ошибок со свойствами и конструкторами

Все шесть встречаются у студентов постоянно, и преподаватель про каждую может спросить «почему так нельзя». Для каждой: как выглядит, что скажет компилятор или программа, почему и как исправить.

## 1. Геттер возвращает сам себя

```cs
private string name;
public string Name
{
    get => Name;          // ← большая N: это снова свойство, а не поле
    set => name = value;
}
```

**Что будет:** компилируется, но при чтении `p.Name` вызывается `get_Name()`, который снова читает `Name`, то есть снова вызывает `get_Name()`… Стек вызовов ([модуль 5](lesson:methods/l1)) переполняется — **StackOverflowException**. Её нельзя поймать `catch`, программа просто падает. В этом курсе такой код не запускается: проверка ловит его заранее и объясняет. **Исправление:** геттер возвращает поле — `get => name;`. То же самое с сеттером: `set => Name = value;` — тоже бесконечная рекурсия.

## 2. Присвоение свойству без set

```cs
private int number;
public int Number { get => number; }    // свойство с телом, set нет

public Student(int number)
{
    Number = number;                     // CS0200: свойство доступно только для чтения
}
```

**Почему:** у такого свойства есть только метод `get_Number`, а писать некуда. Исключение «можно присвоить в конструкторе» действует только для **автосвойства** `{ get; }`: у него есть скрытое поле, в которое компилятор и пишет. **Исправление:** либо в конструкторе писать в поле — `this.number = number;`, либо убрать поле и сделать автосвойство `public int Number { get; }`.

## 3. Конструктор пишет в поле и обходит проверку

```cs
public Student(string name)
{
    this.name = name;     // проверки из set не будет: пустое имя пройдёт
}
```

**Что будет:** компилируется и работает, но `new Student("   ")` создаёт студента с пустым именем — инвариант нарушен. **Исправление:** в конструкторе присваивать **свойству**: `Name = name;`. Тогда вызовется `set_Name` со всеми проверками.

## 4. Забыли public

```cs
int Score { get; private set; }     // нет модификатора → private
```

**Что будет:** внутри класса всё работает, а снаружи — ошибка CS0122 «недоступен из-за уровня защиты». У членов класса по умолчанию `private`. **Исправление:** `public int Score { get; private set; }`.

## 5. void перед конструктором

```cs
public void Player(string name) { … }   // CS0542
```

**Почему:** с типом результата это уже метод, а метод не может называться как класс. **Исправление:** убрать `void`.

## 6. Сеттер забыл сохранить значение

```cs
public string Name
{
    get => name;
    set
    {
        if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустое имя");
        value.Trim();          // результат никуда не записан!
    }
}
```

**Что будет:** проверка работает, но имя никогда не меняется: `Trim()` возвращает **новую** строку, а строки неизменяемы ([модуль 4](lesson:arrays-strings/l5)). Сеттер выбросил результат. **Исправление:** `name = value.Trim();`.

| Симптом | Скорее всего |
| --- | --- |
| StackOverflowException, программа «умерла» | ошибка 1: свойство обращается к себе |
| CS0200 «доступно только для чтения» | ошибка 2: нет set, или это не автосвойство |
| Неверные данные проходят при создании | ошибка 3: конструктор пишет в поле |
| CS0122 «недоступен из-за уровня защиты» | ошибка 4: нет public |
| CS0542 «имена членов не могут совпадать с именем типа» | ошибка 5: void у конструктора |
| Присвоил, а значение не изменилось | ошибка 6: сеттер не записал в поле |

# init: задать один раз при создании

Иногда хочется задавать свойство в инициализаторе объекта (`new P { X = 1 }`), но запретить менять его потом. `{ get; }` не подходит — его можно задать только в конструкторе. `{ get; set; }` тоже — его можно менять когда угодно. Для этого есть `init`: это `set`, который работает только в момент создания — в конструкторе и в фигурных скобках инициализатора.

```cs run
class Profile
{
    private readonly string login = "";

    public string Login                       // init с проверкой: нужно своё поле
    {
        get => login;
        init
        {
            if (string.IsNullOrWhiteSpace(value)) throw new ArgumentException("Пустой логин");
            login = value.Trim().ToLower();
        }
    }

    public string Nickname { get; set; } = "";     // можно менять когда угодно
    public int Year { get; init; } = 2026;         // init-автосвойство со значением по умолчанию

    public override string ToString() => $"{Nickname} (@{Login}, с {Year})";
}

class Program
{
    static void Main()
    {
        var p = new Profile { Login = "  MORS ", Nickname = "Марк" };
        Console.WriteLine(p);
        p.Nickname = "Марк 2.0";                   // set — можно
        // p.Login = "other";                      // CS8852: init-свойство можно задать только при создании
        Console.WriteLine(p);
        var q = new Profile { Login = "anya", Nickname = "Аня", Year = 2024 };
        Console.WriteLine(q);
    }
}
```

| Запись | В конструкторе | В `new X { … }` | Потом, снаружи | Потом, внутри класса |
| --- | --- | --- | --- | --- |
| `{ get; }` | да | нет | нет | нет |
| `{ get; init; }` | да | да | нет | нет |
| `{ get; private set; }` | да | нет (set закрыт) | нет | да |
| `{ get; set; }` | да | да | да | да |
| `=> выражение` | никогда: значения нет, оно вычисляется |

Поле с модификатором `readonly` (как `login` выше) работает по тому же правилу, что и `{ get; }`: записать в него можно только при создании объекта. Поэтому `init` может в него писать, а обычный `set` — нет.

````task
  - Методы `public void Add(int n)` и `public void Sell(int n)`: n ≤ 0 — `ArgumentOutOfRangeException`; продать больше, чем есть, — `InvalidOperationException`.

  p.Sell(3);
````

# Как это могут спросить на защите


````cards
id: step-8
title: Как это могут спросить на защите
items:
  - q: Чем свойство отличается от поля?
    a: 'Поле — это ячейка памяти в объекте. Свойство — пара методов get и set (компилятор делает get_X и set_X), которые снаружи выглядят как поле. Поэтому в свойстве можно проверять значения, вычислять их, по-разному открывать чтение и запись. Поле делают private, свойство — public: это и есть инкапсуляция.'
  - q: Что компилятор генерирует для автосвойства { get; set; }?
    a: 'Скрытое закрытое поле (с именем вида <Name>k__BackingField) и два метода: get_Name, который его возвращает, и set_Name(value), который в него пишет. Для { get; } метода set нет, а присвоение в конструкторе идёт прямо в скрытое поле.'
  - q: В каком порядке выполняется создание объекта?
    a: 'Память под поля заполняется нулями, затем выполняются инициализаторы полей в порядке объявления, затем конструктор. Если есть : this(…) или : base(…), сначала выполняется тот конструктор. Последним возвращается ссылка на объект.'
  - q: Чем init отличается от private set?
    a: init можно задать только при создании — в конструкторе или в инициализаторе new X { … }, причём снаружи класса. private set можно менять сколько угодно, но только внутри класса, а в инициализаторе снаружи — нельзя.
  - q: Почему в конструкторе лучше присваивать свойству, а не полю?
    a: Тогда вызывается сеттер со всеми проверками, и некорректный объект нельзя создать. Если писать в поле напрямую, проверка из set обходится.
````
