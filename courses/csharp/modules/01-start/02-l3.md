# Что поставить на Windows или macOS

Курс работает в браузере, но лабу сдают «в одной из сред программирования» и на защите просят показать отладку. Visual Studio для Mac Microsoft закрыла в 2024 году, поэтому на Windows или macOSOS путь такой:

- **.NET SDK** — компилятор, среда выполнения и команда `dotnet`. Ставится официальным установщиком с сайта dotnet.microsoft.com (выбери macOS и Arm64 для Apple Silicon или x64 для Intel) или через Homebrew: `brew install --cask dotnet-sdk`. Версия 8 или новее.

- **Visual Studio Code** + расширение **C# Dev Kit** (оно само подтянет расширение C#). Даёт подсветку, подсказки и полноценный отладчик.

Проверка в Терминале:

```cs
dotnet --version
```

Если вывелась версия вроде `10.0.100` — всё на месте.

А если в аудитории Windows и Visual Studio
Клавиши отладки в VS Code и Visual Studio одинаковые: F9, F5, F10, F11. Поэтому то, что отрепетируешь дома, сработает и на компьютере кафедры. JetBrains Rider тоже бесплатен для учёбы, но требует вход в аккаунт JetBrains, а из России с этим бывают сложности — VS Code надёжнее.


# Первый проект из терминала

Каждая лаба — отдельный консольный проект. Создаётся так:

```cs
mkdir ~/labs && cd ~/labs
dotnet new console -n Lab1 --use-program-main
cd Lab1
code .          # открыть папку в VS Code
dotnet run      # собрать и запустить
```

| Что появилось | Зачем |
| --- | --- |
| `Lab1.csproj` | файл проекта: версия .NET, тип приложения, подключённые библиотеки |
| `Program.cs` | код. Флаг `--use-program-main` сразу создаёт классический `class Program` с `static void Main` |
| `bin/Debug/net10.0/Lab1.dll` | появится после сборки: твоя программа, скомпилированная в IL (что это — в модуле 1) |
| `obj/` | промежуточные файлы сборки, руками не трогают |

Команды, которые пригодятся: `dotnet build` — только собрать и показать ошибки; `dotnet run` — собрать и запустить; ввод для `Console.ReadLine()` печатаешь прямо в терминале.

> [!WARNING] Важно для отладки ввода
> Отладчик VS Code по умолчанию пускает программу во «Внутреннюю консоль отладки», где нельзя ввести текст. Если программа читает `Console.ReadLine()`, в файле `.vscode/launch.json` поставь `"console": "integratedTerminal"` — тогда ввод будет в терминале VS Code.


# Отладка: что показывать на защите

Требование из всех лаб: *«уметь устанавливать точки останова, выполнять программу пошагово в режиме отладки, просматривать значения переменных»*.

| Действие | Клавиша | Что происходит |
| --- | --- | --- |
| Поставить/снять точку останова | `F9` или клик слева от номера строки | Красный кружок. Программа остановится **перед** выполнением этой строки |
| Запустить с отладкой | `F5` | Идёт до первой точки останова |
| Шаг с обходом | `F10` | Выполнить строку целиком, не заходя в вызываемые методы |
| Шаг с заходом | `F11` | Зайти внутрь вызываемого метода |
| Шаг с выходом | `Shift+F11` | Досчитать текущий метод и вернуться в вызывающий |
| Продолжить | `F5` | До следующей точки останова |
| Остановить | `Shift+F5` |  |

на Windows или macOS функциональные клавиши могут быть заняты яркостью и звуком: тогда жми их вместе с `fn` или включи «Использовать F1, F2 и т. д. как стандартные функциональные клавиши» в настройках клавиатуры.

Где смотреть значения в VS Code (панель «Запуск и отладка» слева):

- **Переменные** (Variables) — все локальные переменные текущего метода;
- **Контрольные значения** (Watch) — впиши выражение, например `r.Numerator`;
- наведи мышь на переменную в коде — всплывёт значение;
- **Стек вызовов** (Call Stack) — кто кого вызвал. Про стек вызовов подробно в модуле 5.

> [!TIP] Как отрепетировать
> Возьми любую задачу из курса с циклом, перенеси в проект, поставь точку останова внутри цикла и пройди его по F10, глядя, как меняется счётчик. Потом зайди по F11 в свой метод. Это ровно то, что попросят на защите.
