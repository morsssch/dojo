# try, catch, finally

Три формы с лекции.

**Блок для отлова любых исключений:**

```cs
try
{
    ...
}
catch
{
    ...
}
```

**Блок для отлова конкретных исключений:** `catch (IOException e)` или `catch (IOException)`, если сам объект исключения не нужен. **Все исключения наследуются прямо или косвенно от Exception.**

**Несколько блоков catch:** какой из них сработает, определяет только **порядок написания**. Поэтому располагаем блоки **от самого специфичного к самому общему**. Несколько типов исключений в один блок поставить нельзя.

```cs run
int[] a = { 10, 20 };
string[] inputs = { "1", "5", "abc", "0" };
foreach (string s in inputs)
{
    try
    {
        int i = int.Parse(s);
        Console.WriteLine(100 / i + a[i]);
    }
    catch (IndexOutOfRangeException)
    {
        Console.WriteLine($"{s}: нет такого индекса");
    }
    catch (FormatException)
    {
        Console.WriteLine($"{s}: это не число");
    }
    catch (Exception e)       // самый общий — последним
    {
        Console.WriteLine($"{s}: другая ошибка {e.GetType().Name}");
    }
}
```

**Блок finally** исполняется **всегда**, независимо от того, произошла ошибка или нет. Перед ним может стоять сколько угодно блоков catch. По лекции, в современных реалиях он применяется редко, потому что есть более современные методы работы (конструкция `using` сама закрывает файлы и соединения).

```cs run
try
{
    Console.WriteLine("Открыли ресурс");
    throw new InvalidOperationException("что-то пошло не так");
}
catch (InvalidOperationException e)
{
    Console.WriteLine("Поймали: " + e.Message);
}
finally
{
    Console.WriteLine("finally: закрыли ресурс");
}
```

> [!DEEP] Уточнение
> «Несколько Exception в один блок нельзя» — верно для синтаксиса `catch (A | B)`, такого нет. Но есть фильтр: `catch (Exception e) when (e is FormatException || e is OverflowException)`. Пригодится, если в лабе захочешь обработать два типа одинаково.


# Проброс исключений и throw

Если происходит ошибка, а обработчика catch нет, то .net ищет **по стеку вызовов наверх** ближайший `try` и обрабатывает его `catch`. На самом деле `try` есть всегда: сама программа запускается в системном `try`. Именно он печатает «Unhandled exception» и завершает программу.

![Стек вызовов: Main вызвал Level1, тот Level2, тот Level3; исключение из Level3 поднимается вниз по кадрам до кадра с подходящим catch](./diagrams/csharp/diagram-4.svg)

```cs run
void Level3() { Console.WriteLine("Level3: бросаю"); throw new ArgumentException("плохие данные"); }
void Level2() { Level3(); Console.WriteLine("Level2: эта строка не выполнится"); }
void Level1()
{
    try { Level2(); }
    catch (ArgumentException e) { Console.WriteLine("Level1 поймал: " + e.Message); }
}

Level1();
Console.WriteLine("Программа продолжает работу");
```

## Бросить своё исключение

`throw new ТипИсключения("сообщение");` Самые нужные для лаб:

| Тип | Когда бросать |
| --- | --- |
| `ArgumentNullException` | параметр равен null, а не должен |
| `ArgumentException` | параметр недопустимый (пустая строка, знаменатель 0) |
| `ArgumentOutOfRangeException` | число вне допустимого диапазона |
| `InvalidOperationException` | операция невозможна в текущем состоянии объекта |
| `DivideByZeroException` | деление на ноль в своей арифметике |

Внутри catch можно написать просто `throw;` — это пробросит **то же самое** исключение дальше, сохранив место, где оно возникло.


# Шаблон из требований к лабам: «продолжить или выйти»

Во всех лабах требуется: *при ошибке информативно вывести данные о ней и предложить продолжить выполнение, проигнорировав ошибку, или завершить программу.* Удобный каркас:

```cs run
using System;

class Program
{
    static void Main()
    {
        while (true)
        {
            try
            {
                Console.Write("Введите делимое: ");
                int a = int.Parse(Console.ReadLine());
                Console.WriteLine($"100 / {a} = {100 / a}");
            }
            catch (Exception e)
            {
                Console.WriteLine($"Ошибка: {e.GetType().Name}: {e.Message}");
                Console.Write("Продолжить? (д/н): ");
                string ans = Console.ReadLine();
                if (ans == null || ans.Trim().ToLower() != "д")
                {
                    Console.WriteLine("Завершение работы.");
                    return;
                }
            }
        }
    }
}
```

Пример ввода: `abc
д
8
0
н
`
Здесь ввод заранее заготовлен: `abc` (ошибка формата) → продолжаем, `8` → считаем, `0` → ошибка → выходим. Этот каркас ляжет в основу демо каждой лабы.

Проверка параметров на null
Второе общее требование — «проверка параметров на null, где это необходимо». В начале публичного метода:

```cs
if (name == null) throw new ArgumentNullException(nameof(name));
// или короче, с .NET 6:
ArgumentNullException.ThrowIfNull(name);
```

`nameof(name)` даёт строку `"name"` — имя параметра попадёт в сообщение, и при переименовании не разъедется.

````task
lang: cs
title: 'Задача: безопасный делитель'
prompt: Напиши функцию `int SafeDivide(int[] a, int i, int j)`, которая возвращает `a[i] / a[j]`. Если `a == null` — брось `ArgumentNullException`. Остальное пусть бросает среда. В Main для каждой тройки индексов вызови функцию и напечатай результат или имя типа исключения. Порядок catch — от специфичного к общему.
starter: |-
  using System;

  class Program
  {
      static int SafeDivide(int[] a, int i, int j)
      {
          // проверь a на null и верни a[i] / a[j]
          return 0;
      }

      static void Main()
      {
          int[] data = { 10, 0, 5 };
          (int[] arr, int i, int j)[] cases = { (data, 0, 2), (data, 0, 1), (data, 0, 7), (null, 0, 0) };
          foreach (var c in cases)
          {
              try
              {
                  Console.WriteLine(SafeDivide(c.arr, c.i, c.j));
              }
              // добавь catch-блоки: DivideByZeroException, IndexOutOfRangeException, ArgumentNullException
          }
      }
  }
solution: |-
  using System;

  class Program
  {
      static int SafeDivide(int[] a, int i, int j)
      {
          if (a == null) throw new ArgumentNullException(nameof(a));
          return a[i] / a[j];
      }

      static void Main()
      {
          int[] data = { 10, 0, 5 };
          (int[] arr, int i, int j)[] cases = { (data, 0, 2), (data, 0, 1), (data, 0, 7), (null, 0, 0) };
          foreach (var c in cases)
          {
              try
              {
                  Console.WriteLine(SafeDivide(c.arr, c.i, c.j));
              }
              catch (DivideByZeroException e) { Console.WriteLine(e.GetType().Name); }
              catch (IndexOutOfRangeException e) { Console.WriteLine(e.GetType().Name); }
              catch (ArgumentNullException e) { Console.WriteLine(e.GetType().Name); }
          }
      }
  }
tests:
  - stdout: |-
      2
      DivideByZeroException
      IndexOutOfRangeException
      ArgumentNullException
hints:
  - 'В catch печатай имя: catch (DivideByZeroException e) { Console.WriteLine(e.GetType().Name); }'
require:
  - - throw\s+new\s+ArgumentNullException
    - Для a == null брось ArgumentNullException сам.
  - - catch\s*\(\s*DivideByZeroException
    - Нужен catch для DivideByZeroException.
````

````task
  using System;

  class Program
  {
      static int ParseAge(string? s)
      {

      static void Main()
      {
          string?[] inputs = { "25", null, "abc", "200", "-1", "0" };
          foreach (var s in inputs)
          {
              try
              {
                  Console.WriteLine("ok " + ParseAge(s));
              }
              catch (Exception e)
              {
                  Console.WriteLine(e.GetType().Name);
              }
          }
      }
  }

      ArgumentOutOfRangeException

  - - throw\s+new\s+ArgumentOutOfRangeException
    - Брось ArgumentOutOfRangeException сам.
````

# Как это могут спросить на защите


````cards
id: step-10
title: Как это могут спросить на защите
items:
  - q: Что будет, если исключение не поймано в методе?
    a: .net ищет по стеку вызовов наверх ближайший try с подходящим catch. Если не находит, срабатывает системный try, в котором запущена программа, и она завершается с сообщением об ошибке.
  - q: Почему catch (Exception) пишут последним?
    a: Какой catch сработает, определяет только порядок написания. Exception — предок всех исключений, поэтому если поставить его первым, он перехватит всё, и специфичные блоки станут недостижимы.
  - q: Когда выполняется finally?
    a: 'Всегда: была ошибка или нет, поймали её или нет. Туда кладут освобождение ресурсов. Сейчас чаще используют конструкцию using, поэтому finally встречается редко.'
  - q: Зачем проверять параметры на null, если среда и так бросит NullReferenceException?
    a: 'Чтобы упасть сразу и понятно: ArgumentNullException с именем параметра на входе в метод, а не NullReferenceException где-то в глубине, где уже не ясно, кто виноват. Плюс объект не остаётся в полусломанном состоянии.'
````
