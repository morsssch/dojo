# Сущности обмениваются событиями

Вспомни базовый принцип ООП с лекции 22.09: множество сущностей со свойствами и поведением, **которые обмениваются между собой событиями**. В C# событие строится на делегате.

дополнение Делегат может хранить **несколько** функций сразу (многоадресный делегат): `+=` добавляет, `-=` убирает. При вызове они выполняются по очереди.

```cs run
Action log = s => Console.WriteLine("в консоль: " + s);
log += s => Console.WriteLine("в «файл»: " + s);
log("событие 1");

Action third = s => Console.WriteLine("третий: " + s);
log += third;
log -= third;          // отписали
log("событие 2");
```

**Событие** (`event`) — поле-делегат с защитой: снаружи класса на него можно только подписаться `+=` или отписаться `-=`. Вызвать событие или перезаписать его `=` может только сам класс. Так чужой код не «выстрелит» событием за тебя и не сотрёт чужих подписчиков.

```cs run
class Thermostat
{
    public event Action? Overheated;           // событие с параметром-температурой
    public event Action? Changed;      // старое и новое значение

    private double temp;
    public double Limit { get; }
    public Thermostat(double limit) => Limit = limit;

    public void Set(double value)
    {
        double old = temp;
        temp = value;
        Changed?.Invoke(old, value);                    // ?. — «если есть подписчики»
        if (value > Limit) Overheated?.Invoke(value);
    }
}

class Program
{
    static void Main()
    {
        var t = new Thermostat(30);
        t.Changed += (o, n) => Console.WriteLine($"изменение {o} → {n}");
        t.Overheated += v => Console.WriteLine($"ПЕРЕГРЕВ: {v}");
        t.Set(25);
        t.Set(35);
        // t.Overheated(100);   // CS0070: вызвать событие снаружи нельзя
        // t.Overheated = null; // тоже нельзя
    }
}
```

| Кто | Что делает |
| --- | --- |
| Издатель (класс с event) | объявляет событие, в нужный момент вызывает `Событие?.Invoke(…)` |
| Подписчик | `obj.Событие += обработчик;`, потом, если нужно, `-=` |

`?.Invoke` обязателен: если подписчиков нет, событие равно `null`, и прямой вызов упал бы с NullReferenceException.


# Стандартный шаблон EventHandler и события-валидаторы

В библиотеке .NET события обычно объявляют как `EventHandler`: обработчик получает отправителя и объект с данными.

```cs
public class ValidationFailedEventArgs : EventArgs
{
    public string Text { get; }
    public ValidationFailedEventArgs(string text) => Text = text;
}

public event EventHandler? ValidationFailed;
// вызов: ValidationFailed?.Invoke(this, new ValidationFailedEventArgs(text));
// подписка: p.ValidationFailed += (sender, e) => Console.WriteLine(e.Text);
```

Для лаб подходят оба варианта. `Action` короче; `EventHandler` — «как принято в .NET», и преподаватель это оценит, если спросит про стандарт. В курсе автопроверка Лабы 2 ожидает `Action`-события — так проще читать.

## Событие, которое возвращает значение

В лабах встречаются «события-фильтры» и «события-валидаторы», которые возвращают `bool` (например `ResultValidator` в варианте 4). У многоадресного делегата `Invoke()` вернёт результат **только последнего** подписчика. Чтобы учесть всех, перебирают список вызовов:

```cs run
Func? validator = null;
validator += x => x > 0;
validator += x => x  x % 2 == 0;

Console.WriteLine("Invoke даёт только последнего: " + validator(7));  // True: 7>0 и 7 f in validator.GetInvocationList())
    all &= f(7);
Console.WriteLine("Все вместе: " + all);                            // False: 7 нечётное
```

prompt: |-
  Класс-издатель: счётчик сам меняет своё значение и сообщает об этом событиями. Подписчики (код проверки) узнают об изменениях, не опрашивая счётчик. Так же `TextPipeline` в Лабе 2 сообщает о `ValidationFailed` и `TransformationApplied`.

  Console.WriteLine();

  Console.WriteLine();
  Console.WriteLine(c.Value);               // 20
  c.Add(0);                                 // ArgumentOutOfRangeException

  [4][9][12]!порог 12! [13]
  [0][20]!порог 20!

  class Counter

solution: |-
  class Counter
  {
      public event Action<int>? Changed;
      public event Action<int>? ThresholdReached;

      private readonly int threshold;
      private bool reached;
      public int Value { get; private set; }

      public Counter(int threshold) => this.threshold = threshold;

      public void Add(int x)
      {
          if (x <= 0) throw new ArgumentOutOfRangeException(nameof(x));
          Value += x;
          Changed?.Invoke(Value);
          if (!reached && Value >= threshold)
          {
              reached = true;
              ThresholdReached?.Invoke(Value);
          }
      }

      public void Reset()
      {
          Value = 0;
          reached = false;
          Changed?.Invoke(Value);
      }
  }

# Пять ловушек событий

События ломаются тихо: код компилируется, а обработчик вызывается дважды, не отписывается или не вызывается вовсе. Проверь каждую ловушку запуском.

```cs run
Action? a = null;
Action h = () => Console.Write("h ");

a += h; a += h;                          // 1) подписали дважды
a();                                     // h h — и вызовется дважды
Console.WriteLine();

a -= () => Console.Write("h ");          // 2) «отписали» новой лямбдой
a();                                     // h h — ничего не изменилось
Console.WriteLine();

a -= h;                                  // отписка той же переменной убирает одну подписку
a();                                     // h
Console.WriteLine();
a -= h;
Console.WriteLine(a == null);            // True — подписчиков не осталось

Action b = () => Console.WriteLine("первый");
b += () => throw new InvalidOperationException("сбой во втором");
b += () => Console.WriteLine("третий");
try { b(); }                             // 5) третий не выполнится
catch (Exception e) { Console.WriteLine(e.GetType().Name + ": " + e.Message); }
```

| Ловушка | Что происходит и как правильно |
| --- | --- |
| 1. Двойная подписка | `+=` не проверяет повторы: обработчик вызывается столько раз, сколько подписан. **Как надо:** подписывать один раз, например в конструкторе или в начале Main |
| 2. Отписка новой лямбдой | две одинаково записанные лямбды — **разные** объекты, `-=` не находит, что убрать. **Как надо:** сохранить обработчик в переменную и делать `+=` и `-=` с ней |
| 3. Вызов без `?.` | без подписчиков событие равно null → NullReferenceException. **Как надо:** `Событие?.Invoke(…)` |
| 4. Событие раньше изменения | подписчик читает свойство издателя и видит **старое** значение. **Как надо:** сначала изменить состояние, потом вызвать событие |
| 5. Исключение в подписчике | подписчики идут по очереди; упал второй — третий не вызовется, исключение уйдёт к тому, кто вызвал событие. **Как надо:** обработчики пишут так, чтобы они не бросали; при необходимости — try/catch внутри обработчика |

Ещё одну ошибку ловит компилятор: вызвать событие или присвоить ему `=` из другого класса — **CS0070** «событие может быть только слева от += и -=». Если это **не** ошибка, значит в классе забыли слово `event` и объявили обычное поле-делегат — тогда защита не работает.

# Задача: мини-конвейер


````task
id: step-7
lang: cs
title: 'Задача: мини-конвейер'
prompt: |-
  Главная разминка к Лабе 2 — уменьшенный `TextPipeline`. Конвейер хранит проверки и шаги-преобразования, прогоняет через них текст и сообщает о происходящем событиями.

  **Что написать**

  - `class MiniPipeline` с двумя закрытыми списками функций: `private readonly List> steps = new();` и `private readonly List> checks = new();`
  - `public void AddStep(Func step)` и `public void AddCheck(Func check)` добавляют функцию в свой список. Если передали `null` — `ArgumentNullException`.
  - Два события: `public event Action? Rejected;` — текст не прошёл проверку; `public event Action? Stepped;` — после каждого шага, параметры: текст до шага и после.
  - `public string? Run(string text)` в три части. (а) Пройди `foreach` по проверкам: на первой, которая вернула false, вызови `Rejected?.Invoke(text)` и сразу `return null`. (б) Если все прошли — пройди по шагам по порядку: `string next = step(text);`, затем `Stepped?.Invoke(text, next);`, затем `text = next;`. (в) Верни итоговый text.
  - Если проверок и шагов нет, Run возвращает текст как есть.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  var p = new MiniPipeline();
  p.AddCheck(s => s.Length > 2);
  p.AddStep(s => s.Trim());
  p.AddStep(s => s.ToUpper());
  p.Stepped += (a, b) => Console.WriteLine($"'{a}' → '{b}'");
  p.Rejected += s => Console.WriteLine($"отклонено: '{s}'");
  Console.WriteLine(p.Run("  abc ") ?? "null");   // два события Stepped, потом ABC
  Console.WriteLine(p.Run("x") ?? "null");        // короче 3 символов: Rejected, потом null

  new MiniPipeline().AddStep(null);                         // ArgumentNullException
  Console.WriteLine(new MiniPipeline().Run("без шагов"));   // без шагов
  ```

  Ожидаемый вывод:

  '  abc ' → 'abc'
  'abc' → 'ABC'
  ABC
  отклонено: 'x'
  nullMain не пиши. Ожидаемый вывод — для первых восьми строк проверки. `Stepped` вызывается с текстом **до** присваивания `text = next`, иначе «было» и «стало» совпадут.
starter: |-
  class MiniPipeline
  {
  }
solution: |-
  class MiniPipeline
  {
      private readonly List<Func<string, string>> steps = new();
      private readonly List<Func<string, bool>> checks = new();

      public event Action<string>? Rejected;
      public event Action<string, string>? Stepped;

      public void AddStep(Func<string, string> step) => steps.Add(step ?? throw new ArgumentNullException(nameof(step)));
      public void AddCheck(Func<string, bool> check) => checks.Add(check ?? throw new ArgumentNullException(nameof(check)));

      public string? Run(string text)
      {
          if (text == null) throw new ArgumentNullException(nameof(text));
          foreach (var check in checks)
              if (!check(text)) { Rejected?.Invoke(text); return null; }
          foreach (var step in steps)
          {
              string next = step(text);
              Stepped?.Invoke(text, next);
              text = next;
          }
          return text;
      }
  }
tests:
  - name: конвейер
    stdout: |-
      '  abc ' → 'abc'
      'abc' → 'ABC'
      ABC
      отклонено: 'x'
      null
    harness: |-
      var p = new MiniPipeline();
      p.AddCheck(s => s.Length > 2);
      p.AddStep(s => s.Trim());
      p.AddStep(s => s.ToUpper());
      p.Stepped += (a, b) => Console.WriteLine($"'{a}' → '{b}'");
      p.Rejected += s => Console.WriteLine($"отклонено: '{s}'");
      Console.WriteLine(p.Run("  abc ") ?? "null");
      Console.WriteLine(p.Run("x") ?? "null");
  - name: null-аргументы
    stdout: |-
      ok
      без шагов
    harness: |-
      var p = new MiniPipeline();
      try { p.AddStep(null); Console.WriteLine("нет"); } catch (ArgumentNullException) { Console.WriteLine("ok"); }
      Console.WriteLine(p.Run("без шагов"));
hints:
  - foreach (var check in checks) if (!check(text)) { Rejected?.Invoke(text); return null; } потом foreach (var step in steps) { var next = step(text); Stepped?.Invoke(text, next); text = next; } return text;
needs:
  - delegates/l2
````

# Вопросы по делегатам на защите


````cards
id: step-9
title: Вопросы по делегатам на защите
items:
  - q: Что такое делегат?
    a: Ссылочный тип, значения которого — ссылки на функции с определённой сигнатурой. Позволяет хранить функцию в переменной, передавать в другую функцию и возвращать из функции — основа функционального стиля в C#.
  - q: Чем анонимный метод отличается от лямбда-выражения?
    a: Оба — функции без имени для делегата. Анонимный метод — старый синтаксис `delegate (int x) { return x * 2; }`, лямбда — короткий `x => x * 2`, где тип параметра выводится из делегата. Лямбду можно записать выражением без блока.
  - q: Что такое замыкание?
    a: 'Лямбда, которая использует переменные из окружающего кода, вместе с этими переменными. Она захватывает саму переменную, а не копию значения. Пример: `MinLength(3)` возвращает `text => text.Length >= length`, и length живёт внутри этой функции.'
  - q: Чем событие отличается от поля-делегата?
    a: 'Событие — поле-делегат с ограничением: снаружи класса доступны только += и -=. Вызвать событие или перезаписать его может только сам класс-издатель.'
  - q: Зачем ?.Invoke?
    a: Если подписчиков нет, событие равно null. Прямой вызов бросил бы NullReferenceException, а ?. вызывает только когда есть кому.
  - q: Зачем в цикле for копировать переменную перед лямбдой?
    a: Лямбда захватывает саму переменную, а у `for` она одна на весь цикл. Без копии все лямбды увидят последнее значение. `int k = i;` внутри тела создаёт новую переменную на каждом шаге, и каждая лямбда захватывает свою.
  - q: Почему `-=` с такой же лямбдой не отписывает?
    a: Каждая запись лямбды создаёт новый объект-делегат. `-=` ищет в списке вызовов именно тот объект, который подписали, а новая лямбда — другой объект. Поэтому обработчик, который нужно будет отписать, сохраняют в переменную.
  - q: Что вернёт вызов многоадресного `Func`?
    a: Выполнятся все функции по очереди, но вернётся результат только последней. Чтобы учесть результаты всех, перебирают `GetInvocationList()`.
  - q: Почему событие вызывают после изменения состояния?
    a: Подписчик может прочитать свойства издателя. Если вызвать событие раньше, он увидит старое значение. Поэтому сначала меняем состояние, потом сообщаем.
````

  class EventBus
  {
      private readonly Dictionary<string, List<Func<int, int>>> handlers = new();

      public event Action<string, int>? Emitted;

      public Action Subscribe(string name, Func<int, int> handler)
      {
          if (name == null) throw new ArgumentNullException(nameof(name));
          if (handler == null) throw new ArgumentNullException(nameof(handler));
          if (!handlers.TryGetValue(name, out var list))
          {
              list = new List<Func<int, int>>();
              handlers[name] = list;
          }
          list.Add(handler);
          bool done = false;
          return () =>
          {
              if (done) return;
              done = true;
              list.Remove(handler);
          };
      }

      public List<int> Emit(string name, int arg)
      {
          if (name == null) throw new ArgumentNullException(nameof(name));
          var results = new List<int>();
          if (handlers.TryGetValue(name, out var list))
              foreach (var h in list) results.Add(h(arg));
          Emitted?.Invoke(name, results.Count);
          return results;
      }

      public int Count(string name) => name != null && handlers.TryGetValue(name, out var list) ? list.Count : 0;
  }
