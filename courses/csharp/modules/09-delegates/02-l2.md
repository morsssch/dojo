# Три способа записать функцию

Функцию для делегата не обязательно объявлять отдельным методом с именем.

```cs run
delegate string TextTransformer(string s);

class Program
{
    static string Upper(string s) => s.ToUpper();

    static void Main()
    {
        TextTransformer a = Upper;                                 // 1) именованный метод
        TextTransformer b = delegate (string s) { return s + "!"; }; // 2) анонимный метод
        TextTransformer c = s => s.Replace(" ", "_");              // 3) лямбда-выражение
        TextTransformer d = (string s) => { var r = s.Trim(); return $"[{r}]"; }; // лямбда с блоком

        foreach (var f in new[] { a, b, c, d })
            Console.WriteLine(f("  hi there "));
    }
}
```

**Анонимный метод** (`delegate (…) { … }`) — старый синтаксис C# 2.0. **Лямбда** (`параметры => тело`) — современный. В Лабе 2 демо должно показать **оба**: «применение анонимных методов и лямбда-выражений для создания кастомных функций-преобразователей и валидаторов».

| Запись | Смысл |
| --- | --- |
| `x => x * 2` | один параметр, тип выводится из делегата |
| `(a, b) => a + b` | несколько параметров — в скобках |
| `() => 42` | без параметров |
| `s => { …; return r; }` | тело-блок, return обязателен (для не-void) |
| `_ => true` | параметр не нужен |

> [!WARNING] Снова про «стрелочную функцию»
> `int Sq(int x) => x * x;` — метод в стрелочной форме, у него есть имя, он член класса. `x => x * x` — лямбда: имени нет, это значение, которое кладут в делегат. Стрелка одна, смысл разный. Если на защите спросят «почему тут стрелочная функция» про лямбду — «это лямбда-выражение, анонимная функция, её передают как делегат; отдельный метод для одной строчки заводить незачем».


# Замыкания и функции, возвращающие функции

Лямбда может использовать переменные из окружающего кода — она их **захватывает**. Функция вместе с захваченными переменными называется **замыканием**. Так делают **фабрики функций**: функция принимает настройку и возвращает новую функцию.

```cs run
delegate bool TextValidator(string text);

static class TextProcessors
{
    public static TextValidator MinLength(int length) => text => text.Length >= length;   // length захвачен
    public static TextValidator MaxLength(int length) => text => text.Length  Multiplier(int k) => x => x * k;
}

class Program
{
    static void Main()
    {
        TextValidator atLeast3 = TextProcessors.MinLength(3);
        TextValidator atMost5 = TextProcessors.MaxLength(5);
        foreach (var w in new[] { "ок", "кот", "лампочка" })
            Console.WriteLine($"{w}: {atLeast3(w) && atMost5(w)}");

        var triple = TextProcessors.Multiplier(3);
        Console.WriteLine(triple(14));

        int counter = 0;                        // захват изменяемой переменной
        Action inc = () => counter++;
        inc(); inc(); inc();
        Console.WriteLine("counter = " + counter);
    }
}
```

Это в точности методы `MinLength(int length)`, `MaxLength`, `ContainsWord(string word)` из твоей Лабы 2: «статический класс со методами, возвращающими функции-валидаторы».

## Композиция

Из двух функций можно собрать третью: (f∘g)(x) = f(g(x)). Это классика ФП и основа конвейера.

```cs run
Func Compose(Func f, Func g) => x => f(g(x));
Func Chain(params Func[] fs) => x => { foreach (var f in fs) x = f(x); return x; };

Func trim = s => s.Trim();
Func upper = s => s.ToUpper();
Func exclaim = s => s + "!";

Console.WriteLine(Compose(upper, trim)("  hello  "));
Console.WriteLine(Chain(trim, upper, exclaim)("  конвейер  "));
```


# Ловушки лямбд и захвата

Первые три ловушки находит компилятор, четвёртая тихая: код работает, но выдаёт не то. Её любят спрашивать на собеседованиях, а для Лабы 2 она важна, если валидаторы или шаги конвейера создаются в цикле.

## 1. Блок без return: CS1643

```cs
Func f = x => { var y = x * 2; };   // CS1643: не все пути возвращают значение
Func g = x => { return x * 2; };    // так
Func h = x => x * 2;                // или короче — без фигурных скобок
```

Правило то же, что у методов ([модуль 5](lesson:methods/l1)): тело в `{ }` обязано вернуть значение через `return`, а выражение после `=>` без скобок возвращается само.

## 2. Несколько параметров без скобок: CS1003

```cs
Func add = a, b => a + b;     // CS1003: синтаксическая ошибка
Func ok  = (a, b) => a + b;
```

Без скобок можно только один параметр. Если число параметров не совпадает с делегатом, будет CS1593 «делегат не принимает 2 аргумента».

## 3. var без типа параметра: CS8917

```cs
var f = x => x * 2;                           // CS8917: не удалось вывести тип делегата
var g = (int x) => x * 2;                     // так можно: компилятор выведет Func
Func h = x => x * 2;                // а так понятнее всего
```

Тип параметра лямбда берёт из делегата слева. Если слева `var`, брать неоткуда.

## 4. Захват переменной цикла for

```cs run
var fs = new List>();
for (int i = 0; i  i);                    // все три лямбды захватили ОДНУ переменную i
foreach (var f in fs) Console.Write(f() + " ");   // 3 3 3 — к моменту вызова i уже 3
Console.WriteLine();

var gs = new List>();
for (int i = 0; i  copy);
}
foreach (var g in gs) Console.Write(g() + " ");   // 0 1 2
```

**Почему:** замыкание захватывает **саму переменную**, а не её значение на момент создания лямбды. Переменная `i` у `for` одна на весь цикл, и после цикла в ней 3. **Исправление:** скопировать в переменную, объявленную **внутри** тела цикла. У `foreach` переменная своя на каждом шаге, поэтому с ним ловушки нет.

static-лямбда: запретить захват явно
Если лямбда не должна ничего захватывать, перед ней можно написать `static`: `Func f = static x => x * 2;`. Попытка использовать внешнюю переменную даст CS8820. На лабах это не требуют, но если преподаватель спросит про «чистые функции», это хороший пример: результат зависит только от аргументов.

````task
  **Что написать**

  {
      public static Func<int> Counter(int start, int step)

          return () =>

              next += step;
              return r;
          };

      public static List<Func<int>> Squares(int n)
      {
          var list = new List<Func<int>>();
          for (int i = 0; i < n; i++)
          {
              int k = i;
              list.Add(() => k * k);
          }
          return list;
      }
  }
````

# Задача: фабрика валидаторов


````task
id: step-6
lang: cs
title: 'Задача: фабрика валидаторов'
prompt: |-
  Фабрика функций: методы не проверяют текст сами, а **возвращают** функцию-валидатор, которая проверит текст потом. Ровно так устроен `TextProcessors` в твоей Лабе 2 (`MinLength`, `MaxLength`, `ContainsWord`).

  **Что написать**

  - Делегат `delegate bool TextValidator(string text);` уже в заготовке, не удаляй его. Под ним — `static class Validators`; все методы `public static` и возвращают `TextValidator`.
  - `MinLength(int n)` возвращает лямбду `text => …`: true, если длина текста ≥ n. `MaxLength(int n)` — то же для длины ≤ n.
  - `ContainsWord(string word)`: **до** return проверь `word == null` → `ArgumentNullException`. Возвращает валидатор: разбей текст `Split` по символам `' ' ',' '.' '!' '?' ';' ':'` с `StringSplitOptions.RemoveEmptyEntries` и проверь, что хотя бы одно слово равно `word` без учёта регистра: `string.Equals(w, word, StringComparison.OrdinalIgnoreCase)`. Слово должно совпасть целиком: в «котлета» слова «кот» нет.
  - `All(params TextValidator[] vs)` возвращает валидатор, который даёт true, только если **каждый** из `vs` вернул true (цикл `foreach` по vs).
  - `Not(TextValidator v)` возвращает валидатор с обратным ответом: `!v(text)`.
  - Правило для всех пяти: если валидатору передали `null` вместо текста, он возвращает `false` — и `Not` тоже false, а не true. Проще всего начинать каждую лямбду с `text != null && …`.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  var v = Validators.All(Validators.MinLength(3), Validators.MaxLength(6));
  foreach (var s in new[] { "ab", "abc", "abcdef", "abcdefg", null })
      Console.Write(v(s) + " ");                    // False True True False False
  Console.WriteLine();

  var hasCat = Validators.ContainsWord("кот");
  Console.WriteLine(hasCat("Вот КОТ, спит.") + " " + hasCat("котлета") + " " + hasCat("кот"));   // True False True
  var noCat = Validators.Not(hasCat);
  Console.WriteLine(noCat("собака") + " " + noCat("кот!"));                                     // True False
  Validators.ContainsWord(null);                    // ArgumentNullException — сразу, при создании валидатора
  ```

  Ожидаемый вывод:

  False True True False False
  True False True
  True FalseMain не пиши. Как выглядит метод, возвращающий лямбду: `public static TextValidator MinLength(int n) => text => text != null && text.Length >= n;` Первая стрелка — стрелочная форма метода, вторая — сама возвращаемая функция. Число `n` она запоминает (замыкание из теории выше).
starter: |-
  delegate bool TextValidator(string text);

  static class Validators
  {
  }
solution: |-
  delegate bool TextValidator(string text);

  static class Validators
  {
      public static TextValidator MinLength(int n) => text => text != null && text.Length >= n;
      public static TextValidator MaxLength(int n) => text => text != null && text.Length <= n;

      public static TextValidator ContainsWord(string word)
      {
          if (word == null) throw new ArgumentNullException(nameof(word));
          char[] seps = { ' ', ',', '.', '!', '?', ';', ':' };
          return text => text != null && text.Split(seps, StringSplitOptions.RemoveEmptyEntries)
              .Any(w => string.Equals(w, word, StringComparison.OrdinalIgnoreCase));
      }

      public static TextValidator All(params TextValidator[] vs) => text =>
      {
          if (text == null) return false;
          foreach (var v in vs) if (!v(text)) return false;
          return true;
      };

      public static TextValidator Not(TextValidator v) => text => text != null && !v(text);
  }
````

# Задача: композиция и частичное применение


````task
id: step-7
lang: cs
title: 'Задача: композиция и частичное применение'
prompt: |-
  Собираем новые функции из готовых: композиция, конвейер и частичное применение. Все три метода возвращают `Func` — лямбду, которую потом вызывают с числом. Это разминка к варианту 4 Лабы 2, а `Pipe` — та же идея, что конвейер в твоём `TextPipeline`.

  **Что написать**

  - Всё внутри `static class Compose`, методы `public static`.
  - `public static Func Of(Func f, Func g)` — возвращает функцию, которая для x даёт `f(g(x))`: **сначала g**, потом f (как f∘g в математике).
  - `public static Func Pipe(params Func[] fs)` — возвращает функцию, которая прогоняет x через fs по порядку слева направо: сначала fs[0], результат — в fs[1] и так далее. Если fs пустой, x возвращается без изменений (с циклом `foreach` это получится само).
  - `public static Func Partial(Func op, double first)` — возвращает функцию одного аргумента x, которая считает `op(first, x)`: первый аргумент уже «вшит».

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  Func inc = x => x + 1, dbl = x => x * 2;
  Console.WriteLine(Compose.Of(inc, dbl)(5));                  // 11: dbl(5) = 10, потом inc → 11
  Console.WriteLine(Compose.Of(dbl, inc)(5));                  // 12: inc(5) = 6, потом dbl → 12
  Console.WriteLine(Compose.Pipe(inc, dbl, Math.Sqrt)(7));     // 4: 7 + 1 = 8, 8 * 2 = 16, √16 = 4
  Console.WriteLine(Compose.Pipe()(3.5));                      // 3,5 — пустой конвейер ничего не меняет
  Console.WriteLine(Compose.Partial(Math.Pow, 2)(10));         // 1024: Math.Pow(2, 10)
  Console.WriteLine(Compose.Partial((a, b) => a - b, 100)(1)); // 99: 100 - 1
  ```

  Ожидаемый вывод:

  11
  12
  4
  3,5
  1024
  99Main не пиши. `3,5` через запятую — не опечатка: в курсе русская культура, и `double` печатается с запятой.
starter: |-
  static class Compose
  {
  }
solution: |-
  static class Compose
  {
      public static Func<double, double> Of(Func<double, double> f, Func<double, double> g) => x => f(g(x));

      public static Func<double, double> Pipe(params Func<double, double>[] fs) => x =>
      {
          foreach (var f in fs) x = f(x);
          return x;
      };

      public static Func<double, double> Partial(Func<double, double, double> op, double first) => x => op(first, x);
  }

      1024

      Console.WriteLine(Compose.Of(dbl, inc)(5));
      Console.WriteLine(Compose.Pipe(inc, dbl, Math.Sqrt)(7));
      Console.WriteLine(Compose.Pipe()(3.5));
````
