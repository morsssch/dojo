# Что такое делегат

На лекции 08.09 делегаты (в конспекте «деликаты») стоят в списке **ссылочных** типов. Делегат — это тип, значения которого — **ссылки на функции** с определённой сигнатурой. Переменная делегата хранит функцию, как `int`-переменная хранит число.

дополнение Объявление делегата описывает сигнатуру: что принимает и что возвращает.

```cs run
delegate string TextTransformer(string text);   // тип: string → string
delegate bool TextValidator(string text);        // тип: string → bool

class Program
{
    static string Shout(string s) => s.ToUpper() + "!";
    static string Whisper(string s) => s.ToLower() + "…";
    static bool NotEmpty(string s) => !string.IsNullOrWhiteSpace(s);

    static void Main()
    {
        TextTransformer t = Shout;          // кладём метод в переменную (без скобок!)
        Console.WriteLine(t("привет"));     // вызываем через переменную
        t = Whisper;                        // переменная теперь указывает на другой метод
        Console.WriteLine(t("ПРИВЕТ"));

        TextValidator v = NotEmpty;
        Console.WriteLine(v("  ") + " " + v("текст"));
    }
}
```

Два делегата из твоей Лабы 2 — `TextTransformer` и `TextValidator` — объявляются ровно так.

Связь с названием предмета
Функциональное программирование держится на идее «функция — это значение»: её можно положить в переменную, в список, передать в другую функцию и вернуть из функции. В C# это делают делегаты. Весь этот модуль — про это.


# Делегат по строкам: присвоить, вызвать, null

Разберём, что лежит в переменной делегата на каждой строке. Переменная делегата — **ссылочная**, как массив ([модуль 2, значимые и ссылочные типы](lesson:variables/l3)): в ней хранится ссылка на объект-делегат, а он помнит, какой метод вызывать.

```cs run
delegate string TextTransformer(string text);

class Program
{
    static string Shout(string s) => s.ToUpper() + "!";

    static void Main()
    {
        TextTransformer? t = null;                       // 1
        Console.WriteLine(t == null);                    // 2
        Console.WriteLine(t?.Invoke("тихо") ?? "(никого)"); // 3
        t = Shout;                                       // 4
        Console.WriteLine(t("привет"));                  // 5
        Console.WriteLine(t.Invoke("привет"));           // 6
        Console.WriteLine(t.Method.Name);                // 7
        TextTransformer t2 = t;                          // 8
        t = null;                                        // 9
        Console.WriteLine(t2("ещё раз"));                // 10
    }
}
```

| Строка | В переменных | Что происходит |
| --- | --- | --- |
| 1 | `t`: null | переменная есть, функции в ней нет |
| 2 | `t`: null | печатает `True` |
| 3 | `t`: null | `?.` видит null и не вызывает; `??` подставляет «(никого)» |
| 4 | `t`: → Shout | метод кладётся **без скобок**: это не вызов, а «вот эта функция» |
| 5–6 | `t`: → Shout | `t("привет")` и `t.Invoke("привет")` — одно и то же: оба вызывают Shout |
| 7 | `t`: → Shout | делегат знает свой метод: печатает `Shout` |
| 8 | `t`: → Shout `t2`: → Shout | скопировалась **ссылка**, обе переменные указывают на один делегат |
| 9–10 | `t`: null `t2`: → Shout | обнулили только t, t2 по-прежнему работает |

> [!WARNING] Вызов пустого делегата
> Если в строке 3 написать `t("тихо")` без `?.`, программа упадёт с **NullReferenceException**: вызывать нечего. Компилятор это не ловит. Поэтому делегат, который могли не задать (необязательный обработчик, событие без подписчиков), вызывают через `?.Invoke(…)`. Запись `t?.("x")` в C# не существует — именно поэтому пишут длинное `?.Invoke`.

Как сказать на защите
«В переменной делегата хранится ссылка на метод. Без скобок я передаю сам метод, со скобками — вызываю его. Если делегат может быть пустым, вызываю через `?.Invoke`, иначе будет NullReferenceException».

# Готовые делегаты: Func, Action, Predicate

Чтобы не объявлять делегат под каждую сигнатуру, в .NET есть готовые обобщённые:

| Тип | Сигнатура | Пример |
| --- | --- | --- |
| `Func` | принимает T, возвращает TResult. Последний параметр типа — всегда результат | `Func sq`, `Func add` |
| `Action` | принимает T, ничего не возвращает (void) | `Action log = Console.WriteLine;` |
| `Predicate` | принимает T, возвращает bool | `Predicate isEven` |

Главное применение — **функции высшего порядка**: функция принимает другую функцию параметром. Поведение подставляется снаружи.

# Четыре типичные ошибки с делегатами

Все четыре компилятор или программа покажут сразу, но сообщение не всегда понятно с первого раза. Для каждой: как выглядит, что скажет компилятор, почему и как исправить.

## 1. Не та сигнатура: CS0123 и CS0407

```cs
delegate string TextTransformer(string text);

static string FromInt(int x) => x.ToString();
static int Len(string s) => s.Length;

TextTransformer a = FromInt;   // CS0123: нет перегрузки FromInt, подходящей делегату
TextTransformer b = Len;       // CS0407: Len имеет неправильный возвращаемый тип
```

**Почему:** делегат — это договор «принимает string, возвращает string». `FromInt` принимает int — не те параметры (CS0123). `Len` возвращает int — не тот результат (CS0407). **Исправление:** метод должен совпасть по параметрам и по типу результата, имя значения не имеет.

## 2. Скобки там, где нужен сам метод: CS0029

```cs
TextTransformer t = Shout("x");   // CS0029: нельзя преобразовать string в TextTransformer
```

**Почему:** со скобками метод **вызывается**, и в переменную пытается попасть его результат — строка. **Исправление:** `TextTransformer t = Shout;` — без скобок.

## 3. void-метод в Func: CS0407

```cs
static void Log(string s) => Console.WriteLine(s);
Func f = Log;     // CS0407: неправильный возвращаемый тип
Action g = Log;           // так правильно
```

**Почему:** у `Func` последний параметр типа — всегда результат, значит `Func` обязан что-то вернуть. Для методов без результата — `Action`.

## 4. Вызов пустого делегата: NullReferenceException

```cs
Func? f = null;
Console.WriteLine(f(5));          // компилируется, но падает при запуске
```

**Исправление:** присвоить функцию до вызова, проверить `if (f != null)` или вызвать `f?.Invoke(5)`. А если параметр-делегат **обязателен** (как `op` в калькуляторе), правильнее сразу бросить `ArgumentNullException` — так в лабах требуют «проверку параметров на null».

| Симптом | Скорее всего |
| --- | --- |
| CS0123 «нет перегрузки, соответствующей делегату» | у метода другие параметры |
| CS0407 «неправильный возвращаемый тип» | другой тип результата, часто void вместо значения |
| CS0029 «нельзя преобразовать string в …» | написал вызов со скобками вместо имени метода |
| NullReferenceException при вызове | в делегат ничего не положили |
