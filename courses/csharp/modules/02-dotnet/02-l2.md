# От текста до машинного кода

Процессор понимает только машинный код своей архитектуры: у твоего Mac на Apple Silicon он один (ARM64), у компьютера в аудитории другой (x64). C# решает это в два прыжка:

![Program.cs компилируется Roslyn в сборку с IL при сборке, а при запуске CLR с помощью JIT переводит IL каждого метода в машинный код процессора](./diagrams/csharp/diagram-1.svg)

По лекции:

**.net → Intermediate Language (IL)** — «абстрактный ООП ассемблер». IL не привязан к процессору: в нём есть понятия класса, метода, вызова, но нет регистров конкретного процессора.

- **JIT — Just in Time Compilation**. IL компилируется в машинный код **на лету**. По умолчанию: вызов метода вызывает проверку, есть ли для него машинный код. Если нет — компилируется **конкретный метод**, а не вся программа.

## Два вида ошибок — два момента времени

|  | Ошибка компиляции | Исключение во время выполнения |
| --- | --- | --- |
| Когда | при сборке, программа ещё не запускалась | программа уже работает |
| Кто находит | компилятор Roslyn | среда CLR |
| Как выглядит | `CS0029: Не удаётся неявно преобразовать тип "string" в "int"` | `System.DivideByZeroException` |
| Пример | `int x = "5";` | `int z = 0; Console.WriteLine(1 / z);` |

Правило: чем больше ошибок ловит компилятор, тем лучше — их видно до запуска. Поэтому C# такой строгий: запреты на неинициализированные переменные или `while (i)` — это ошибки, которые иначе вылезли бы во время работы.


# Заглянуть в IL своими глазами

Сборку можно не только запускать, но и читать: в ней хранится IL каждого метода. Программа ниже берёт твой метод `Sum`, достаёт его IL-байты и переводит их в названия инструкций.

```cs run
using System.Reflection;
using System.Reflection.Emit;

// таблица «код операции → инструкция IL» из самой платформы
var ops = typeof(OpCodes).GetFields(BindingFlags.Public | BindingFlags.Static)
    .Select(f => (OpCode)f.GetValue(null)!).ToDictionary(o => o.Value, o => o);

byte[] il = typeof(Calc).GetMethod("Sum")!.GetMethodBody()!.GetILAsByteArray()!;
Console.WriteLine("Байты: " + string.Join(" ", il.Select(b => b.ToString("X2"))));
foreach (byte b in il) Console.WriteLine(ops[b].Name);

class Calc
{
    public static int Sum(int a, int b) => a + b;
}
```

Получится 4 байта и 4 инструкции:

| IL | Что делает | Стек вычислений после |
| --- | --- | --- |
| ldarg.0 | положить на стек аргумент №0 (a) | a |
| ldarg.1 | положить аргумент №1 (b) | a, b |
| add | снять два верхних, сложить, положить результат | a+b |
| ret | вернуть то, что на вершине |  |

IL — **стековая машина**: инструкции не имеют имён регистров, они кладут значения на стек и снимают их. Именно поэтому IL не зависит от процессора, а JIT уже раскладывает это по регистрам конкретного железа. Это и есть «абстрактный ООП ассемблер» с лекции.

Попробуй в песочнице заменить `a + b` на `a * b` или `a - b + 1` и посмотри, как изменится IL.


# Задача: IL умножения


````task

  В заготовке программа печатает IL метода `Calc.Op`. Напиши метод `Op` так, чтобы его IL был ровно таким:

  ```cs
  ldarg.0
  ldarg.1
  mul
  ldc.i4.1
  sub
  ret
  ```

  Подсказка по инструкциям: `mul` — умножение, `sub` — вычитание, `ldc.i4.1` — положить на стек целую константу 1. Подумай, какому выражению на C# соответствует эта последовательность.

  using System.Reflection;
  using System.Reflection.Emit;

  var ops = typeof(OpCodes).GetFields(BindingFlags.Public | BindingFlags.Static)
      .Select(f => (OpCode)f.GetValue(null)!).ToDictionary(o => o.Value, o => o);
  foreach (byte b in typeof(Calc).GetMethod("Op")!.GetMethodBody()!.GetILAsByteArray()!)
      Console.WriteLine(ops[b].Name);

  class Calc
  {
      public static int Op(int a, int b) => a + b;   // измени выражение
  }
solution: |-
  using System.Reflection;
  using System.Reflection.Emit;

  var ops = typeof(OpCodes).GetFields(BindingFlags.Public | BindingFlags.Static)
      .Select(f => (OpCode)f.GetValue(null)!).ToDictionary(o => o.Value, o => o);
  foreach (byte b in typeof(Calc).GetMethod("Op")!.GetMethodBody()!.GetILAsByteArray()!)
      Console.WriteLine(ops[b].Name);

  class Calc
  {
      public static int Op(int a, int b) => a * b - 1;
  }
tests:
  - stdout: |-
      ldarg.0
      ldarg.1
      mul
      ldc.i4.1
      sub
      ret
hints:
  - 'Читай стек: a, потом b, перемножить, потом 1, вычесть. Получается (a * b) - 1.'
````
