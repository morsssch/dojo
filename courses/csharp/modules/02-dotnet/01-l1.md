# Язык и платформа — это разные вещи

Новички часто говорят «шарпы» и «дотнет» как одно и то же. Это две разные вещи, которые работают в паре.

|  | C# | .NET |
| --- | --- | --- |
| Что это | **Язык программирования**: правила, по которым пишется текст программы — ключевые слова, типы, синтаксис | **Платформа**: всё, что нужно, чтобы программа на этом языке запустилась и работала |
| Из чего состоит | спецификация языка + компилятор (Roslyn), который превращает текст в промежуточный код | **CLR** — среда выполнения (запускает код, управляет памятью); **BCL** — огромная библиотека готовых классов (`Console`, `List`, `Math`…); **SDK** — инструменты: команда `dotnet`, сборка проектов, менеджер пакетов NuGet |
| Аналогия | русский язык: грамматика и слова | инфраструктура, в которой этот язык работает: почта, бумага, типография |

**Связь:** программу пишут на C#, компилятор C# переводит её в код для платформы .NET, а .NET её выполняет. При этом на .NET работают и другие языки — F#, Visual Basic. На лекции 01.09 прозвучало: *50+ языков, включая C#, C++ и F#, компилируются в IL*. Все они пользуются одной библиотекой BCL и одной средой CLR, поэтому класс, написанный на F#, можно вызвать из C#.

## Тебе это уже знакомо

Ты писал на TypeScript. Там та же схема из двух слоёв:

| Роль | Мир TypeScript | Мир C# |
| --- | --- | --- |
| Язык, на котором пишешь | TypeScript | C# |
| Компилятор | `tsc` | Roslyn (`csc`), вызывается из `dotnet build` |
| Во что компилируется | JavaScript | IL — промежуточный язык, в файле `.dll` |
| Что исполняет | движок V8 (в Chrome и Node.js) | CLR — среда выполнения .NET |
| Как исполняет | JIT-компиляция горячего кода в машинный | JIT-компиляция каждого метода в машинный код при первом вызове |
| Стандартная библиотека | браузерные API, модули Node | BCL: `System.*` |
| Пакеты | npm | NuGet |
| Команда в терминале | `npm`, `node` | `dotnet` |

И ещё совпадение не случайное: главный автор C# — **Андерс Хейлсберг**, и он же позже придумал TypeScript. Поэтому многое в TypeScript (классы, интерфейсы, обобщения `List`, стрелки `=>`) покажется тебе в C# знакомым.

Главное отличие от TypeScript
В TypeScript типы живут только при компиляции: в JavaScript их уже нет, и во время работы `"5" + 1` спокойно станет `"51"`. В C# типы существуют и при выполнении: среда знает, что лежит в каждой переменной, и не даст положить строку туда, где ждут число. Отсюда и строгость: многие ошибки C# ловит ещё до запуска.


# Короткая история

| Год | Событие | Почему тебе это важно |
| --- | --- | --- |
| 1995 | Sun выпускает Java и виртуальную машину JVM: «написал один раз — запускай везде» | На лекции 01.09 преподаватель начал именно с JVM — .NET задумывался как ответ Java |
| 2000 | Microsoft анонсирует платформу .NET и язык C# |  |
| 2002 | .NET Framework 1.0 и C# 1.0. Работает только на Windows | В конспекте таблица типов озаглавлена «.net Framework» — это оттуда |
| 2004 | Mono — открытая реализация .NET для Linux и macOS. На ней позже вырос Unity | В браузере этого курса работает потомок именно Mono |
| 2005 | C# 2.0: обобщения `List`, анонимные методы | Анонимные методы — в Лабе 2 |
| 2007 | C# 3.0: `var`, лямбды, методы расширения, LINQ | Ядро Лабы 2 |
| 2010 | C# 4.0: параметры по умолчанию и именованные аргументы | Лекция 15.09 |
| 2016 | .NET Core: открытый код, Windows + Linux + macOS | Поэтому C# работает на твоём Mac |
| 2019 | .NET Framework 4.8 — последняя большая версия старой ветки |  |
| 2020 | .NET 5: ветки объединены, слово «Core» убрали. C# 9: записи `record`, код без класса Program | Записи — Лаба 2 (вариант 1, 3, 5) |
| 2023 | .NET 8 (долгая поддержка) и C# 12 |  |
| 2025 | .NET 10 (долгая поддержка) и C# 14 | Это версия, на которой работает курс |

> [!DEEP] Путаница в названиях
> «.NET Framework» — старая платформа только для Windows. «.NET» без слова Framework (раньше «.NET Core») — современная кроссплатформенная. Базовые типы (`System.Int32`, `System.String`…) и язык у них общие, поэтому всё из лекций верно для обеих. Новые проекты, в том числе твои лабы, создаются на современной .NET.
