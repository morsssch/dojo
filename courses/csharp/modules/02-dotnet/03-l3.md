# Полное имя типа

Классов в BCL тысячи, и у многих одинаковые короткие имена. Порядок наводят **пространства имён**. У каждого типа есть полное имя. Пример с лекции:

| Запись | Что это |
| --- | --- |
| `System.Collections.ArrayList` | **FullName** — полное имя |
| `ArrayList` | имя типа данных |
| `System.Collections` | пространство имён |

- В одной программе не может быть двух типов с одинаковым **полным** именем. А с одинаковым коротким — сколько угодно, если они в разных пространствах.

- В JVM пакеты — это конкретные каталоги на диске, а в .net пространство имён — просто часть имени, без физической реализации. Классы одного пространства могут лежать в разных файлах и даже в разных сборках.

- В .net `using` — лишь способ сокращения названий. Стандартные имена подключены и доступны всегда.

- `using AL = System.Collections.ArrayList;` создаёт сокращение (псевдоним) для типа.

```cs run
using AL = System.Collections.ArrayList;

System.Console.WriteLine("без using: полное имя работает всегда");

var list = new AL();       // псевдоним вместо длинного имени
list.Add(5);
list.Add("пять");
System.Console.WriteLine(list.Count);
System.Console.WriteLine(typeof(AL).FullName);
System.Console.WriteLine(typeof(AL).Namespace);
System.Console.WriteLine(typeof(AL).Name);
```


# Сборка и свои пространства имён

**Сборка** (assembly) — результат компиляции проекта: файл `.dll` (или `.exe`) с IL всех методов и **метаданными** — описанием всех типов, их полей и методов. Именно по метаданным среда знает, что лежит в каждой переменной, а ты в Лабе 3 через рефлексию будешь искать в чужих сборках классы с нужным интерфейсом.

Своё пространство имён объявляется так (две записи равносильны):

```cs
namespace Labs.Math
{
    class Rational { }
}

// короткая форма C# 10: действует до конца файла
namespace Labs.Math;
class Rational { }
```

```cs run
namespace Shop
{
    class Product { public string Name = "чай"; }
}
namespace Warehouse
{
    class Product { public int Stock = 12; }   // то же короткое имя — другое полное
}

class Program
{
    static void Main()
    {
        var a = new Shop.Product();
        var b = new Warehouse.Product();
        System.Console.WriteLine(a.GetType().FullName + ": " + a.Name);
        System.Console.WriteLine(b.GetType().FullName + ": " + b.Stock);
        System.Console.WriteLine(typeof(Program).Assembly.GetName().Name); // имя сборки, в которой мы
    }
}
```

Неявные using
В новом проекте .NET включены «неявные using»: `System`, `System.Collections.Generic`, `System.IO`, `System.Linq`, `System.Threading`, `System.Threading.Tasks` подключены автоматически, и `using System;` можно не писать. В этом курсе они тоже подключены, как в проекте. На лекции и в старых книгах `using System;` пишут явно — это не ошибка.

````task

title: 'Задача: полные имена'
prompt: 'Не используя ни одной директивы `using`, выведи три строки: полное имя типа `int`, полное имя типа `string` и количество элементов в списке `System.Collections.Generic.List`, в который добавлены числа 1, 2, 3. Подсказка: `typeof(int).FullName`.'
starter: // без using!
solution: |-
  System.Console.WriteLine(typeof(int).FullName);
  System.Console.WriteLine(typeof(string).FullName);
  var list = new System.Collections.Generic.List<int>();

  System.Console.WriteLine(list.Count);

  - stdout: |-

    message: 'Здесь нужно обойтись без using: пиши полные имена.'
````

# Задача: псевдоним типа


````task
id: step-4
lang: cs
title: 'Задача: псевдоним типа'
prompt: Создай псевдоним `Dict` для типа `System.Collections.Generic.Dictionary`, создай через него словарь, положи `"лаб" → 4` и `"экз" → 1` и выведи `лаб=4 экз=1`.
starter: // using Dict = …;
solution: |-
  using Dict = System.Collections.Generic.Dictionary<string, int>;

  var d = new Dict();
  d["лаб"] = 4;
  d["экз"] = 1;
  Console.WriteLine($"лаб={d["лаб"]} экз={d["экз"]}");
tests:
  - stdout: лаб=4 экз=1
hints:
  - using Dict = System.Collections.Generic.Dictionary; var d = new Dict(); d["лаб"] = 4;
require:
  - - using\s+Dict\s*=
    - 'Нужен псевдоним: using Dict = …;'
````
