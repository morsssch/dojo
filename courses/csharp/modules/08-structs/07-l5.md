# From и TryCreate

В твоём варианте Лабы 1 требуются две фабрики — статические методы, создающие значение:

- `From(int n, int d)` — возвращает рациональное число, при ошибке бросает исключение;

- `TryCreate(int n, int d, out Rational value)` — возвращает успешность, число кладёт в out-параметр, **исключений не бросает**.

Это тот же шаблон, что `int.Parse` / `int.TryParse`. Типичная реализация: вся логика — в одном месте (конструктор или From), TryCreate проверяет условия заранее и не допускает исключения.

```cs run
readonly struct Percent
{
    public double Value { get; }

    private Percent(double v) => Value = v;       // снаружи — только через фабрики

    public static Percent From(double v)
    {
        if (double.IsNaN(v) || v  100) throw new ArgumentOutOfRangeException(nameof(v), "Процент от 0 до 100");
        return new Percent(v);
    }

    public static bool TryCreate(double v, out Percent value)
    {
        if (double.IsNaN(v) || v  100) { value = default; return false; }
        value = new Percent(v);
        return true;
    }

    public override string ToString() => $"{Value}%";
}

class Program
{
    static void Main()
    {
        Console.WriteLine(Percent.From(12.5));
        Console.WriteLine(Percent.TryCreate(150, out var p) + " " + p);
        Console.WriteLine(Percent.TryCreate(99, out var q) + " " + q);
        try { Percent.From(-1); } catch (ArgumentOutOfRangeException) { Console.WriteLine("From бросил исключение"); }
    }
}
```

Почему TryCreate не ловит исключение из From
Можно написать `try { value = From(n, d); return true; } catch { value = default; return false; }`, и это будет работать. Но исключения медленные и прячут настоящие ошибки. Лучше заранее проверить условие (d != 0) и не допустить исключения. Если спросят на защите — это хороший аргумент.


# Каркас демо-программы для лабы

Последний пункт любой лабы — «консольное приложение, демонстрирующее работу». Плюс общие требования: проверки на null и обработка ошибок с выбором «продолжить/выйти». Удобный каркас — меню в цикле:

```cs run
using System;

class Program
{
    static void Main()
    {
        while (true)
        {
            Console.WriteLine("1 — разобрать дробь, 2 — сложить, 0 — выход");
            string? choice = Console.ReadLine();
            if (choice == null || choice == "0") break;
            try
            {
                switch (choice)
                {
                    case "1":
                        Console.WriteLine("Разбираю: " + Console.ReadLine());
                        break;
                    case "2":
                        string? a = Console.ReadLine(), op = Console.ReadLine(), b = Console.ReadLine();
                        Console.WriteLine($"Считаю {a} {op} {b}");
                        break;
                    default:
                        Console.WriteLine("Нет такого пункта");
                        break;
                }
            }
            catch (Exception e)
            {
                Console.WriteLine($"Ошибка ({e.GetType().Name}): {e.Message}");
                Console.Write("Продолжить? (д/н): ");
                if (Console.ReadLine()?.Trim().ToLower() != "д") break;
            }
        }
        Console.WriteLine("До свидания!");
    }
}
```

Пример ввода: `1
3/4
1/0
д
2
1/2
+
1/3
0
`
Для защиты полезно, чтобы демо показывало каждое требование задания отдельным пунктом или блоком с подписью: «Нормализация», «Знак в числителе», «TryCreate», «Операторы», «Сравнение». Тогда проверяющему не нужно самому придумывать, что ввести.


# Задача: цвет по фабрике


````task
id: step-3
lang: cs
title: 'Задача: цвет по фабрике'
prompt: |-
  Опиши `readonly struct Rgb` с байтовыми свойствами `R`, `G`, `B` и **закрытым** конструктором, плюс:

  - `static Rgb From(int r, int g, int b)` — каждое 0..255, иначе `ArgumentOutOfRangeException`;
  - `static bool TryParse(string s, out Rgb value)` — строка вида `#1A2B3C` (ровно 7 символов, решётка, 6 шестнадцатеричных цифр); без исключений; для `null` — false;
  - `ToString()` → `#RRGGBB` заглавными (`{R:X2}`).

  Подсказка по разбору: `byte.TryParse(s.Substring(1, 2), System.Globalization.NumberStyles.HexNumber, null, out byte r)`.
starter: |-
  readonly struct Rgb
  {
  }
solution: |-
  using System.Globalization;

  readonly struct Rgb
  {
      public byte R { get; }
      public byte G { get; }
      public byte B { get; }

      private Rgb(byte r, byte g, byte b) { R = r; G = g; B = b; }

      public static Rgb From(int r, int g, int b)
      {
          if (r < 0 || r > 255) throw new ArgumentOutOfRangeException(nameof(r));
          if (g < 0 || g > 255) throw new ArgumentOutOfRangeException(nameof(g));
          if (b < 0 || b > 255) throw new ArgumentOutOfRangeException(nameof(b));
          return new Rgb((byte)r, (byte)g, (byte)b);
      }

      public static bool TryParse(string? s, out Rgb value)
      {
          value = default;
          if (s == null || s.Length != 7 || s[0] != '#') return false;
          if (!byte.TryParse(s.Substring(1, 2), NumberStyles.HexNumber, null, out byte r)) return false;
          if (!byte.TryParse(s.Substring(3, 2), NumberStyles.HexNumber, null, out byte g)) return false;
          if (!byte.TryParse(s.Substring(5, 2), NumberStyles.HexNumber, null, out byte b)) return false;
          value = new Rgb(r, g, b);
          return true;
      }

      public override string ToString() => $"#{R:X2}{G:X2}{B:X2}";
  }
````

# Вопросы по структурам на защите


````cards
id: step-4
title: Вопросы по структурам на защите
items:
  - q: Почему Rational — структура, а не класс?
    a: 'Это маленькое значение, которое сравнивается по содержимому и не меняется. Структура — значимый тип: копируется целиком, не требует выделения в куче, не бывает null. Плюс так требует задание: «структура только для чтения».'
  - q: Что даёт readonly struct?
    a: Все поля только для чтения, изменить значение после создания нельзя. Инварианты проверяются один раз в конструкторе и больше не нарушаются. Компилятор к тому же не делает защитных копий при вызове методов.
  - q: Зачем GetHashCode, если есть Equals?
    a: Hash-коллекции (Dictionary, HashSet) сначала ищут по хэшу, а потом уточняют Equals. Равные значения обязаны давать равный хэш, иначе равные ключи окажутся в разных «корзинах» и не найдутся.
  - q: Что будет с default(Rational)?
    a: 'Структура по умолчанию создаётся без вызова конструктора, все поля нули — получилось бы 0/0. Поэтому свойство Denominator возвращает 1, если поле равно 0: default ведёт себя как ноль, 0/1.'
  - q: Чем From отличается от TryCreate?
    a: From при ошибке бросает исключение, TryCreate возвращает false и кладёт default в out-параметр. Второй вариант удобен, когда ошибка ожидаема, например при разборе пользовательского ввода, — как int.Parse и int.TryParse.
````
