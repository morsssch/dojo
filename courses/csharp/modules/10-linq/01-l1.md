# Добавить метод чужому типу

Метод расширения позволяет вызывать свою функцию так, будто она метод существующего типа: `"текст".WordCount()`, хотя в `string` такого метода нет. Правила:

- метод **статический** и лежит в **статическом** необобщённом классе верхнего уровня;

- перед первым параметром стоит `this` — это тип, который расширяем.

```cs run
static class TextExtensions
{
    public static int WordCount(this string text)
    {
        if (text == null) throw new ArgumentNullException(nameof(text));
        return text.Split(' ', StringSplitOptions.RemoveEmptyEntries).Length;
    }

    public static string Capitalize(this string text) =>
        string.Join(" ", text.Split(' ').Select(w => w.Length == 0 ? w : char.ToUpper(w[0]) + w.Substring(1)));
}

class Program
{
    static void Main()
    {
        string s = "мама мыла раму";
        Console.WriteLine(s.WordCount());                  // как будто метод string
        Console.WriteLine(TextExtensions.WordCount(s));    // на самом деле — обычный статический вызов
        Console.WriteLine(s.Capitalize());
        Console.WriteLine("а б".Capitalize().WordCount()); // цепочки
    }
}
```

Под капотом `s.WordCount()` компилятор превращает в `TextExtensions.WordCount(s)`. Поэтому расширение не получает доступа к закрытым членам типа и может быть вызвано даже для `null` — проверку делай сам.

Весь LINQ — это методы расширения для `IEnumerable`, поэтому они «появляются» у массивов и списков после `using System.Linq;`. В Лабе 2 у тебя статический класс `TextExtensions` с пятью расширениями для `string`.


# Расширение по шагам и три ошибки

Метод расширения — **обычный статический метод**, которому компилятор разрешил «точечную» запись. Посмотрим, что он делает с каждой строкой.

```cs run
static class E
{
    public static bool IsNothing(this string s) => s == null;
    public static string Twice(this string s) => s + s;
}

class Program
{
    static void Main()
    {
        string a = "ля";
        Console.WriteLine(a.Twice());            // 1
        Console.WriteLine(E.Twice(a));           // 2
        Console.WriteLine(a.Twice().Twice());    // 3
        string n = null;
        Console.WriteLine(n.IsNothing());        // 4
    }
}
```

| Строка | Как написано | Во что превращает компилятор | Вывод |
| --- | --- | --- | --- |
| 1 | `a.Twice()` | `E.Twice(a)` | ляля |
| 2 | `E.Twice(a)` | то же самое, просто записано явно | ляля |
| 3 | `a.Twice().Twice()` | `E.Twice(E.Twice(a))` | ляляляля |
| 4 | `n.IsNothing()` | `E.IsNothing(null)` — падения нет, null просто пришёл параметром | True |

Строка 3 — причина, по которой расширения так любят в функциональном стиле: цепочка `a.Twice().Twice()` читается слева направо, как конвейер, а вложенные вызовы — изнутри наружу.

## Три ошибки, которые покажет компилятор

| Ошибка | Что написано | Как исправить |
| --- | --- | --- |
| CS1106 «должен быть определён в неуниверсальном статическом классе» | `class E { … this … }` или `static class E` | класс — `static` и без `` |
| CS1105 «метод расширения должен быть статическим» | `public int Twice(this int x)` | добавить `static` к методу |
| CS1061 «не содержит определения … и не удалось найти метод расширения» | вызов `"abc".Twice()`, а метода нет, забыт `this` или класс в другом пространстве имён без `using` | проверить `this` у первого параметра и `using` |

> [!WARNING] Метод типа важнее расширения
> Если у типа есть свой метод с тем же именем и подходящими параметрами, расширение **молча игнорируется**: `list.Contains(2)` вызовет `List.Contains`, даже если ты написал расширение `Contains(this List l, int x)`. Ошибки не будет — поэтому имена расширений лучше выбирать такие, которых у типа точно нет.

# Задача: расширения для строки


````task
id: step-4
lang: cs
title: 'Задача: расширения для строки'
prompt: |-
  Три метода расширения для `string` — тренировка перед классом `TextExtensions` из Лабы 2. После них можно писать `"Марк".Reverse()`, будто такой метод всегда был у строки.

  **Что написать**

  - Все три метода пишешь внутри `static class StrExt` (он уже в заготовке). Каждый — `public static`, первый параметр — `this string text`.
  - `public static string Reverse(this string text)` — та же строка задом наперёд. Удобно так: `ToCharArray()` → `Array.Reverse(a)` → `new string(a)`.
  - `public static bool IsPalindrome(this string text)` — `true`, если строка читается одинаково в обе стороны **без учёта регистра и пробелов**: убери пробелы (`Replace(" ", "")`), переведи в нижний регистр и сравни с перевёрнутой (можно вызвать свой же `Reverse()`).
  - `public static string Truncate(this string text, int max)` — если длина строки `<= max`, верни её как есть; иначе возьми первые `max - 1` символов и допиши один символ многоточия `…` (это **один** символ U+2026, не три точки), чтобы итоговая длина была ровно `max`.
  - Проверки первыми строками: во всех трёх методах `text == null` → `ArgumentNullException(nameof(text))`; в `Truncate` ещё `max < 1` → `ArgumentOutOfRangeException(nameof(max))`.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  Console.WriteLine("Марк".Reverse());                          // краМ
  Console.WriteLine("А роза упала на лапу Азора".IsPalindrome());  // True
  Console.WriteLine("C#".IsPalindrome());                          // False
  Console.WriteLine("Функциональное".Truncate(8));                 // Функцио…  (7 букв + «…» = 8)
  Console.WriteLine("кот".Truncate(8));                            // кот       (короче 8 — без изменений)
  Console.WriteLine("abcdef".Truncate(1));                         // …         (0 букв + «…» = 1)

  string s = null;
  s.Reverse();            // ArgumentNullException — расширение можно вызвать и у null!
  "abc".Truncate(0);      // ArgumentOutOfRangeException
  ```

  Main не пиши: проверка сама вызывает твои методы. Вызов `s.Reverse()` у `null` не падает сразу с NullReferenceException, как у обычного метода: компилятор превращает его в `StrExt.Reverse(s)`, и в метод просто приходит `null`. Поэтому проверка на null внутри обязательна — преподаватель спросит, зачем она.
starter: |-
  static class StrExt
  {
  }
solution: |-
  static class StrExt
  {
      public static string Reverse(this string text)
      {
          if (text == null) throw new ArgumentNullException(nameof(text));
          var a = text.ToCharArray();
          Array.Reverse(a);
          return new string(a);
      }

      public static bool IsPalindrome(this string text)
      {
          if (text == null) throw new ArgumentNullException(nameof(text));
          string t = text.Replace(" ", "").ToLower();
          return t == t.Reverse();
      }

      public static string Truncate(this string text, int max)
      {
          if (text == null) throw new ArgumentNullException(nameof(text));
          if (max < 1) throw new ArgumentOutOfRangeException(nameof(max));
          return text.Length <= max ? text : text.Substring(0, max - 1) + "…";
      }
  }
tests:
  - name: работа
    stdout: |-
      краМ
      True False
      Функцио…|кот|…
    harness: |-
      Console.WriteLine("Марк".Reverse());
      Console.WriteLine("А роза упала на лапу Азора".IsPalindrome() + " " + "C#".IsPalindrome());
      Console.WriteLine("Функциональное".Truncate(8) + "|" + "кот".Truncate(8) + "|" + "abcdef".Truncate(1));
  - name: ошибки
    stdout: |-
      ok1
      ok2
    harness: |-
      string s = null;
      try { s.Reverse(); Console.WriteLine("нет"); } catch (ArgumentNullException) { Console.WriteLine("ok1"); }
      try { "abc".Truncate(0); Console.WriteLine("нет"); } catch (ArgumentOutOfRangeException) { Console.WriteLine("ok2"); }
hints:
  - 'Reverse: var a = text.ToCharArray(); Array.Reverse(a); return new string(a); Truncate: text.Length <= max ? text : text.Substring(0, max - 1) + "…"'
require:
  - - this\s+string
    - 'Методы расширения: первый параметр this string.'
````


# Задача: расширения для int


````task
id: step-5
lang: cs
title: 'Задача: расширения для int'
prompt: |-
  Расширять можно любой тип, не только строки. Три расширения для `int`; последнее принимает делегат — так модули 8 и 9 соединяются: `3.Times(i => …)` читается почти как английская фраза.

  **Что написать**

  - Всё внутри `static class IntExt`, методы `public static`, первый параметр — `this int x` (у Times — `this int n`).
  - `public static bool IsEven(this int x)` — `true` для чётных, в том числе отрицательных и нуля (подсказка: `x % 2 == 0` работает и для −4).
  - `public static int Clamp(this int x, int lo, int hi)` — «зажать» число в отрезок: меньше lo → lo, больше hi → hi, иначе само x. Если `lo > hi` — `ArgumentException`.
  - `public static void Times(this int n, Action action)` — вызвать `action(i)` для i = 0, 1, …, n − 1. Проверки первыми строками: `action == null` → `ArgumentNullException`, `n  Console.Write($"[{i}]"));                              // [0][1][2]
  Console.WriteLine();
  5.Clamp(10, 0);           // ArgumentException
  3.Times(null);            // ArgumentNullException
  (-1).Times(i => { });     // ArgumentOutOfRangeException
  ```

  Ожидаемый вывод:

  True False True
  10 0 5
  [0][1][2]Main не пиши. Скобки в `(-4).IsEven()` нужны: без них `-4.IsEven()` читается как `-(4.IsEven())`, а минус к bool не применяется.
starter: |-
  static class IntExt
  {
      // IsEven, Clamp, Times
  }
solution: |-
  static class IntExt
  {
      public static bool IsEven(this int x) => x % 2 == 0;

      public static int Clamp(this int x, int lo, int hi)
      {
          if (lo > hi) throw new ArgumentException("Нижняя граница больше верхней", nameof(lo));
          return x < lo ? lo : x > hi ? hi : x;
      }

      public static void Times(this int n, Action<int> action)
      {
          if (action == null) throw new ArgumentNullException(nameof(action));
          if (n < 0) throw new ArgumentOutOfRangeException(nameof(n));
          for (int i = 0; i < n; i++) action(i);
      }
  }
tests:
  - name: работа
    stdout: |-
      True False True True
      10 0 5 7
      [0][1][2]
    harness: |-
      Console.WriteLine($"{4.IsEven()} {7.IsEven()} {(-4).IsEven()} {0.IsEven()}");
      Console.WriteLine($"{15.Clamp(0, 10)} {(-3).Clamp(0, 10)} {5.Clamp(0, 10)} {7.Clamp(7, 7)}");
      3.Times(i => Console.Write($"[{i}]"));
      0.Times(i => Console.Write("нет"));
      Console.WriteLine();
  - name: ошибки
    stdout: |-
      ok1
      ok2
      ok3
    harness: |-
      try { 5.Clamp(10, 0); Console.WriteLine("нет"); } catch (ArgumentException) { Console.WriteLine("ok1"); }
      try { 3.Times(null); Console.WriteLine("нет"); } catch (ArgumentNullException) { Console.WriteLine("ok2"); }
      try { (-1).Times(i => { }); Console.WriteLine("нет"); } catch (ArgumentOutOfRangeException) { Console.WriteLine("ok3"); }
hints:
  - 'Clamp: if (lo > hi) throw new ArgumentException("lo > hi"); return x  hi ? hi : x; Times: for (int i = 0; i < n; i++) action(i);'
require:
  - - this\s+int
    - 'Это методы расширения: первый параметр this int.'
````
