# IEnumerable и ленивость

`IEnumerable` — «то, что можно перебрать foreach». Его реализуют массивы, списки, словари, строки (как последовательность `char`). Свою последовательность проще всего сделать через `yield return`:

```cs run
static IEnumerable Evens(int limit)
{
    for (int i = 0; i <= limit; i += 2)
    {
        Console.Write($"(выдаю {i}) ");
        yield return i;              // отдать элемент и «заморозиться» до следующего запроса
    }
}

var seq = Evens(6);                  // пока ничего не выполнилось!
Console.WriteLine("последовательность создана");
foreach (var x in seq) Console.WriteLine(x);
```

Это **ленивость**: элементы вычисляются по запросу. LINQ устроен так же — `Where` и `Select` ничего не считают, пока результат не перебирают (`foreach`, `ToList()`, `Count()`). В Лабе 2 `GetWords` удобно сделать через `yield return` — «возвращает последовательность слов».


# yield по строкам и ошибки итераторов

Метод с `yield return` называют **итератором**. Компилятор превращает его в объект, который «помнит, где остановился». Проследим, в каком порядке выполняются строки:

```cs run
static IEnumerable Nums()
{
    Console.WriteLine("  старт");
    yield return 1;
    Console.WriteLine("  после 1");
    yield return 2;
    Console.WriteLine("  конец");
}

var s = Nums();
Console.WriteLine("создали");
foreach (var x in s) Console.WriteLine("получили " + x);
Console.WriteLine("Count = " + s.Count());   // перебор заново — с самого начала
```

| Что запросили | Что выполнилось внутри Nums | Вывод |
| --- | --- | --- |
| `var s = Nums();` | **ничего** — создан объект-итератор | создали |
| первый шаг foreach | от начала до первого `yield return 1` | старт, получили 1 |
| второй шаг | от места остановки до `yield return 2` | после 1, получили 2 |
| третий шаг | до конца метода — элементов больше нет, foreach выходит | конец |
| `s.Count()` | метод прогоняется **ещё раз целиком** | старт, после 1, конец, Count = 2 |

Два следствия. Первое: последовательность может быть **бесконечной** — пока её не перебирают до конца, бесконечный цикл не страшен. Второе: каждый перебор запускает итератор заново, поэтому дорогую последовательность, которую перебираешь несколько раз, сохраняют `ToList()`.

```cs run
static IEnumerable Naturals()
{
    int i = 0;
    while (true) yield return i++;          // бесконечно — но лениво
}

static IEnumerable UpTo(int n)
{
    for (int i = 0; ; i++)
    {
        if (i > n) yield break;             // yield break — «элементов больше нет»
        yield return i;
    }
}

Console.WriteLine(string.Join(",", Naturals().Take(5)));     // 0,1,2,3,4
Console.WriteLine(string.Join(",", UpTo(3)));                // 0,1,2,3
```

> [!WARNING] Осторожно в курсе
> `Naturals()` без `Take`, например `Naturals().Count()`, никогда не закончится и подвесит вкладку. Если случилось — просто обнови страницу, код сохранён.

## Ошибки компилятора в итераторах

| Ошибка | Что написано | Как исправить |
| --- | --- | --- |
| CS1622 «невозможно вернуть значение из итератора» | в методе есть и `yield return`, и `return list;` | либо всё через `yield return` (закончить — `yield break`), либо обычный метод без yield |
| CS1624 «… не является типом интерфейса итератора» | `static List F() { yield return 1; }` | тип результата — `IEnumerable` (или `IEnumerator`) |
| CS1623 «итераторы не могут иметь параметры ref, in или out» | `IEnumerable F(out int count)` | вернуть количество отдельным методом или через `Count()` |
| CS1626 «нельзя использовать yield в блоке try с catch» | `try { yield return x; } catch { … }` | ловить ошибку вокруг вычисления значения, а `yield return` вынести из try |

И одна ловушка без ошибки компиляции — та, что в задаче про `GetWords`: проверка аргумента внутри итератора тоже ленивая. `"x".Words()` с `null` не бросит исключение при вызове, а только при первом переборе.

# LINQ: методы

LINQ (Language Integrated Query) — набор методов расширения для последовательностей. Каждый принимает лямбду и возвращает новую последовательность, исходная не меняется — чистый функциональный стиль.

```cs run
var words = new[] { "delegate", "event", "lambda", "linq", "record", "event", "lambda", "lambda" };

Console.WriteLine(string.Join(" ", words.Where(w => w.Length > 5)));          // фильтр
Console.WriteLine(string.Join(" ", words.Select(w => w.ToUpper()).Take(3)));   // преобразование + первые 3
Console.WriteLine(string.Join(" ", words.Distinct().OrderBy(w => w.Length).ThenBy(w => w)));
Console.WriteLine(words.Count(w => w.StartsWith("l")) + " " + words.Any(w => w == "linq") + " " + words.All(w => w.Length > 3));
Console.WriteLine(words.First() + " " + words.Last() + " " + words.Max(w => w.Length) + " " + words.Average(w => w.Length).ToString("F2"));

var freq = words.GroupBy(w => w)                     // группы по ключу
                .OrderByDescending(g => g.Count())
                .ToDictionary(g => g.Key, g => g.Count());
foreach (var kv in freq) Console.WriteLine($"{kv.Key}: {kv.Value}");
```

| Метод | Что делает |
| --- | --- |
| `Where(x => усл)` | оставить подходящие |
| `Select(x => выр)` | преобразовать каждый |
| `OrderBy / OrderByDescending / ThenBy` | сортировка по ключу |
| `Take(n) / Skip(n)` | первые n / пропустить n |
| `Distinct()` | без повторов |
| `GroupBy(x => ключ)` | группы; у группы есть `Key`, её можно перебирать |
| `Count / Sum / Average / Max / Min` | агрегаты |
| `First / FirstOrDefault / Last / Single` | один элемент (First бросает исключение на пустой) |
| `Any / All / Contains` | проверки |
| `ToList / ToArray / ToDictionary` | материализовать результат |
| `SelectMany` | развернуть последовательность последовательностей |


# Язык запросов

То же самое можно записать синтаксисом, похожим на SQL. Компилятор переводит его в вызовы методов, так что это одно и то же. Если знаешь SQL из курса аналитика — узнаешь сразу.

```cs run
var sales = new[]
{
    (City: "Ростов", Sum: 1200m), (City: "Краснодар", Sum: 800m),
    (City: "Ростов", Sum: 300m), (City: "Шахты", Sum: 150m), (City: "Краснодар", Sum: 900m)
};

var report = from s in sales
             where s.Sum > 200
             group s by s.City into g
             orderby g.Sum(x => x.Sum) descending
             select new { City = g.Key, Total = g.Sum(x => x.Sum) };

foreach (var r in report) Console.WriteLine($"{r.City}: {r.Total}");

// то же методами:
var same = sales.Where(s => s.Sum > 200).GroupBy(s => s.City)
                .OrderByDescending(g => g.Sum(x => x.Sum))
                .Select(g => new { City = g.Key, Total = g.Sum(x => x.Sum) });
Console.WriteLine(same.Count());
```

`new { City = …, Total = … }` — анонимный тип: объект «на лету» с нужными свойствами. В требованиях Лабы 2 сказано «с использованием технологии LINQ» — подходит любой из двух синтаксисов.


# Пять ловушек LINQ

LINQ-запрос легко написать и легко ошибиться: компилятор почти всё пропустит, а неправильный ответ или исключение появятся при запуске. Проверь каждую ловушку.

```cs run
var empty = new List();
Console.WriteLine(empty.FirstOrDefault());                    // 0 — значение по умолчанию для int
try { empty.First(); } catch (InvalidOperationException) { Console.WriteLine("First на пустой — исключение"); }
try { empty.Average(); } catch (InvalidOperationException) { Console.WriteLine("Average на пустой — тоже"); }

var w = new List { "bb", "c", "aaa" };
Console.WriteLine(string.Join(",", w.OrderBy(x => x.Length).OrderBy(x => x)));   // aaa,bb,c — второй OrderBy всё пересортировал
Console.WriteLine(string.Join(",", w.OrderBy(x => x.Length).ThenBy(x => x)));    // c,bb,aaa — длина, потом алфавит

w.Where(x => x.Length > 1);                                   // результат никуда не записан!
Console.WriteLine(w.Count);                                   // 3 — исходный список не изменился

try { new[] { "a", "a" }.ToDictionary(x => x); }
catch (ArgumentException) { Console.WriteLine("ToDictionary: повторяющийся ключ"); }

int calls = 0;
var q = new[] { 1, 2, 3 }.Select(x => { calls++; return x * 2; });
Console.WriteLine($"{q.Sum()} {q.Max()} — лямбда вызвана {calls} раз");   // 6 раз: два перебора
```

| Ловушка | Что происходит и как правильно |
| --- | --- |
| 1. First / Average / Max на пустой | InvalidOperationException (в VS сообщение «Sequence contains no elements», в курсе — ключ `NoElements`). **Как надо:** `FirstOrDefault()`, проверить `Any()` перед агрегатом, или осознанно бросить своё исключение, как в `GetMostFrequentChar` |
| 2. Два OrderBy подряд | второй сортирует заново и отменяет первый. **Как надо:** дополнительный ключ — `ThenBy` / `ThenByDescending` |
| 3. Результат не сохранён | `Where`, `Select`, `OrderBy` не меняют исходную коллекцию, а возвращают новую последовательность. **Как надо:** `var big = w.Where(…)` или `w = w.Where(…).ToList()` |
| 4. ToDictionary с повтором ключа | ArgumentException. **Как надо:** сначала `GroupBy` по ключу, потом `ToDictionary(g => g.Key, …)` |
| 5. Повторный перебор | ленивый запрос пересчитывается при каждом `Sum`, `Max`, `foreach`. **Как надо:** если результат нужен несколько раз — один раз `ToList()` |

Сортировка строк и культура
Курс работает в культуре ru-RU, и `OrderBy(w => w)` сравнивает строки по русским правилам: кириллица идёт **раньше** латиницы, регистр почти не важен. `OrderBy(w => w, StringComparer.Ordinal)` сравнивает коды символов: латиница раньше, заглавные раньше строчных, «ё» после «я». Если в задаче важен точный порядок — выбери сравнение явно и скажи на защите, какое.

````task
  **Что написать**

  - Запись `record Student(string Name, string Group, int Mark);` уже в заготовке. Методы пиши внутри `static class Q`, все `public static`, параметр — `IEnumerable s`.

  - `public static double AverageOrZero(IEnumerable s)` — средняя оценка; для пустого списка 0, а не исключение (ловушка 1).

  ```cs

      Console.Write($"{kv.Key}={kv.Value} ");                         // ПИ-21=2 ПИ-22=2
  Console.WriteLine();
  Console.WriteLine(Q.BestOrNone(list) + " " + Q.AverageOrZero(list)); // Петрова 4,25
  var none = new List();
  Console.WriteLine(Q.BestOrNone(none) + " " + Q.AverageOrZero(none)); // нет 0

solution: |-
  record Student(string Name, string Group, int Mark);

  static class Q
  {
      public static List<string> Excellent(IEnumerable<Student> s) =>
          s.Where(x => x.Mark == 5).Select(x => x.Name).OrderBy(n => n).ToList();

      public static Dictionary<string, int> CountByGroup(IEnumerable<Student> s) =>
          s.GroupBy(x => x.Group).ToDictionary(g => g.Key, g => g.Count());

      public static string BestOrNone(IEnumerable<Student> s) =>
          s.OrderByDescending(x => x.Mark).ThenBy(x => x.Name).Select(x => x.Name).FirstOrDefault() ?? "нет";

      public static double AverageOrZero(IEnumerable<Student> s) =>
          s.Any() ? s.Average(x => x.Mark) : 0;
  }
````

# Задача: GetWords через yield


````task
id: step-11
lang: cs
title: 'Задача: GetWords через yield'
prompt: |-
  Это почти готовый `GetWords` из Лабы 2. Слово — непрерывная цепочка букв и цифр (`char.IsLetterOrDigit`); всё остальное (пробелы, запятые, тире, точки) — разделители. Слова надо выдавать **лениво, через `yield return`**, а не собирать в список.

  **Что написать**

  - Оба метода пишешь внутри `static class WordExt` (он уже в заготовке), оба `public static`.
  - `public static IEnumerable Words(this string text)`: заведи `StringBuilder sb` (нужен `using System.Text;` в начале файла) и пройди `foreach (char c in text)`. Буква или цифра → `sb.Append(c)`. Другой символ → если в `sb` что-то накопилось, `yield return sb.ToString()` и `sb.Clear()`.
  - После цикла не забудь последнее слово: если `sb.Length > 0` — ещё один `yield return`. Иначе слово в самом конце строки (без точки после него) потеряется.
  - `public static int CountWords(this string text) => text.Words().Count();` — одна строка.
  - Для `null` брось `ArgumentNullException(nameof(text))` (по требованиям лабы). Учти: в методе с `yield` эта проверка сработает не в момент вызова `Words()`, а при первом переборе результата.

  **Как проверка будет пользоваться твоим кодом**

  ```cs
  Console.WriteLine(string.Join("|", "Привет, мир! C# 12 — это... ок?".Words()));
  // Привет|мир|C|12|это|ок      — «#», «—», «...» и «?» не буквы, значит разделители

  Console.WriteLine("  ,,  ".CountWords());   // 0 — одни разделители
  Console.WriteLine("one".CountWords());      // 1 — слово без разделителя в конце
  Console.WriteLine("a-b-c".CountWords());    // 3

  var e = "a b c".Words();   // проверка смотрит тип e: это должен быть итератор,
                             // который сделал компилятор из yield, а не List
  ```

  Main не пиши. Почему важна ленивость: метод с `yield return` не выполняется при вызове `Words()` — он начинает работать, только когда кто-то перебирает результат (`foreach`, `Count()`, `string.Join`), и отдаёт слова по одному. Если вместо этого собрать `List` и вернуть его, ответ будет тот же, но тест на ленивость не пройдёт.
starter: |-
  static class WordExt
  {
  }
solution: |-
  using System.Text;

  static class WordExt
  {
      public static IEnumerable<string> Words(this string text)
      {
          if (text == null) throw new ArgumentNullException(nameof(text));
          var sb = new StringBuilder();
          foreach (char c in text)
          {
              if (char.IsLetterOrDigit(c)) sb.Append(c);
              else if (sb.Length > 0) { yield return sb.ToString(); sb.Clear(); }
          }
          if (sb.Length > 0) yield return sb.ToString();
      }

      public static int CountWords(this string text) => text.Words().Count();
  }
````
