# Бэклог Dojo

Живой документ: что сделано, что в работе, что дальше и почему решили именно так.
Обновляется в конце каждой рабочей сессии. Читать первым делом, если подхватываешь проект.

## Контекст

- **Цель:** платформа-движок под любые курсы. Контент пишут другие нейронки по `docs/AUTHORING.md`.
  Сначала — техническая платформа и шаблон, потом контент.
- **Первый курс — «Go Backend с нуля».** Целевой ученик: писал немного на JS/TS и Python, понимает базовые структуры данных,
  git на базовом уровне, бэкенд знает только со стороны фронта, SQL и ООП — нет. Цель — бэкенд на Go к весеннему хакатону (~март).
- **Формат:** как Stepik, темп свободный. Порционно (почитал → попрактиковался), глубокое «почему, как устроено внутри»,
  визуал и схемы, один сквозной проект. Тон — живой, неформальный, на «ты».
- **Сквозной проект:** сначала «хакатон-стартер» (auth/JWT, CRUD, файлы, WebSocket, TG-бот, LLM, админка), потом поверх — продукт.
- **Приватность:** репозиторий и сайт публичные — не упоминать имена, команды и личный контекст.

## Решения (и почему)

| Решение | Почему |
|---|---|
| Vite + React + TS, хэш-роутинг, `base: './'` | Статика для GitHub Pages, работает из любой подпапки, без серверного роутинга |
| Контент = папки + YAML + Markdown с fenced-блоками (`quiz`, `task`, `git`, `anim`, `project`, `<lang> run`, `mermaid`) | Нейронкам и людям проще всего писать Markdown; YAML внутри блоков валидируется zod-схемами |
| Порядок модулей/уроков — по числовому префиксу имени (`01-...`), id — имя без префикса | Перестановка не ломает прогресс; не нужно поддерживать списки вручную |
| Манифест курса строится при сборке (Vite-плагин), уроки грузятся лениво | Курс будет огромным — нельзя тянуть все тексты на главную |
| Go в браузере — интерпретатор **yaegi** в wasm, урезанная stdlib (включая `net/http` + `httptest`) | Настоящий компилятор в wasm — слишком тяжело. yaegi даёт горутины, каналы, дженерики, HTTP-хендлеры без сети |
| Проверка Go — склейка кода ученика и харнесса в один файл (`src/core/runners/gosrc.ts`) | yaegi не даёт повторно импортировать пакет во втором Eval |
| SQL — **PGlite** (настоящий Postgres в wasm) | Учим именно Postgres; поведение 1-в-1 |
| Git — свой терминал + **isomorphic-git** поверх MemFS; remote = папка (`/srv/origin.git`) | Реальная модель git, работает офлайн; push/pull/clone через копирование объектов |
| Прогресс — localStorage + экспорт/импорт JSON | Без бэкенда. Синк через GitHub Gist — позже |
| Проверка контента `npm run check` прогоняет эталонные решения всех задач | Другая нейронка не сможет закоммитить нерешаемую задачу |

## Известные ограничения

- **yaegi ≠ компилятор Go.** Не ругается на неиспользуемые переменные/импорты; stdlib уровня Go 1.22 (нет `slices.Sorted`, итераторов 1.23);
  вывод типов в дженериках слабее (иногда нужно явно `Map[int, string](...)`); дедлок не детектится — ловим таймаутом.
  Сообщения об ошибках отличаются от `go build`. Для задач, где это критично, — `project`-блоки с локальным `go test`.
- Git-эмулятор: нет rebase, stash, cherry-pick, revert, `checkout -`; `restore` берёт файл из HEAD, а не из индекса; нет hunk-заголовков в diff.
- Python (pyodide) грузится с CDN (~10 МБ) — только при первом запуске python-блока.

## Найдено и исправлено при проверке

- `window.scrollTo` в новых Chromium возвращает Promise → эффект React падал. Эффекты всегда в фигурных скобках.
- Google Fonts блокировали отрисовку при недоступной сети → шрифты грузятся неблокирующе.
- После `setup` git-задачи ученик оставался в чужой папке → всегда стартует в `~`.
- Граф коммитов из одной секунды путал порядок → топологическая сортировка.
- YAML: строки с `: ` становятся объектами — описано в AUTHORING, ловится `check`.
